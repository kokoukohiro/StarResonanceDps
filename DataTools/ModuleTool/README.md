# DataTools(モジュールツール用)

モジュールツール(`StarResonanceDps.Plugins.ModuleTool`)が使う表と名前を、言語別の JSON テーブルから作り直すツール。
本体用(`../Core`)とは別のもので、共通の `_common.py` も別に持つ。

素の Python 3 だけで動く。依存パッケージは無い。

```bash
cd StarResonanceDps/DataTools/ModuleTool
python gen_modules.py    # モジュールの効果・モジュール・リンクの戦闘力と、その名前
```

作業ディレクトリはどこでもよい（`_common.py` が自身の位置からリポジトリを求める）。
`_common.py` はパスと入出力だけを持つ共有モジュールで、単体では実行しない。

## 入力

置き場は環境変数 `BPSR_TABLES` で指定する。無ければリポジトリの隣の `JSONS` を見る。
期待する構成は「出所 → `Ztable` → 言語フォルダ → `ZTable` → `*.json`」で、本体用と同じ。

使う表: `ModEffectTable` / `ModLinkEffectTable` / `ModHoleTable` / `ModTable` / `ItemTable`。

## 出力

出力は `StarResonanceDps.Plugins.ModuleTool/Data/` に書き、プラグインの DLL に埋め込まれる。本体の `Data` には書かない。

| ファイル | 中身 |
|---|---|
| `ModuleTables.json` | 枠の数、効果ごとの絵と段階(必要なリンク数・戦闘力)、モジュールごとの絵と品質、出所ごとの「リンクの総和 → 戦闘力」の並び |
| `ModuleNames.json` | 効果・モジュールの4言語の名前 |

- リンクの戦闘力は出所ごとに持つ。出所で表の長さが違い、表の最後を超えた総和は最後の行の値になるため。両方にある総和の値は同じでなければ止まる

## 名前の土台

言語フォルダごとに、その言語が入っているビルドの表を土台にする(cn / en は `Star`、jp / kr は `StarASIA`)。
土台の名前が空なら、もう一方の出所で補う。名前が無い言語は空文字で入り、プラグインが zh-CN へ落とす。
未翻訳の行に入っている埋め草文字列（`_common.PLACEHOLDERS`）は空として扱う。

## 止まる条件

数値は言語に依らないので、出所の間で同じでなければ止める(どちらを採るか決められないため)。

- 効果の段階の数値(必要なリンク数・戦闘力)か絵が出所で違う、効果の段階が 0 から続いていない
- リンクの総和が 0 から続いていない、両方の出所にある総和で戦闘力が違う
- 枠の数が出所で違う
- モジュールの行がアイテムの表に無い、絵が無い、絵か品質が言語で違う

## 絵

絵(モジュール・効果・品質の背景)はこのツールでは作らない。プラグインの `Assets/` に置き、ファイル名は表の絵の名前と同じにする。

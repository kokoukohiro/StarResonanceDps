플러그인으로 게임 데이터를 읽기 위한 설명입니다. 모든 플러그인에 필요한 것은 [플러그인 개발](플러그인-개발)에 있습니다.

| `IPluginContext`의 멤버 | 내용 |
|---|---|
| `GameData`(`IPluginGameDataService`) | 앱이 통신으로부터 만든 값(접속과 맵, 플레이어, 주변의 적, 버프, 전투 집계, 자신의 모듈)과, 바뀌었을 때의 이벤트 |
| `Names`(`IPluginNameService`) | 스킬, 버프, 몬스터, 클래스, 맵, 아이템의 번호로 이름을 찾음 |
| `Packets`(`IPluginPacketService`) | 게임 메시지 그 자체 |

## 게임 데이터(`GameData`)

다음 예는 전투가 끝났을 때 모든 사람의 준 피해 합계를 로그에 씁니다.

```csharp
using StarResonanceDps.PluginSdk;

[assembly: PluginRegistration(typeof(MyPlugin.Plugin), PluginSdkVersion.Current)]
[assembly: PluginDisplayName("ja-JP", "私のプラグイン")]
[assembly: PluginAuthor("YourName")]
[assembly: PluginVersion("1.0.0")]

namespace MyPlugin;

public sealed class Plugin : IStarResonancePlugin
{
    private IPluginContext? _context;

    public void Initialize(IPluginContext context)
    {
        _context = context;
        context.GameData.EncounterClosed += OnEncounterClosed;
    }

    private void OnEncounterClosed(object? sender, PluginEncounterResult result)
    {
        foreach (PluginEncounterPlayer player in result.Totals.Players)
        {
            _context?.Logger.Info($"{player.CharacterId}: {player.Damage.Total}");
        }
    }

    public void Shutdown()
    {
        if (_context is not null)
        {
            _context.GameData.EncounterClosed -= OnEncounterClosed;
        }
    }
}
```

| 멤버 | 내용 | 바뀌었을 때의 이벤트 |
|---|---|---|
| `CurrentServer` | 지금 읽고 있는 게임의 서버(`PluginGameServer`의 `Asia`, `China`, `Global`, `SoutheastAsia`). 알 수 없으면 `Unknown` | 없음 |
| `Session` | 접속과 맵의 상태(`PluginSessionState`) | `SessionChanged` |
| `Players` | 플레이어 목록(`PluginPlayer`) | `PlayersChanged` |
| `Entities` | 주변 몬스터 목록(`PluginEntity`) | `EntitiesChanged` |
| `SelfModules` | 자신의 보유 모듈과 장착 중인 칸(`PluginModuleInventory`). 아직 도착하지 않았으면 `null` | `SelfModulesChanged` |
| `GetPlayerBuffs(characterId)` | 그 사람에게 지금 붙어 있는 버프와 디버프(`PluginBuff`) | 없음(다시 읽음) |
| `GetEntityBuffs(entityUuid)` | 그 엔티티에 지금 붙어 있는 버프와 디버프 | 없음(다시 읽음) |
| `GetEncounter()` | '[DPS 미터](DPS-미터)'가 표시하고 있는 전투의 모든 사람의 집계(`PluginEncounterSnapshot`) | 없음(다시 읽음) |
| `GetSkillTotals(characterId, kind)` | 같은 전투에서 그 사람의 스킬별 내역(`PluginSkillTotals`). `kind`는 준 피해(`Damage`)나 치유(`Healing`) | 없음(다시 읽음) |

| 이벤트 | 오는 때 |
|---|---|
| `EncounterStarted` | 앱이 새 전투를 만들었을 때 |
| `EncounterClosed` | 기록이 있는 전투를 닫았을 때. 닫은 전투의 집계와 모든 사람의 스킬별 내역(`PluginEncounterResult`)이 전달됩니다 |
| `MapEntered` | 다른 맵이나 채널로 이동했을 때 |
| `LoggedOut` | 게임이 로그인 화면으로 돌아갔을 때 |

- 값은 어느 스레드에서 읽어도 괜찮습니다. 이벤트는 모두 UI 스레드에서 옵니다.
- `SessionChanged`, `PlayersChanged`, `EntitiesChanged`, `SelfModulesChanged`는 짧은 사이의 변화를 1번으로 묶어, 왔을 때의 값으로 알립니다. 나머지 4개는 일어날 때마다 옵니다.
- 값은 바꿀 수 없는 복사본이며, 나중에 새로워지지 않습니다. 새 값은 다시 읽습니다. 두 값을 이어서 읽으면 서로 다른 순간의 값이 될 수 있습니다.
- `Players`, `Entities`, `SelfModules`와 `EncounterClosed`의 결과는 모든 플러그인에 같은 것을 넘깁니다. `IReadOnlyList` 등을 원래 형식으로 바꿔서 고치지 마세요.
- 이벤트 처리는 앱의 화면과 같은 UI 스레드에서 동작합니다. 무거운 처리를 하면 위젯도 멈춥니다.
- 이벤트 처리에서 예외를 내면 플러그인이 멈춥니다.

### 접속과 맵(`Session`)

| 속성 | 내용 |
|---|---|
| `SelfCharacterId` | 자신의 캐릭터 ID. 알 때까지와 로그아웃 뒤에는 `null` |
| `SceneId` | 지금 맵의 번호. `Names.GetSceneName`에 넘깁니다 |
| `SeasonId` | 지금 시즌의 번호 |
| `DungeonState` | 던전 밖(`NotInDungeon`), 안(`InDungeon`), 끝난 뒤(`Finished`) |
| `IsMidLaunch` | 게임의 통신을 도중부터 읽기 시작해서, 아직 자신의 정보가 갖춰지지 않음(게임 도중에 앱을 실행했을 때 등). 맵을 이동하면 `false`가 됩니다 |

- 게임 도중에 앱을 실행했을 때는 자신의 캐릭터 ID나 보유 모듈을 맵을 이동할 때까지 알 수 없을 수 있습니다.

### 플레이어(`Players`)

- 자신, 파티 멤버, 주변 플레이어와, DPS 미터가 표시하고 있는 전투에 기록이 있는 사람이 들어갑니다. '[플레이어 목록](플레이어-목록)'의 원래 목록이며, 플레이어 목록의 필터와 이름순 정렬은 적용하지 않습니다.
- 순서는 자신, 파티 멤버(파티 번호순), 주변에도 파티에도 없는 사람, 전투 중인 사람, 그 밖의 사람 순입니다.
- 이름은 설정의 '플레이어 이름'을 따릅니다. 숨긴 사람은 `*****`입니다. 알 수 없을 때는 비어 있을 수도 있습니다.

| 속성 | 내용 |
|---|---|
| `CharacterId` | 캐릭터 ID. 이름을 숨기고 있어도 실제 값입니다 |
| `Name` | 이름 |
| `ProfessionId` | 직업의 번호. 알 수 없으면 0 |
| `SpecState`, `SpecId` | 클래스의 상태(`Unknown`, `NotEquipped`(1단계), `Specialized`, `Transformation`(변신)). `Specialized`일 때만 `SpecId`에 번호가 들어갑니다(`Names.GetClassSpecName`에 넘김) |
| `Level`, `AbilityScore`, `SeasonStrength` | 레벨, 능력 점수, 시즌 강도. 알 수 없으면 0 |
| `CurrentHp`, `MaxHp`, `CurrentShield` | HP와 실드의 양. 실드는 자신과 주변 사람만 알 수 있습니다 |
| `PartyNumber` | 파티 번호. 파티 밖이면 `null` |
| `IsSelf`, `IsNpc`, `IsPartyMember`, `IsNearby` | 자신인지, 도우미 NPC인지, 파티 멤버인지, 주변에 있는지 |
| `IsInCombat`, `IsIncapacitated` | 전투 상태, 쓰러짐. 전투 상태를 알 수 있는 것은 자신과 주변 사람뿐입니다 |
| `PsychoscopeRootBuffId`, `IsPsychoscopeInactive` | 깊은 잠 심상의의 유형(루트 버프의 번호)과, 미적용인지 |
| `IsFromRecord` | 열어 둔 집계의 기록에만 있는 사람 |

### 주변의 적(`Entities`)

- 주변에 있는, 종류가 몬스터인 것만 들어갑니다. '[엔티티 목록](엔티티-목록)'의 원래 목록이며, 엔티티 목록의 필터와 이름순 정렬은 적용하지 않습니다.
- 순서는 전투 상태인 것, 그 밖의 것 순이며, 각각의 안에서는 보스, 정예, 일반, 기타 순입니다.

| 속성 | 내용 |
|---|---|
| `EntityUuid` | 엔티티의 UUID. `GetEntityBuffs`에 넘깁니다 |
| `MonsterId` | 몬스터의 번호(`Names.GetMonsterName`에 넘김). 앱을 실행하기 전부터 주변에 있던 몬스터는 한 번 주변에서 벗어났다가 다시 나타날 때까지 `null`입니다 |
| `CurrentHp`, `MaxHp` | HP |
| `IsInCombat` | 전투 상태 |
| `Cast` | 캐스팅하고 있는 스킬(`SkillId`, `StartedAtUtc`, `TotalSeconds`). 캐스팅 시간이 있는 스킬을 시작했을 때 들어가고, 다음에 스킬이 바뀔 때까지 남습니다. `TotalSeconds`가 지나도 남을 수 있으므로, 끝은 시각으로 정합니다 |
| `TargetCharacterId` | 노리고 있는 플레이어의 캐릭터 ID. 적대 수치 1위라고는 할 수 없습니다 |
| `HateRanking` | 적대 수치 목록(플레이어만, 값이 큰 순) |

### 버프(`GetPlayerBuffs`, `GetEntityBuffs`)

- 지금 붙어 있는 것이 모두 들어갑니다. '[버프 목록](버프-목록)'처럼 표시할 것을 거르거나 묶는 처리는 적용하지 않습니다.
- 주변에 없는 사람과 적의 것은 비어 있습니다. 맵을 이동하면 모두 사라집니다.
- 집계의 기록을 열어 두어도 지금의 값입니다.

| 속성 | 내용 |
|---|---|
| `BuffUuid` | 버프 하나하나의 UUID |
| `BuffId` | 버프의 번호(`Names.GetBuffName`에 넘김) |
| `Level`, `Layer` | 레벨과 층(중첩 수) |
| `DurationSeconds` | 효과 시간의 총량(연장하면 늘어납니다). 지속 시간이 없으면 `null` |
| `EndUtc` | 끝나는 시각(UTC). 지속 시간이 없거나 남은 시간을 알 수 없으면 `null` |
| `IsRemainingUnknown` | 남은 시간을 알 수 없음 |
| `CasterEntityUuid`, `CasterCharacterId` | 부여한 엔티티의 UUID(알 수 없으면 0)와, 부여한 것이 플레이어라면 그 캐릭터 ID |

### 전투 집계(`GetEncounter`, `GetSkillTotals`)

- 읽는 것은 DPS 미터가 표시하고 있는 전투입니다. 집계의 기록을 열어 두었으면 그 전투, 설정의 '다음 이벤트까지 결과 유지'로 이전 전투를 표시하고 있으면 그 전투입니다.

| `PluginEncounterSnapshot`의 속성 | 내용 |
|---|---|
| `IsHistory` | 집계의 기록을 열어 두었음 |
| `StartUtc` | 전투의 시계가 움직이기 시작한 시각(UTC). 아직이면 `null` |
| `Elapsed` | 전투의 경과 시간(자동 일시정지 동안 제외) |
| `IsClosed` | 전투가 끝났음 |
| `Players` | 준 피해, 치유, 받은 피해 중 하나라도 있는 플레이어(`PluginEncounterPlayer`). 파티로 거르지 않으며, 순서는 정해져 있지 않습니다 |

- `PluginEncounterPlayer`는 `CharacterId`와, 준 피해(`Damage`), 치유(`Healing`), 받은 피해(`DamageTaken`)의 합계(`PluginCombatTotals`)를 갖습니다.
- `PluginCombatTotals`는 합계(`Total`), 초당 값(`PerSecond`, DPS 미터와 같음), 그 사람의 유효한 시간에서의 초당 값(`ActivePerSecond`, 스킬 상세와 같음), 히트 수(`Hits`), 치명타와 행운의 합계와 수입니다.
- `PluginSkillTotals`는 스킬 상세와 같은 행으로, 행의 키(`RowKey`), 행의 이름(`Name`, 없으면 `null`), 합계, 초당 값, 히트 수, 치명타율(`CritRate`), 그 사람의 합계에서 차지하는 비율(`Share`)을 갖습니다. 합계가 큰 순입니다.
- `EncounterStarted`는 맵 이동, 던전 시작, '진행에 따라 자동 리셋'의 구분, 수동 리셋, 측정의 시작과 중지, 로그아웃에서 옵니다. 1번의 맵 이동에서 몇 번 올 수 있습니다.
- 전투의 시계가 움직이기 시작했을 때의 이벤트는 없습니다. `GetEncounter().StartUtc`를 읽습니다.
- `EncounterClosed`는 기록이 있는 전투를 닫고 다음 전투를 만들 때 옵니다. 앱을 닫을 때의 마지막 전투에서는 오지 않습니다. 닫은 전투의 값은 받은 결과를 그 자리에서 가지고 있습니다.

### 자신의 모듈(`SelfModules`)

- `Modules`는 보유 모듈(`PluginModuleItem`: `Uuid`, 아이템 번호인 `ConfigId`, `Quality`, 효과인 `Effects`), `EquippedUuidBySlot`은 장착 중인 칸의 번호와 모듈의 `Uuid`입니다.
- 효과(`PluginModuleEffect`)는 효과의 번호(`EffectId`)와 연결 수(`LinkCount`, 도착하지 않았으면 `null`)입니다.
- 맵에 들어갈 때마다, 내용이 같아도 `SelfModulesChanged`가 옵니다.
- 로그아웃 뒤와, 설정의 '네트워크 어댑터', '게임 실행 파일'을 바꾼 뒤에는 다음에 맵을 이동할 때까지 `null`입니다.

## 이름 찾기(`Names`)

| 메서드 | 찾는 이름 |
|---|---|
| `GetSkillName(skillId)` | 스킬 |
| `GetBuffName(buffId)` | 버프 |
| `GetMonsterName(monsterId)` | 몬스터 |
| `GetClassSpecName(specId)` | 클래스(`PluginPlayer.SpecId`) |
| `GetSceneName(sceneId, dungeonDifficulty)` | 맵. 난이도의 이름이 있으면 '맵 이름-난이도 이름'. `dungeonDifficulty`는 생략할 수 있습니다 |
| `GetItemName(itemId)` | 아이템(장비 포함) |

- 이름은 앱의 표시 언어의 이름입니다. 그 언어의 이름이 없으면 중국어 이름, 둘 다 없으면 `null`입니다.
- 앱의 화면과 달리 내부 이름이나 내부 ID는 붙이지 않습니다. 설정의 '내부 ID', '이름 없는 스킬과 버프'도 적용되지 않습니다.
- 1단계와 변신의 이름은 없으므로, `GetClassSpecName`은 `null`입니다.
- 직업, 깊은 잠 심상의의 유형, 시즌, 모듈 효과의 이름을 찾는 메서드는 없습니다.
- 어느 스레드에서 호출해도 괜찮습니다. 표시 언어가 바뀌면 `Localization.CultureChanged` 안에서 다시 찾습니다.

## 게임 메시지(`Packets`)

`ReadAsync`에 받을 종류를 넘기고, 도착한 메시지를 `await foreach`로 읽습니다.

```csharp
private static async Task ReadMessagesAsync(IPluginContext context, IReadOnlyCollection<PluginPacketType> types)
{
    await foreach (PluginPacketMessage message in context.Packets.ReadAsync(types).ConfigureAwait(false))
    {
        context.Logger.Info($"{message.Kind} {message.ServiceId}/{message.MethodId}: {message.Payload.Length} bytes");
    }
}
```

- `Initialize` 안에서 `_ = ReadMessagesAsync(context, types);`처럼 기다리지 않고 시작합니다.
- 받을 종류(`PluginPacketType`)는 종류(`Kind`), 서비스 번호, 메서드 번호의 조합이며, 1개 이상 넘깁니다. 세 가지가 모두 맞는 메시지만 도착합니다.
- 종류는 서버로부터의 알림(`Notify`), 게임에서 서버로의 호출(`Call`), 호출에 대한 응답(`Return`)입니다. `Return`의 번호는 응답하고 있는 호출의 번호입니다.
- `await foreach`를 시작했을 때부터 도착한 메시지를 도착한 순서대로 넘깁니다. 그 전의 것은 넘기지 않습니다. 반복을 빠져나오면 받기를 멈춥니다.
- 내용(`Payload`)은 protobuf의 바이트열입니다. `Notify`와 `Return`은 압축을 푼 뒤이며, `Return`은 응답을 감싼 형태 그대로입니다. `Call`은 압축을 풀지 않았습니다.
- `Payload`는 앱이 복사한 것이므로 언제까지 가지고 있어도 괜찮습니다.
- 아직 가져가지 않은 내용의 합계가 플러그인 1개당 64MB를 넘으면 플러그인이 멈춥니다('[플러그인](플러그인)'의 행의 툴팁은 '통신 수신을 따라가지 못해 중지됨, 다음 실행 시 다시 시작'). 받을 종류를 좁히고, 도착한 것은 바로 가져갑니다.
- `Initialize`는 UI 스레드에서 호출되므로, `ConfigureAwait(false)`를 붙이지 않으면 반복의 내용이 UI 스레드에서 동작합니다.
- 앱이 플러그인을 멈추면 반복은 끝납니다. `Stopping`을 넘기지 않았으면 예외 없이, 넘겼으면 `OperationCanceledException`으로 끝납니다.
- 게임 메시지의 번호와 내용의 형태는 이 Wiki에서 설명하지 않습니다.

## 데이터를 읽을 때의 규칙

- 창의 내용, 위젯의 본체와 푸터에서 구독한 이벤트는 `Dispose`에서 해제합니다. 해제하지 않으면 닫은 창의 내용이 이벤트를 계속 받고, 메모리에도 남습니다.
- `Initialize`에서 구독한 이벤트는 `Shutdown`에서 해제합니다. 앱도 `Shutdown` 전에 해제하므로, 멈춘 뒤에 처리가 호출되는 일은 없습니다.
- 버프와 전투 집계에는 바뀌었을 때의 이벤트가 없으므로, 타이머로 다시 읽습니다.

## 넘겨주지 않는 것

- 장비, 능력치, 어빌리티, 스킬 칸, 재사용 대기시간, 던전의 목표와 점수, 예고 스킬, 채팅 등은 넘겨주지 않습니다. 필요할 때는 게임 메시지를 읽습니다.

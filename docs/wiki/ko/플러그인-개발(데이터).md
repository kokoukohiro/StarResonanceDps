플러그인으로 게임 데이터를 읽기 위한 설명입니다. 모든 플러그인에 필요한 것은 [플러그인 개발](플러그인-개발)에 있습니다.

| `IPluginContext`의 멤버 | 내용 |
|---|---|
| `GameData`(`IPluginGameDataService`) | 앱이 통신으로부터 만든 값(접속과 맵, 플레이어, 주변의 적, 버프, 전투 집계와 기록, 자신의 모듈)과 집계 설정, 바뀌었을 때의 이벤트 |
| `Names`(`IPluginNameService`) | 스킬, 버프, 몬스터, 클래스, 맵, 아이템의 번호로 이름을 찾음 |
| `Packets`(`IPluginPacketService`) | 게임 메시지 그 자체 |
| `CombatEvents`(`IPluginCombatEventService`) | 앱이 처리한 전투 이벤트(피해, 스킬과 받은 피해와 타임라인의 기록, 버프의 부여와 제거, 몬스터의 스킬과 HP 0)의 흐름 |
| `History`(`IPluginHistoryService`) | 저장된 전투(기록)를 읽거나 열고, 전투에 플러그인의 값을 저장함([플러그인 개발(기록)](플러그인-개발(기록))) |

## 게임 데이터(`GameData`)

다음 예는 전투가 끝났을 때 모든 사람의 준 피해 합계를 로그에 씁니다.

```csharp
using StarResonanceDps.PluginSdk;

[assembly: PluginRegistration(typeof(MyPlugin.Plugin), PluginSdkVersion.Current)]
[assembly: PluginDisplayName("ja-JP", "私のプラグイン")]
[assembly: PluginAuthor("YourName")]
[assembly: PluginVersion("1.0.0")]

namespace MyPlugin;

public sealed class Plugin : IStarResonancePlugin
{
    private IPluginContext? _context;

    public void Initialize(IPluginContext context)
    {
        _context = context;
        context.GameData.EncounterClosed += OnEncounterClosed;
    }

    private void OnEncounterClosed(object? sender, PluginEncounterResult result)
    {
        foreach (PluginEncounterPlayer player in result.Totals.Players)
        {
            _context?.Logger.Info($"{player.CharacterId}: {player.Damage.Total}");
        }
    }

    public void Shutdown()
    {
        if (_context is not null)
        {
            _context.GameData.EncounterClosed -= OnEncounterClosed;
        }
    }
}
```

| 멤버 | 내용 | 바뀌었을 때의 이벤트 |
|---|---|---|
| `CurrentServer` | 지금 읽고 있는 게임의 서버(`PluginGameServer`의 `Asia`, `China`, `Global`, `SoutheastAsia`). 알 수 없으면 `Unknown` | 없음 |
| `Session` | 접속과 맵의 상태(`PluginSessionState`) | `SessionChanged` |
| `Players` | 플레이어 목록(`PluginPlayer`) | `PlayersChanged` |
| `Entities` | 주변 몬스터 목록(`PluginEntity`) | `EntitiesChanged` |
| `SelfModules` | 자신의 보유 모듈과 장착 중인 칸(`PluginModuleInventory`). 아직 도착하지 않았으면 `null` | `SelfModulesChanged` |
| `GetPlayerBuffs(characterId)` | 그 사람에게 지금 붙어 있는 버프와 디버프(`PluginBuff`) | 없음(다시 읽음) |
| `GetEntityBuffs(entityUuid)` | 그 엔티티에 지금 붙어 있는 버프와 디버프 | 없음(다시 읽음) |
| `GetPlayer(characterId)` | 그 사람의 행(`PluginPlayer`). `Players`에 없는 사람은 목록에서 벗어난 뒤의 마지막 값이나, 명함이나 채팅으로 받은 값입니다. 어느 것도 없으면 `null` | 없음(다시 읽음) |
| `GetPlayerBuild(characterId)` | 그 사람의 빌드(`PluginPlayerBuild`, 아래 '빌드'). `GetPlayer`가 `null`인 사람은 `null` | 없음(다시 읽음) |
| `GetEncounter()` | '[DPS 미터](DPS-미터)'가 표시하고 있는 전투의 모든 사람의 집계(`PluginEncounterSnapshot`) | 없음(다시 읽음) |
| `GetSkillTotals(characterId, kind)` | 같은 전투에서 그 사람의 스킬별 내역(`PluginSkillTotals`). `kind`는 준 피해(`Damage`)나 치유(`Healing`) | 없음(다시 읽음) |
| `GetShownEncounter()` | `GetEncounter`와 같은 전투의 읽기 객체(`IPluginEncounterRecord`). 전투가 아직 없으면 `null` | `ShownEncounterChanged` |
| `GetLiveEncounter()` | 현재 전투의 읽기 객체. 전투가 아직 없으면 `null` | `EncounterStarted` |
| `AggregationSettings` | 설정의 '집계 설정'의 값(`PluginAggregationSettings`) | `AggregationSettingsChanged` |

| 이벤트 | 오는 때 |
|---|---|
| `EncounterStarted` | 앱이 새 전투를 만들었을 때 |
| `EncounterClosed` | 기록이 있는 전투를 닫았을 때. 닫은 전투의 집계와 모든 사람의 스킬별 내역(`PluginEncounterResult`)이 전달됩니다 |
| `EncounterSaved` | 전투를 기록에 저장했을 때. 그 전투의 `EncounterKey`와 기록 번호(`HistoryId`)가 전달됩니다(`PluginEncounterSaved`) |
| `MapEntered` | 다른 맵이나 채널로 이동했을 때 |
| `LoggedOut` | 게임이 로그인 화면으로 돌아갔을 때 |

- 값은 어느 스레드에서 읽어도 괜찮습니다. 이벤트는 모두 UI 스레드에서 옵니다.
- `SessionChanged`, `PlayersChanged`, `EntitiesChanged`, `SelfModulesChanged`, `ShownEncounterChanged`, `AggregationSettingsChanged`는 짧은 사이의 변화를 1번으로 묶어, 왔을 때의 값으로 알립니다. 나머지 5개는 일어날 때마다 옵니다.
- 값은 바꿀 수 없는 복사본이며, 나중에 새로워지지 않습니다. 새 값은 다시 읽습니다. 두 값을 이어서 읽으면 서로 다른 순간의 값이 될 수 있습니다. 전투 읽기 객체(`IPluginEncounterRecord`)는 복사본이 아니며, 호출할 때마다 값을 읽습니다(아래 '전투 읽기 객체').
- `Players`, `Entities`, `SelfModules`와 `EncounterClosed`의 결과는 모든 플러그인에 같은 것을 넘깁니다. `IReadOnlyList` 등을 원래 형식으로 바꿔서 고치지 마세요.
- 이벤트 처리는 앱의 화면과 같은 UI 스레드에서 동작합니다. 무거운 처리를 하면 위젯도 멈춥니다.
- 이벤트 처리에서 예외를 내면 플러그인이 멈춥니다.

### 접속과 맵(`Session`)

| 속성 | 내용 |
|---|---|
| `SelfCharacterId` | 자신의 캐릭터 ID. 알 때까지와 로그아웃 뒤에는 `null` |
| `SceneId` | 지금 맵의 번호. `Names.GetSceneName`에 넘깁니다 |
| `SeasonId` | 지금 시즌의 번호 |
| `DungeonState` | 던전 밖(`NotInDungeon`), 안(`InDungeon`), 끝난 뒤(`Finished`) |
| `IsMidLaunch` | 게임의 통신을 도중부터 읽기 시작해서, 아직 자신의 정보가 갖춰지지 않음(게임 도중에 앱을 실행했을 때 등). 맵을 이동하면 `false`가 됩니다 |
| `SelfTargetEntityUuid` | 자신의 타겟인 적의 UUID('[타겟 정보](타겟-정보)'가 표시하는 적). 자신이 마지막으로 스킬을 쓴 적이며, 그 적이 주변에서 사라지면 `null`이 되고, 다음에 그 적에게 스킬을 쓰면 돌아옵니다 |
| `DungeonFlowState`, `DungeonFlowChanges` | 던전 진행 상태(`PluginDungeonFlowState`)와, 맵에 들어온 뒤의 상태 변화(`PluginDungeonFlowChange`: 상태와 받은 시각(UTC), 오래된 순). 받지 않았으면 `null`과 빈 목록입니다 |
| `DungeonTimer` | 게임의 던전 시계(`PluginDungeonTimer`). 시작 시각(서버 시각의 Unix 초와, 이 PC의 시각으로 고친 UTC), 제한 시간, 줄어드는지, 멈춰 있던 초의 합계, 멈춰 있는 동안 표시되는 값입니다. 시계를 보내지 않는 던전과 던전 밖에서는 `null`입니다 |

- 게임 도중에 앱을 실행했을 때는 자신의 캐릭터 ID나 보유 모듈을 맵을 이동할 때까지 알 수 없을 수 있습니다.
- 게임의 락온과 다른 플레이어의 타겟은 게임이 보내지 않으므로 알 수 없습니다.
- 진행 상태는 게임의 값 그대로이며, `Active`(던전 맵에 들어옴), `Ready`(시작 전), `Playing`(시작), `End`(종료), `Settlement`(결과 화면), `Vote`(투표)의 순서로 옵니다. `None`은 게임의 초기값입니다. 같은 상태가 연달아 와도 변화에는 더하지 않습니다. 맵을 이동하거나 로그아웃하면 비게 됩니다.

### 플레이어(`Players`)

- 자신, 파티 멤버, 주변 플레이어와, DPS 미터가 표시하고 있는 전투에 기록이 있는 사람이 들어갑니다. '[플레이어 목록](플레이어-목록)'의 원래 목록이며, 플레이어 목록의 필터와 이름순 정렬은 적용하지 않습니다.
- 순서는 자신, 파티 멤버(파티 번호순), 주변에도 파티에도 없는 사람, 전투 중인 사람, 그 밖의 사람 순입니다.
- 이름은 설정의 '플레이어 이름'을 따릅니다. 숨긴 사람은 `*****`입니다. 알 수 없을 때는 비어 있을 수도 있습니다.

| 속성 | 내용 |
|---|---|
| `CharacterId` | 캐릭터 ID. 이름을 숨기고 있어도 실제 값입니다 |
| `Name` | 이름 |
| `ProfessionId` | 직업의 번호. 알 수 없으면 0 |
| `SpecState`, `SpecId` | 클래스의 상태(`Unknown`, `NotEquipped`(1단계), `Specialized`, `Transformation`(변신)). `Specialized`일 때만 `SpecId`에 번호가 들어갑니다(`Names.GetClassSpecName`에 넘김) |
| `Level`, `AbilityScore`, `SeasonStrength` | 레벨, 능력 점수, 시즌 강도. 알 수 없으면 0 |
| `CurrentHp`, `MaxHp`, `CurrentShield` | HP와 실드의 양. 실드는 자신과 주변 사람만 알 수 있습니다 |
| `PartyNumber` | 파티 번호. 파티 밖이면 `null` |
| `IsSelf`, `IsNpc`, `IsPartyMember`, `IsNearby` | 자신인지, 도우미 NPC인지, 파티 멤버인지, 주변에 있는지 |
| `IsInCombat`, `IsIncapacitated` | 전투 상태, 쓰러짐. 전투 상태를 알 수 있는 것은 자신과 주변 사람뿐입니다 |
| `PsychoscopeRootBuffId`, `IsPsychoscopeInactive` | 깊은 잠 심상의의 유형(루트 버프의 번호)과, 미적용인지 |
| `IsFromRecord` | 열어 둔 집계의 기록에만 있는 사람. 저장된 전투의 `GetPlayers` 행은 모두 `true` |

### 빌드(`GetPlayerBuild`)

- '[어빌리티 정보](어빌리티-정보)', '[깊은 잠 심상의 정보](깊은-잠-심상의-정보)', '[모듈 정보](모듈-정보)', '[장비 정보](장비-정보)'와 같은 출처의 값입니다. 부를 때마다 새로운 사본을 만듭니다.
- 집계의 기록을 열고 있는 동안은, 기록에만 있는 사람은 그 전투의 값, 다른 사람은 현재 값입니다(플레이어 위젯과 같음). 저장된 전투의 값은 전투 읽기 객체의 `GetPlayerBuild`로 읽습니다.
- 목록은 모두, 받지 않았으면 `null`, 받았는데 비어 있으면 빈 목록입니다. `PluginPlayerBuild`끼리 `==`로 비교해도 목록의 내용은 비교하지 않으므로 내용을 비교합니다.

| `PluginPlayerBuild`의 속성 | 내용 |
|---|---|
| `RootBuffIds` | 붙어 있는 루트 버프(어빌리티, 깊은 잠 심상의의 노드 효과와 고급 노드 효과, 인자, 모듈 효과)의 번호. 오름차순입니다. 그 사람의 버프를 모두 받을 때까지 `null` |
| `TalentNodeIds` | 현재 직업에서 습득한 어빌리티 트리의 노드 번호. 오름차순입니다. 자신만이며, 다른 사람은 `null` |
| `LastUsedReplaceableSkills` | 버프를 붙이지 않는 어빌리티로 스킬이 바뀌는 것의, 원래 스킬 번호에서 마지막으로 쓴 쪽(원래 또는 바뀐 뒤)의 스킬 번호로의 대응. 어느 것도 아직 쓰지 않았으면 `null` |
| `Equipment` | 장비(`PluginEquipmentItem`: 부위 `Slot`과 장비 번호 `EquipmentId`. 이름은 `Names.GetItemName`). 게임의 값을 읽지 못했을 때는 `IsReadable`이 `false`이고 목록은 비어 있습니다 |
| `SkillLevels` | 스킬 번호, 레벨, 단계(`PluginSkillLevel`의 `SkillId`, `Level`, `RemodelLevel`). 자신은 현재 직업의 습득 스킬, 역할 스킬, 고른 이매진, 다른 사람은 게임이 보내는 목록(이매진은 장착 중인 2개만), 주변에 없는 파티 멤버는 파티 동기화로 마지막에 받은 목록입니다 |
| `Factors` | 현재 시즌의 적용 중인 유형에 붙인 인자(칸 번호 `SlotId`와 아이템 번호 `ItemId`). 자신만이며, 다른 사람은 `null` |
| `ModuleEffects` | 장착 중인 모듈의 효과(`PluginModuleEffect`). `LinkCount`는 장착 중인 모듈의 합입니다. 자신만이며, 다른 사람은 `null` |

### 주변의 적(`Entities`)

- 주변에 있는, 종류가 몬스터인 것만 들어갑니다. '[엔티티 목록](엔티티-목록)'의 원래 목록이며, 엔티티 목록의 필터와 이름순 정렬은 적용하지 않습니다.
- 순서는 전투 상태인 것, 그 밖의 것 순이며, 각각의 안에서는 보스, 정예, 일반, 기타 순입니다.

| 속성 | 내용 |
|---|---|
| `EntityUuid` | 엔티티의 UUID. `GetEntityBuffs`에 넘깁니다 |
| `MonsterId` | 몬스터의 번호(`Names.GetMonsterName`에 넘김). 앱을 실행하기 전부터 주변에 있던 몬스터는 한 번 주변에서 벗어났다가 다시 나타날 때까지 `null`입니다 |
| `CurrentHp`, `MaxHp` | HP |
| `IsInCombat` | 전투 상태 |
| `Cast` | 캐스팅하고 있는 스킬(`SkillId`, `StartedAtUtc`, `TotalSeconds`). 캐스팅 시간이 있는 스킬을 시작했을 때 들어가고, 다음에 스킬이 바뀔 때까지 남습니다. `TotalSeconds`가 지나도 남을 수 있으므로, 끝은 시각으로 정합니다 |
| `TargetCharacterId` | 노리고 있는 플레이어의 캐릭터 ID. 적대 수치 1위라고는 할 수 없습니다 |
| `HateRanking` | 적대 수치 목록(플레이어만, 값이 큰 순) |
| `Level` | 레벨('[엔티티 목록](엔티티-목록)'과 같은 값). 알 수 없으면 0 |
| `CurrentShield` | 실드의 양 |

### 버프(`GetPlayerBuffs`, `GetEntityBuffs`)

- 지금 붙어 있는 것이 모두 들어갑니다. '[버프 목록](버프-목록)'처럼 표시할 것을 거르거나 묶는 처리는 적용하지 않습니다.
- 주변에 없는 사람과 적의 것은 비어 있습니다. 맵을 이동하면 모두 사라집니다.
- 집계의 기록을 열어 두어도 지금의 값입니다.

| 속성 | 내용 |
|---|---|
| `BuffUuid` | 버프 하나하나의 UUID |
| `BuffId` | 버프의 번호(`Names.GetBuffName`에 넘김) |
| `Level`, `Layer` | 레벨과 층(중첩 수) |
| `DurationSeconds` | 효과 시간의 총량(연장하면 늘어납니다). 지속 시간이 없으면 `null` |
| `EndUtc` | 끝나는 시각(UTC). 지속 시간이 없거나 남은 시간을 알 수 없으면 `null` |
| `IsRemainingUnknown` | 남은 시간을 알 수 없음 |
| `CasterEntityUuid`, `CasterCharacterId` | 부여한 엔티티의 UUID(알 수 없으면 0)와, 부여한 것이 플레이어라면 그 캐릭터 ID |

### 전투 집계(`GetEncounter`, `GetSkillTotals`)

- 읽는 것은 DPS 미터가 표시하고 있는 전투입니다. 집계의 기록을 열어 두었으면 그 전투, 설정의 '다음 이벤트까지 결과 유지'로 이전 전투를 표시하고 있으면 그 전투입니다.
- 전투가 아직 없으면 `GetEncounter`는 `EncounterKey`가 0인 빈 집계입니다.
- 같은 전투를 읽기 객체로 읽는 것이 `GetShownEncounter`, 현재 전투를 읽는 것이 `GetLiveEncounter`입니다(아래 '전투 읽기 객체').

| `PluginEncounterSnapshot`의 속성 | 내용 |
|---|---|
| `IsHistory` | 저장된 기록에서 읽은 전투. `GetEncounter`에서는 집계의 기록을 열어 두었음 |
| `StartUtc` | 전투의 시계가 움직이기 시작한 시각(UTC). 아직이면 `null`. 보통은 전투에서 처음 일어난 일의 시각이고, 던전 시계(`ClockOrigin`)의 전투에서는 던전이 시작된 시각입니다 |
| `Elapsed` | 전투의 경과 시간(자동 일시정지 동안과, 던전 시계의 전투에서는 게임의 던전 시계가 멈춰 있던 동안 제외) |
| `IsClosed` | 전투가 끝났음 |
| `Players` | 준 피해, 치유, 받은 피해 중 하나라도 있는 플레이어(`PluginEncounterPlayer`). 파티로 거르지 않으며, 순서는 정해져 있지 않습니다 |
| `EncounterKey` | 앱을 실행하고 있는 동안 전투를 구별하는 번호(1부터). 전투가 없으면 0. 현재 전투는 저장한 뒤에도 같은 번호입니다. 기록에서 읽은 전투는 읽을 때마다 새 번호가 되므로, 저장된 전투는 `HistoryId`로 구별합니다. 앱을 다시 실행하면 1부터 다시 셉니다 |
| `HistoryId` | 기록 번호([플러그인 개발(기록)](플러그인-개발(기록))). 저장하기 전과, 기록이 없어 저장되지 않는 전투에서는 `null`. `EncounterClosed`의 결과에서는 항상 `null`이며, 번호는 `EncounterSaved`로 받습니다 |
| `LastCombatEventUtc` | 전투에서 마지막으로 일어난 일(피해, 치유 등)이 도착한 시각(UTC). 아직이면 `null`. 전투의 시계는 여기서부터 `Info.AutoPauseSeconds`의 초 수가 지나면 멈춥니다(0이면 멈추지 않습니다. 아래 '전투의 값') |
| `IsAggregationStopped` | 현재 전투에서 앱이 아무것도 기록하지 않고, 전투의 시계도 움직이지 않음(설정의 '비전투 지역에서 집계 중지'가 켜져 있고 비전투 지역에 있음). 닫은 전투와 기록에서 읽은 전투에서는 `false` |
| `ClockOrigin` | 전투 시계의 기점(`PluginClockOrigin`). 전투에서 처음 일어난 일, 던전 시작을 받은 시각, 게임 던전 시계의 시작 시각 중 하나입니다. 플러그인이 던전 시계를 등록하지 않았으면 전투에서 처음 일어난 일입니다([플러그인 개발(전투 구분)](플러그인-개발(전투-구분))) |
| `FirstCombatEventUtc` | 전투에서 처음 일어난 일이 도착한 시각(UTC). 아직이면 `null`. 치유, 적대 수치, 내성 파괴는 이 시각부터 기록합니다. 던전 시계의 전투가 아니면 `StartUtc`와 같습니다 |
| `BenchmarkFirstTargetEntityUuid` | 측정에서 처음 공격한 적만 집계할 때, 자신이 처음 피해를 준 적의 UUID. 이 적에 대한 피해, 적대 수치, 내성 파괴만 셉니다. 정해질 때까지와, 다른 전투와, 기록에서 읽은 전투에서는 `null` |

- `PluginEncounterPlayer`는 `CharacterId`와, 준 피해(`Damage`), 치유(`Healing`), 받은 피해(`DamageTaken`)의 합계(`PluginCombatTotals`)를 갖습니다.
- `PluginCombatTotals`는 합계(`Total`), 초당 값(`PerSecond`, DPS 미터와 같음), 그 사람의 유효한 시간에서의 초당 값(`ActivePerSecond`, 스킬 상세와 같음), 히트 수(`Hits`), 치명타와 행운의 합계와 수입니다.
- `PluginSkillTotals`는 스킬 상세와 같은 행으로, 행의 키(`RowKey`), 행의 이름(`Name`, 없으면 `null`), 합계, 초당 값, 히트 수, 치명타율(`CritRate`), 그 사람의 합계에서 차지하는 비율(`Share`)을 갖습니다. 합계가 큰 순입니다.
- `EncounterStarted`는 맵 이동, 던전 시작, '진행에 따라 자동 리셋'의 구분, 수동 리셋, 측정의 시작과 중지, 로그아웃과, 플러그인의 구분 요청과 규칙([플러그인 개발(전투 구분)](플러그인-개발(전투-구분)))에서 옵니다. 1번의 맵 이동에서 몇 번 올 수 있습니다.
- 전투의 시계가 움직이기 시작했을 때의 이벤트는 없습니다. `GetEncounter().StartUtc`를 읽습니다.
- `EncounterClosed`는 기록이 있는 전투를 닫고 다음 전투를 만들 때 옵니다. 앱을 닫을 때의 마지막 전투에서는 오지 않습니다. 닫은 전투를 `GetEncounter`로 읽을 수 있는 것은 미터가 그 전투를 표시하고 있는 동안뿐이므로, 필요한 값은 받은 결과에서 그 자리에서 가지고 있습니다. 저장된 뒤에는 `EncounterSaved`의 `HistoryId`로 [플러그인 개발(기록)](플러그인-개발(기록))의 `LoadAsync`에서 다시 읽을 수 있습니다.
- `EncounterSaved`는 앱이 전투를 기록에 저장할 때마다 1번, 같은 전투의 `EncounterClosed` 뒤, 다음 `EncounterStarted` 전에 옵니다. 기록이 없는 전투는 저장하지 않으므로 오지 않습니다. 앱을 닫을 때의 마지막 전투에서도 오지 않습니다.
- `ShownEncounterChanged`는 `GetEncounter`와 `GetShownEncounter`가 읽는 전투가 바뀐 뒤에 옵니다. 기록을 열었을 때(사용자가 열었을 때도, `OpenAsync`일 때도), 현재 전투로 돌아갔을 때(자동으로 돌아갔을 때도), 새 전투를 표시하기 시작했을 때, 표시하고 있던 이전 전투를 그만두었을 때입니다. 같은 기록을 다시 열어도 옵니다. 이전 전투를 표시하고 있는 동안 새 전투를 만들었을 때와, 기록을 열 수 없었을 때는 오지 않습니다.

### 전투 읽기 객체(`GetShownEncounter`, `GetLiveEncounter`)

- `GetShownEncounter`는 `GetEncounter`와 같은 전투를, `GetLiveEncounter`는 현재 전투를 읽기 객체(`IPluginEncounterRecord`)로 반환합니다. 전투가 아직 없으면 `null`입니다.
- `GetLiveEncounter`는 집계의 기록을 열어 둔 동안과 이전 전투를 표시하고 있는 동안에도 현재 전투를 반환합니다.
- 읽기 객체는 만들어졌을 때의 전투를 계속 읽습니다. 앱이 다음 전투로 옮겨 간 뒤에도 같은 전투를 읽습니다.
- 읽기 객체를 가지고 있는 동안에는 그 전투가 메모리에 남습니다. 필요한 동안만 가지고 있습니다.
- 어느 스레드에서 호출해도 괜찮습니다. 현재 전투의 값은 호출할 때마다 그때의 값을 읽으므로, 두 가지를 이어서 호출하면 서로 다른 순간의 값이 될 수 있습니다. 기록에서 읽은 전투는 플러그인의 값을 빼고는 바뀌지 않습니다.
- 저장된 전투도 같은 읽기 객체로 읽을 수 있습니다([플러그인 개발(기록)](플러그인-개발(기록))의 `LoadAsync`).

| `IPluginEncounterRecord`의 멤버 | 내용 |
|---|---|
| `EncounterKey`, `HistoryId` | 전투 번호와 기록 번호(위의 `PluginEncounterSnapshot`과 같음). 현재 전투의 `HistoryId`는 저장되면 들어갑니다 |
| `IsHistory` | 저장된 기록에서 읽은 전투(집계의 기록으로 연 전투와 `LoadAsync`로 읽은 전투). 현재 전투와, 이전 전투를 표시하고 있는 동안의 그 전투는 `false` |
| `Info` | 맵, 서버, 측정 등의 값(`PluginEncounterInfo`, 아래 '전투의 값') |
| `GetTotals()` | 모든 사람의 집계(`PluginEncounterSnapshot`). DPS 미터와 같은 값이며, DPS 미터가 표시하고 있는 전투라면 `GetEncounter()`와 같습니다 |
| `GetSkillTotals(characterId, kind)` | 그 사람의 스킬별 내역(위의 `GetSkillTotals`와 같은 행). 그 전투에 합계가 없는 사람은 비어 있습니다 |
| `ToCombatOffset(utc)` | 시각을 전투 경과 시간으로 바꿈(아래 '전투 경과 시간') |
| `GetPlayers()` | 저장된 전투에 있던 플레이어(아래 '저장된 전투의 플레이어'). 현재 전투에서는 `null` |
| `GetMonsters()` | 전투에 남아 있는 몬스터(아래 '전투의 몬스터') |
| `GetPlayerBuffIntervals(characterId)` | 그 사람에게 버프가 붙어 있던 구간과 주변에 있던 구간(아래 '버프 구간') |
| `GetPlayerBuild(characterId)` | 저장된 전투에서 그 사람의 빌드(위의 '빌드'). 저장했을 때의 값이며, `TalentNodeIds`, `Factors`, `ModuleEffects`는 저장했을 때 로그인해 있던 캐릭터만, `SkillLevels`는 게임이 보낸 목록입니다. 현재 전투와 `GetPlayers`에 없는 사람은 `null` |
| `GetSkillActivations(characterId, startIndex)` | 그 사람이 사용한 스킬의 기록(`PluginSkillActivation`)의 `startIndex`번째부터 뒤(아래 '전투의 기록') |
| `GetTakenHits(startIndex)` | 플레이어가 받은 피해의 기록(`PluginTakenHit`)의 `startIndex`번째부터 뒤(아래 '전투의 기록') |
| `GetCombatLog(startIndex)` | '[타임라인](타임라인)'의 기록(`PluginCombatLogRecord`)의 `startIndex`번째부터 뒤(아래 '전투의 기록') |
| `GetPerSecondTotals(characterId, kind)` | 그 사람의 1초마다의 피해나 치유의 합계(아래 '1초마다의 합계') |
| `GetPluginData(key)` | 이 플러그인이 전투에 저장한 값. 없으면 `null`([플러그인 개발(기록)](플러그인-개발(기록))의 '전투에 저장') |

### 전투의 값(`Info`)

| `PluginEncounterInfo`의 속성 | 내용 |
|---|---|
| `CreatedUtc` | 앱이 전투를 만든 시각(UTC). 전투의 시계는 보통 그 뒤에 움직이기 시작하고, 던전 시계의 전투에서는 조금 앞에서부터 움직일 수 있습니다(`StartUtc`). 기록 목록은 이 시각이 새로운 순서입니다 |
| `SceneId`, `DungeonDifficulty` | 맵 번호(알 수 없으면 `null`)와 던전 난이도(없으면 0). 이름은 `Names.GetSceneName(sceneId, dungeonDifficulty)`로 찾습니다 |
| `ChannelLine` | 채널 번호. 채널이 없는 곳에서는 `null` |
| `Server` | 게임 서버. 앱이 전투를 저장할 때 쓰므로, 현재 전투에서는 저장할 때까지 `Unknown`입니다. 지금 서버는 `CurrentServer`로 읽습니다 |
| `SeasonId` | 시즌 번호. `Server`와 마찬가지로 저장할 때까지 `null`입니다. 지금 시즌은 `Session.SeasonId`로 읽습니다 |
| `IsWipe` | 설정의 '진행에 따라 자동 리셋'으로 전멸했을 때 닫은 전투 |
| `BenchmarkSeconds` | 측정 전투라면 측정 시간(초)이며, 측정이 시작되기를 기다리는 동안에도 들어갑니다. 측정이 아니면 0 |
| `BenchmarkFirstTargetOnly` | 측정에서 처음 공격한 적만 집계할지. 측정이 아니면 `false`. 앱이 저장하지 않으므로 기록에서 읽은 전투에서는 `null` |
| `AutoPauseSeconds` | 앱이 전투를 만들었을 때의 설정 '자동 일시정지'의 초 수. 전투의 시계는 전투에서 마지막으로 일이 일어난 뒤 이 초 수가 지나면 멈춥니다. 멈추지 않는 설정일 때, 측정 전투, 던전 시계의 전투에서는 0 |

- 현재 전투에서는 채널, 난이도, `IsWipe`가 바뀔 수 있으므로 필요할 때 `Info`를 다시 읽습니다.

### 전투 경과 시간(`ToCombatOffset`)

- 시각을 앱의 그래프와 타임라인 가로축과 같은 전투 경과 시간으로 바꿉니다. `StartUtc`부터의 시간에서 그보다 앞의 멈춰 있던 동안(자동 일시정지와, 던전 시계의 전투에서는 게임의 던전 시계가 멈춰 있던 동안)을 뺀 것입니다.
- 멈춰 있는 동안의 시각은 멈춘 시점의 경과 시간이 됩니다.
- 전투의 시계가 움직이기 시작하기 전은 `null`, `StartUtc`보다 앞의 시각은 음수입니다.
- UTC 시각을 넘깁니다. `DateTime.Kind`를 보고 변환하지는 않습니다.
- 현재 전투에서는 전투에서 마지막으로 일이 일어난 시각보다 뒤의 시각의 값은 전투가 이어지면 바뀔 수 있습니다.

### 기록하는 규칙

앱이 전투에 기록하는 것의 규칙입니다. 집계와 `GetMonsters`의 캐스팅은 이 규칙으로 기록한 것입니다.

- `IsAggregationStopped`가 `true`인 전투에서는 아무것도 기록하지 않습니다.
- 치유, 적대 수치, 내성 파괴는 전투에서 처음 일어난 일 뒤(`FirstCombatEventUtc`부터)에만 기록합니다.
- 측정 전투(`Info.BenchmarkSeconds`가 0보다 큼)에서는 `StartUtc`부터 측정 시간이 지날 때까지의 일만 기록합니다. 그 안에서도 기록하는 것은 자신의 일과, 어느 플레이어의 것도 아닌 일(적의 캐스팅, 보스 스킬의 예고, 적의 행동)뿐입니다.
- `Info.BenchmarkFirstTargetOnly`가 `true`일 때는 피해, 적대 수치, 내성 파괴는 자신이 처음 피해를 준 적(`BenchmarkFirstTargetEntityUuid`)에 대한 것만 셉니다. 그 적이 정해지기 전의 적대 수치와 내성 파괴는 세지 않습니다.

### 저장된 전투의 플레이어(`GetPlayers`)

- 기록에서 읽은 전투(`IsHistory`가 `true`)에서만 반환하며, 현재 전투에서는 `null`입니다. 현재 전투의 플레이어는 `Players`로 읽습니다.
- 들어가는 것은 그 전투에 준 피해, 치유, 적대 수치, 내성 파괴, 받은 피해 중 하나라도 있거나 타임라인 기록이 있는 사람입니다. 순서는 정해져 있지 않습니다.
- 행은 `Players`와 같은 `PluginPlayer`(위의 '플레이어')입니다. 값은 전투와 함께 저장한 것(저장했을 때 앱이 표시하고 있던 값)뿐이며, 지금의 파티나 앱이 지금 가지고 있는 값은 사용하지 않으므로 `Players`의 같은 사람 행과 다를 수 있습니다.
- `IsFromRecord`는 `true`, `CurrentHp`는 `MaxHp`와 같고, `CurrentShield`는 0, `PartyNumber`는 `null`, `IsPartyMember`, `IsNearby`, `IsInCombat`, `IsIncapacitated`는 `false`입니다.
- `IsSelf`는 호출했을 때 로그인하고 있는 캐릭터입니다. 이름은 호출했을 때의 설정 '플레이어 이름'을 따릅니다.

### 전투의 몬스터(`GetMonsters`)

- 현재 전투에서는 주변의 몬스터와, 주변에서 벗어난 몬스터 중 보스이거나 '[타임라인](타임라인)'이나 '[받은 피해 로그](받은-피해-로그)'에 실리는 것입니다. 호출할 때마다 그때의 값을 읽습니다.
- 기록에서 읽은 전투에서는 전투와 함께 저장한 몬스터입니다. 저장되는 것은 캐스팅 기록이 있는 것, 타임라인의 적의 행동에 실리는 것, 플레이어에게 피해를 준 것입니다. 기록이 없는 보스는 저장되지 않습니다.
- 순서는 정해져 있지 않습니다.

| `PluginRecordedMonster`의 속성 | 내용 |
|---|---|
| `EntityUuid` | 엔티티의 UUID. 주변에 있는 동안은 `Entities`의 `EntityUuid`와 같습니다 |
| `MonsterId` | 몬스터 번호(`Names.GetMonsterName`에 넘김). 도착하지 않았으면 `null` |
| `Hp`, `MaxHp` | 마지막으로 도착한 HP와 최대 HP. 기록에서 읽은 전투에서는 저장했을 때의 값입니다. 도착하지 않았으면 0 |
| `Casts` | 그 몬스터의 캐스팅(`PluginRecordedCast`)을 도착한 순서대로. 캐스팅 시간이 있는 스킬과, 전투 화면에 경고가 표시되는 스킬입니다 |

- `PluginRecordedCast`는 스킬 번호(`SkillId`, `Names.GetSkillName`에 넘김), 시작이 도착한 시각(`StartedAtUtc`, UTC), 경고가 표시되는 스킬인지(`IsWarning`)입니다.
- 자신의 이름을 갖지 않는, 소환된 엔티티의 캐스팅은 소환한 몬스터의 캐스팅으로 기록합니다.
- 캐스팅은 위의 '기록하는 규칙'으로 기록하고 있을 때만 기록합니다.

### 버프 구간(`GetPlayerBuffIntervals`)

- '[버프 가동률](버프-가동률)'을 위해 앱이 기록하고 있는 구간입니다. 버프 목록에 표시되는 버프(디버프 제외)이며, 플레이어만입니다. 측정 전투에서는 자신만이며, `IsAggregationStopped`가 `true`인 전투에서는 아무것도 기록하지 않습니다.
- 그 사람의 기록이 없을 때와 전투의 시계가 움직이기 시작하기 전에는 `null`입니다.
- 시각은 `StartUtc`부터 전투의 시계가 끝날 때까지의 사이입니다. 전투의 시계가 움직이기 시작하기 전부터 붙어 있던 버프는 `StartUtc`부터 시작합니다. 현재 전투에서는 붙은 채인 버프는 현재 전투의 시계의 끝까지 늘어납니다.
- 떨어졌다는 정보가 도착하지 않은 버프는 효과 시간이 끝난 시각에 끝납니다.
- 그래프 가로축에 맞출 때는 `ToCombatOffset`으로 전투 경과 시간으로 바꿉니다.

| 속성 | 내용 |
|---|---|
| `Buffs` | 버프 번호별 구간(`PluginBuffInterval`). 그 전투에서 처음 붙은 순서입니다 |
| `PresentIntervals` | 그 사람의 값이 도착하고 있던(주변에 있던) 구간. 오래된 순서입니다. 이 구간 밖의 버프는 알 수 없습니다. 주변에서 벗어나면 붙어 있던 버프의 구간도 거기서 끝납니다 |
| `PluginBuffInterval.BuffId` | 버프 번호(`Names.GetBuffName`에 넘김). 도착한 번호 그대로이며, '버프 가동률'에서 1행으로 묶는 버프도 묶지 않습니다 |
| `PluginBuffInterval.IsPermanent` | 마지막 구간이 시작되었을 때(붙어 있지 않은 상태에서 붙었을 때)의 버프에 효과 시간이 없었음(상시 버프) |
| `PluginBuffInterval.Intervals` | 버프가 1개 이상 붙어 있던 구간. 오래된 순서이며, 겹치지 않습니다 |

- 구간(`PluginTimeInterval`)은 시작(`StartUtc`)과 끝(`EndUtc`)의 UTC 시각입니다.

### 전투의 기록(`GetSkillActivations`, `GetTakenHits`, `GetCombatLog`)

- 앱이 전투에 기록한 것을 기록한 순서(오래된 순서)대로 `startIndex`번째부터 뒤를 돌려줍니다. 앞서 읽은 개수를 `startIndex`에 넘기면 늘어난 만큼만 읽을 수 있습니다.
- `startIndex`가 음수이거나 호출했을 때의 기록 개수보다 크면 `ArgumentOutOfRangeException`입니다. `GetSkillActivations`의 개수는 사람별입니다.
- 위의 '기록하는 규칙'으로 기록한 것입니다. `GetSkillActivations`에는 전투의 시계가 움직이기 시작하기 전의 것도 들어갑니다.
- 기록에서 읽은 전투에서도 같은 방법으로 읽을 수 있습니다.
- 시각(`ArrivalTimeUtc`)은 도착한 시각(UTC)입니다. 예고의 끝의 기록은 예고 바가 끝난 시각입니다. 그래프 가로축에 맞출 때는 `ToCombatOffset`으로 바꿉니다.
- 받은 피해의 기록과 타임라인의 기록은 공통의 일련번호(`Sequence`)를 가집니다. 두 가지를 합쳐서 늘어놓을 때는 이 번호의 순서로 늘어놓습니다.

| 메서드 | 1건의 내용 |
|---|---|
| `GetSkillActivations` | `PluginSkillActivation`: 스킬 번호(`SkillId`), 아이콘 테두리(`Frame`), 도착한 시각. 자신은 게임이 스킬을 받아들였을 때, 다른 플레이어는 스킬을 사용하기 시작했을 때 기록합니다. 이름은 `Names.GetSkillActivationName`으로 찾습니다 |
| `GetTakenHits` | `PluginTakenHit`: 피해를 받은 플레이어(`CharacterId`), 피해를 준 엔티티(`Attacker`), 피해의 출처(`Source`와 `SourceId`), 값, 속성, 타입, 쓰러졌는지(`IsLethal`). 값이 0인 피해는 들어가지 않습니다. 자신의 스킬, 낙하, 플레이어로부터의 피해도 들어갑니다 |
| `GetCombatLog` | `PluginCombatLogRecord`에서 파생된 형식: 적의 캐스팅(`PluginCastRecord`), 보스 스킬의 예고와 예고의 끝(`PluginAnnouncementRecord`), 피해 없는 쓰러짐(`PluginPlayerDeathRecord`), 적의 치유(`PluginEnemyHealRecord`), 적이 적에게 준 피해(`PluginEnemyDamageRecord`), 적이 붙인 버프(`PluginEnemyBuffRecord`) |

- `Frame`은 '[DPS 추이 그래프](DPS-추이-그래프)' 등에서 스킬 아이콘 뒤에 표시하는 테두리입니다(`Imagine`: 이매진, `Ultimate`: 궁극 스킬이며, 둘 다 거기서 파생되는 스킬을 포함합니다. `Standard`: 그 밖의 스킬).
- 기록에 나오는 엔티티(`PluginCombatParty`)는 UUID(`EntityUuid`), 종류(`Kind`: `Player`, `Monster`, `System`, `Other`), 플레이어라면 캐릭터 번호(`CharacterId`), 몬스터라면 몬스터 번호(`MonsterId`, 도착하지 않았으면 `null`)입니다. `System`은 타임라인에서 '시스템'으로 표시하는, 플레이어도 몬스터도 아닌 게임의 장치입니다.
- 소환된 엔티티의 행동은 알 수 있을 때는 소환한 플레이어나 몬스터의 행동으로 기록합니다('타임라인'과 같음).
- 피해의 출처(`Source`)는 스킬, 탄, 버프, 낙하 등이며, `SourceId`는 그 번호입니다. 버프나 소환된 엔티티의 피해에서는 원래의 스킬(`BuffSourceSkillId`, `SummonSourceSkillId`)도 들어갑니다.

### 1초마다의 합계(`GetPerSecondTotals`)

- 그 사람의 피해(`Damage`)나 치유(`Healing`)의, 전투의 시계 1초마다의 합계입니다. '[DPS 추이 그래프](DPS-추이-그래프)', '[HPS 추이 그래프](HPS-추이-그래프)'와 같은 값입니다.
- `Totals[i]`는 전투 경과 시간의 i초부터 i+1초까지(i+1초 포함)의 합계입니다. 늦게 도착한 피해도 그 시각의 초에 들어갑니다.
- 현재 전투에서는 다 찬 초만 들어갑니다. 닫힌 전투(`IsClosed`)에서는 마지막 1초 미만의 분량도 들어갑니다. `Elapsed`는 읽었을 때의 전투 경과 시간입니다.
- 그 사람이 전투에 없을 때와 전투의 시계가 움직이기 시작하기 전에는 `null`입니다.
- 호출할 때마다 모든 초를 다시 셉니다. 바뀌었을 때의 이벤트가 없으므로 정해진 간격으로 다시 읽습니다.

### 자신의 모듈(`SelfModules`)

- `Modules`는 보유 모듈(`PluginModuleItem`: `Uuid`, 아이템 번호인 `ConfigId`, `Quality`, 효과인 `Effects`), `EquippedUuidBySlot`은 장착 중인 칸의 번호와 모듈의 `Uuid`입니다.
- 효과(`PluginModuleEffect`)는 효과의 번호(`EffectId`)와 연결 수(`LinkCount`, 도착하지 않았으면 `null`)입니다.
- 맵에 들어갈 때마다, 내용이 같아도 `SelfModulesChanged`가 옵니다.
- 로그아웃 뒤와, 설정의 '네트워크 어댑터', '게임 실행 파일'을 바꾼 뒤에는 다음에 맵을 이동할 때까지 `null`입니다.

### 집계 설정(`AggregationSettings`)

- 설정의 '집계 설정'의 값이며, 사용자가 설정한 그대로입니다. 설정에서 저장해서 값이 바뀌면 `AggregationSettingsChanged`가 옵니다.

| `PluginAggregationSettings`의 속성 | 설정 항목 |
|---|---|
| `StopInNonCombatAreas` | 비전투 지역에서 집계 중지. 켜져 있을 때 비전투 지역에서는 아무것도 기록하지 않고, 전투의 시계도 움직이지 않습니다(`IsAggregationStopped`) |
| `AutoPauseSeconds` | 자동 일시정지의 초 수. 멈추지 않을 때는 0. 바꾼 뒤에 만든 전투부터 적용됩니다(전투별 값은 `Info.AutoPauseSeconds`) |
| `SplitOnProgress` | 진행에 따라 자동 리셋. 던전 시작, 보스 방 입장, 전멸 시 새 전투를 만듭니다. 사용자의 설정 그대로이며, 플러그인의 덮어쓰기는 `EncounterControl.AppliedOverrides`로 읽습니다 |
| `KeepResultUntilNextEvent` | 다음 이벤트까지 결과 유지. 진행에 따른 구분이나 맵 이동 뒤, 새 전투에 기록이 들어갈 때까지 미터가 이전 전투를 표시합니다 |
| `ReturnToLiveOnNextEvent` | 기록 표시 자동 해제. 기록을 열고 있는 동안 현재 전투에서 일이 일어나면 현재 전투로 돌아갑니다. 플러그인이 `KeepHistoryOpen`으로 유지하고 있는 동안은 돌아가지 않습니다 |
| `MaxSavedEncounters` | 기록 최대 보관 수. 상한이 없으면 0. 넘으면 오래된 전투부터 플러그인의 값과 함께 삭제됩니다 |
| `BenchmarkSeconds` | 측정 시간(초). 다음 측정부터 적용됩니다(측정 전투의 값은 `Info.BenchmarkSeconds`) |
| `BenchmarkFirstTargetOnly` | 처음 공격한 적만 측정. 다음 측정부터 적용됩니다(측정 전투의 값은 `Info.BenchmarkFirstTargetOnly`) |

## 이름 찾기(`Names`)

| 메서드 | 찾는 이름 |
|---|---|
| `GetSkillName(skillId)` | 스킬 |
| `GetSkillActivationName(skillId)` | 사용한 스킬. '[DPS 추이 그래프](DPS-추이-그래프)' 등의 아이콘과 같은 이름이며, 미터의 행 이름이 있으면 그 이름입니다 |
| `GetBuffName(buffId)` | 버프 |
| `GetMonsterName(monsterId)` | 몬스터 |
| `GetClassSpecName(specId)` | 클래스(`PluginPlayer.SpecId`) |
| `GetSceneName(sceneId, dungeonDifficulty)` | 맵. 난이도의 이름이 있으면 '맵 이름-난이도 이름'. `dungeonDifficulty`는 생략할 수 있습니다 |
| `GetItemName(itemId)` | 아이템(장비 포함) |

- 이름은 앱의 표시 언어의 이름입니다. 그 언어의 이름이 없으면 중국어 이름, 둘 다 없으면 `null`입니다.
- 앱의 화면과 달리 내부 이름이나 내부 ID는 붙이지 않습니다. 설정의 '내부 ID', '이름 없는 스킬과 버프'도 적용되지 않습니다.
- 1단계와 변신의 이름은 없으므로, `GetClassSpecName`은 `null`입니다.
- 직업, 깊은 잠 심상의의 유형, 시즌, 모듈 효과의 이름을 찾는 메서드는 없습니다.
- 어느 스레드에서 호출해도 괜찮습니다. 표시 언어가 바뀌면 `Localization.CultureChanged` 안에서 다시 찾습니다.

## 게임 메시지(`Packets`)

`ReadAsync`에 받을 종류를 넘기고, 도착한 메시지를 `await foreach`로 읽습니다.

```csharp
private static async Task ReadMessagesAsync(IPluginContext context, IReadOnlyCollection<PluginPacketType> types)
{
    await foreach (PluginPacketMessage message in context.Packets.ReadAsync(types).ConfigureAwait(false))
    {
        context.Logger.Info($"{message.Kind} {message.ServiceId}/{message.MethodId}: {message.Payload.Length} bytes");
    }
}
```

- `Initialize` 안에서 `_ = ReadMessagesAsync(context, types);`처럼 기다리지 않고 시작합니다.
- 받을 종류(`PluginPacketType`)는 종류(`Kind`), 서비스 번호, 메서드 번호의 조합이며, 1개 이상 넘깁니다. 세 가지가 모두 맞는 메시지만 도착합니다.
- 종류는 서버로부터의 알림(`Notify`), 게임에서 서버로의 호출(`Call`), 호출에 대한 응답(`Return`)입니다. `Return`의 번호는 응답하고 있는 호출의 번호입니다.
- `await foreach`를 시작했을 때부터 도착한 메시지를 도착한 순서대로 넘깁니다. 그 전의 것은 넘기지 않습니다. 반복을 빠져나오면 받기를 멈춥니다.
- 내용(`Payload`)은 protobuf의 바이트열입니다. `Notify`와 `Return`은 압축을 푼 뒤이며, `Return`은 응답을 감싼 형태 그대로입니다. `Call`은 압축을 풀지 않았습니다.
- `Payload`는 앱이 복사한 것이므로 언제까지 가지고 있어도 괜찮습니다.
- 아직 가져가지 않은 내용의 합계가 아래의 '전투 이벤트'와 합쳐서 플러그인 1개당 64MB를 넘으면 플러그인이 멈추고, '[플러그인](플러그인)'의 행이 '오류'가 됩니다('플러그인 오류' 창이 표시되고, 다음 실행 때 다시 불러옵니다). 받을 종류를 좁히고, 도착한 것은 바로 가져갑니다.
- `Initialize`는 UI 스레드에서 호출되므로, `ConfigureAwait(false)`를 붙이지 않으면 반복의 내용이 UI 스레드에서 동작합니다.
- 앱이 플러그인을 멈추면 반복은 끝납니다. `Stopping`을 넘기지 않았으면 예외 없이, 넘겼으면 `OperationCanceledException`으로 끝납니다.
- 게임 메시지의 번호와 내용의 형태는 이 Wiki에서 설명하지 않습니다.

## 전투 이벤트(`CombatEvents`)

`ReadAsync`에 받을 종류를 넘기고, 앱이 처리한 전투 이벤트를 `await foreach`로 읽습니다.

```csharp
private static async Task ReadCombatEventsAsync(IPluginContext context)
{
    PluginCombatEventKinds kinds = PluginCombatEventKinds.SkillActivation | PluginCombatEventKinds.MonsterHpZero;
    await foreach (PluginCombatEvent combatEvent in context.CombatEvents.ReadAsync(kinds).ConfigureAwait(false))
    {
        if (combatEvent is PluginSkillActivationEvent activation)
        {
            context.Logger.Info($"{activation.CharacterId}: {context.Names.GetSkillActivationName(activation.Record.SkillId)}");
        }
        else if (combatEvent is PluginMonsterHpZeroEvent { IsZero: true, MonsterId: { } monsterId })
        {
            context.Logger.Info($"{context.Names.GetMonsterName(monsterId)}: 0 HP");
        }
    }
}
```

| 종류 | 형식 | 오는 때 |
|---|---|---|
| `Damage` | `PluginDamageEvent` | 플레이어와 플레이어가 소환한 엔티티가 적에게 피해를 주고, 앱이 '[DPS 미터](DPS-미터)'에 더했을 때 |
| `SkillActivation` | `PluginSkillActivationEvent` | 스킬의 기록을 더했을 때(`GetSkillActivations`와 같은 기록) |
| `TakenHit` | `PluginTakenHitEvent` | 받은 피해의 기록을 더했을 때(`GetTakenHits`와 같은 기록) |
| `CombatLog` | `PluginCombatLogEvent` | 타임라인의 기록을 더했을 때(`GetCombatLog`와 같은 기록) |
| `PlayerBuff` | `PluginBuffEvent` | 플레이어의 버프의 부여, 변화, 제거가 도착했을 때 |
| `MonsterBuff` | `PluginBuffEvent` | 몬스터의 버프의 부여, 변화, 제거가 도착했을 때 |
| `MonsterSkill` | `PluginMonsterSkillEvent` | 몬스터가 사용하고 있는 스킬이 도착했을 때(사용 시작과 사용 끝) |
| `MonsterHpZero` | `PluginMonsterHpZeroEvent` | 몬스터의 HP가 0이 되었을 때, 0에서 돌아왔을 때 |

- `Initialize` 안에서 `_ = ReadCombatEventsAsync(context);`처럼 기다리지 않고 시작합니다. `ConfigureAwait(false)`와, 앱이 플러그인을 멈췄을 때 끝나는 방식은 '게임 메시지'와 같습니다.
- 종류는 `|`로 조합하여 1개 이상 넘깁니다. `None`이거나 정의에 없는 값을 포함하면 `ArgumentException`입니다.
- `await foreach`를 시작했을 때부터의 이벤트를 앱이 처리한 순서대로 넘깁니다. 그 전의 것은 넘기지 않습니다.
- 시각(`ArrivalTimeUtc`)은 그 이벤트를 운반한 메시지가 도착한 시각(UTC)입니다. 예고의 끝의 기록은 예고 바가 끝난 시각입니다.
- `SequenceNumber`는 게임 메시지(`Packets`)와 공통의 일련번호입니다. 메시지로 인해 일어난 이벤트는 그 메시지보다 뒤의 번호입니다.
- 기록의 종류(`SkillActivation`, `TakenHit`, `CombatLog`)는 기록한 전투의 `EncounterKey`와 기록의 번호(`RecordIndex`)를 가집니다. `GetLiveEncounter()`의 `EncounterKey`가 같으면 `RecordIndex + 1`을 `startIndex`에 넘겨 이어서 읽을 수 있습니다.
- `Damage`는 위의 '기록하는 규칙'으로 기록한 것만 옵니다. 다른 종류의 `IsRecorded`는 그때 앱의 현재 전투가 기록하는 규칙으로 기록하고 있었는지입니다.
- `PluginDamageEvent`의 `RowKey`는 `GetSkillTotals`의 행(`PluginSkillTotals.RowKey`)과 같습니다. `IsImmune`인 피해는 미터에 더하지 않습니다.
- `PluginBuffEvent`의 `Kind`는 부여(`Added`), 중첩이나 효과 시간의 변화(`Changed`), 제거(`Removed`), 그 시점에 붙어 있던 버프(`Present`), 그 목록의 끝(`AppearListEnd`)입니다.
  - `Present`는 주변에 들어온 엔티티의 버프 목록과, 맵을 이동한 뒤 게임이 자신의 버프를 모두 다시 붙였을 때 옵니다. 이어서 `AppearListEnd`가 1건 옵니다. 그때까지 붙어 있고 목록에 없는 버프는 보지 못한 사이에 떨어진 것입니다. 게임이 목록을 보내지 않는 등장에서는 둘 다 오지 않습니다.
  - `Changed`와 `Removed`의 버프 번호, 부여자, 부여 출처(`SourceType`, `SourceConfigId`)는 부여가 도착했을 때의 값입니다. 부여가 도착하지 않은 버프(맵에 들어오기 전부터 붙어 있던 것 등)에서는 번호가 0입니다.
  - 도착한 메시지가 운반하지 않은 값(`Level`, `Layer`, `DurationMilliseconds`, `ServerCreateTimeUtc`)은 `null`입니다.
- `PluginMonsterSkillEvent`는 사용이 끝났을 때 `SkillId`가 0으로 옵니다. 같은 스킬이 다시 도착했을 때도 옵니다. 주변에 들어왔을 때 사용하고 있던 스킬은 오지 않습니다.
- `PluginMonsterHpZeroEvent`는 최대 HP가 0인 엔티티(HP 바가 없는 장치 등)에서도 옵니다. 주변에 들어왔을 때 HP가 0이었던 몬스터는 `IsOnAppear`가 `true`로 옵니다.
- 던전의 결과와 투표 화면 동안은 앱이 버프, 피해, 치유를 처리하지 않으므로, `Damage`, `TakenHit`, `PlayerBuff`, `MonsterBuff`와 `CombatLog`의 적의 치유, 적이 적에게 준 피해, 적이 붙인 버프는 오지 않습니다.
- 아직 가져가지 않은 이벤트는 게임 메시지와 합쳐서 플러그인 1개당 64MB를 넘으면 플러그인이 멈춥니다(위의 '게임 메시지'와 같음). 받을 종류를 좁히고, 도착한 것은 바로 가져갑니다.
- 넘기는 값은 바꿀 수 없는 사본이며, 모든 플러그인에 같은 것을 넘기고 있습니다.

## 데이터를 읽을 때의 규칙

- 창의 내용, 위젯의 본체와 푸터에서 구독한 이벤트는 `Dispose`에서 해제합니다. 해제하지 않으면 닫은 창의 내용이 이벤트를 계속 받고, 메모리에도 남습니다.
- `Initialize`에서 구독한 이벤트는 `Shutdown`에서 해제합니다. 앱도 `Shutdown` 전에 해제하므로, 멈춘 뒤에 처리가 호출되는 일은 없습니다.
- 버프, 전투 집계, `GetPlayer`, `GetPlayerBuild`에는 바뀌었을 때의 이벤트가 없으므로, 타이머로 다시 읽습니다. 버프가 붙거나 떨어진 순간은 `CombatEvents`로 받을 수 있습니다.

## 넘겨주지 않는 것

- 장비의 자세한 값, 능력치, 스킬 칸, 재사용 대기시간, 던전의 목표와 점수, 채팅 등은 넘겨주지 않습니다. 필요할 때는 게임 메시지를 읽습니다. 장비의 부위와 번호, 어빌리티, 스킬 레벨은 `GetPlayerBuild`, 적의 캐스팅과 전투 화면에 경고가 표시되는 스킬은 전투 읽기 객체의 `GetMonsters`, 보스 스킬의 예고는 `GetCombatLog`로 읽을 수 있습니다.

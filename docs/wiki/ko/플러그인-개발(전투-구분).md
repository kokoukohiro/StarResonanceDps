`IPluginContext.EncounterControl`(`IPluginEncounterControlService`)로 앱의 전투 구분과 전투의 시계를 바꿉니다. 앱의 화면(미터, 추이 그래프, 타임라인, 기록)은 바꾼 구분과 시계로 표시합니다.

## 현재 전투를 구분하기(`SplitAsync`)

```csharp
private static async Task SplitNowAsync(IPluginContext context)
{
    PluginEncounterSplitResult result = await context.EncounterControl.SplitAsync().ConfigureAwait(false);
    context.Logger.Info($"{result.Outcome} {result.ClosedEncounterHadRecords}");
}
```

- 현재 전투를 닫고 새 전투를 만듭니다. '집계'의 수동 리셋과 같은 동작입니다.
- `keepPreviousInMeter`가 `true`이면, 설정의 '다음 이벤트까지 결과 유지'가 켜져 있을 때 새 전투에 기록이 들어갈 때까지 미터가 이전 전투를 표시합니다. `false`이면 바로 새 전투를 표시합니다.
- 측정 중(첫 이벤트를 기다리는 동안도)에는 아무것도 하지 않고 `SkippedBenchmark`로 끝납니다.
- 새 전투는 `GameData.EncounterStarted`, 닫은 전투는 기록이 있으면 `GameData.EncounterClosed`로 받습니다. `ClosedEncounterHadRecords`는 닫은 전투에 기록이 있었는지입니다(기록이 없는 전투는 저장하지 않습니다).

## 구분 규칙(`SetRulesAsync`)

```csharp
private static async Task RegisterRulesAsync(IPluginContext context)
{
    PluginEncounterRulesResult result = await context.EncounterControl.SetRulesAsync(new PluginEncounterRules
    {
        IdleSplitSeconds = 30,
        DungeonClock = PluginDungeonClock.DungeonServerStart,
    }).ConfigureAwait(false);
    if (result.Status == PluginEncounterRulesStatus.Pending)
    {
        context.Logger.Warning($"Held by another plugin: {string.Join(", ", result.PendingItems)}");
    }
}
```

- 앱이 게임의 메시지를 처리하면서 판정하는 규칙을 등록합니다. 플러그인이 이벤트를 받은 뒤에 구분하면, 그 사이에 도착한 메시지의 기록이 이전 전투에 들어가기 때문입니다.
- 다시 등록하면 이전 규칙을 바꾸고, `null`로 해제합니다. 앱은 규칙을 저장하지 않으므로 `Initialize`에서 자신의 설정으로 등록합니다.

| 속성 | 내용 |
|---|---|
| `IdleSplitSeconds` | 전투 이벤트가 이 초 수(1~86400) 동안 오지 않으면 현재 전투를 구분합니다. 0은 구분하지 않습니다 |
| `IntervalSplitSeconds` | 전투에서 처음 일어난 일부터 이 초 수(1~86400)가 지나면 현재 전투를 구분합니다. 멈춰 있던 동안도 셉니다. 0은 구분하지 않습니다 |
| `KeepPreviousInMeterOnConditionSplit` | 위의 두 구분에서 이전 전투를 미터에 남길지(`SplitAsync`의 `keepPreviousInMeter`와 같음) |
| `DungeonStartSplit`, `BossRoomSplit`, `WipeSplit` | 던전 시작, 보스 방 입장, 전멸에서 구분할지(`PluginAutoSplitMode`). `HostSetting`은 설정의 '진행에 따라 자동 리셋' 그대로, `Split`은 구분, `DoNotSplit`은 구분하지 않습니다 |
| `DungeonClock` | 던전 시계(아래 '던전 시계'). `None`은 사용하지 않습니다 |

- 무조작과 경과의 초는 메시지를 처리하기 직전과 1초마다 판정합니다. 구분한 뒤의 첫 전투 이벤트는 새 전투에 들어갑니다.
- 측정 전투, 닫은 전투, 전투의 시계가 아직 움직이지 않은 전투, 던전 시계의 전투에서는 무조작과 경과의 초로 구분하지 않습니다.
- 규칙은 등록한 뒤에 만드는 전투부터 적용됩니다. 무조작과 경과의 초는 현재 전투에도 적용됩니다.
- 범위 밖의 값은 `ArgumentOutOfRangeException`, 던전 시계와 맞지 않는 조합(`DungeonStartSplit`이 `DoNotSplit`, `BossRoomSplit`이나 `WipeSplit`이 `Split`)은 `ArgumentException`이 됩니다.

## 던전 시계(`DungeonClock`)

- 던전 시작에서 만드는 전투의 시계를 던전 시작부터 움직이고, 던전이 끝날 때까지 하나의 전투로 셉니다.
- 그 전투 안에서는 보스 방, 전멸, 무조작과 경과의 초로 구분하지 않고, 자동 일시정지도 사용하지 않습니다. 게임의 던전 시계가 멈춰 있던 동안(보스 방 입장부터 보스전 시작까지, 보스를 쓰러뜨린 뒤 등)은 경과 시간에서 뺍니다.
- 기점은 두 가지 중에서 고릅니다.
  - `DungeonStartArrival`: 던전 시작을 받은 시각
  - `DungeonServerStart`: 게임 던전 시계의 시작 시각(게임이 표시하는 시간의 기점). 시계는 던전 시작 조금 뒤에 도착하므로, 앱은 받은 시각으로 시작하고 시계가 도착했을 때 전투의 기록이 아직 없으면 기점을 바꿉니다. 시계를 보내지 않는 던전, 앱이 서버 시각을 아직 받지 않았을 때, 기록이 먼저 들어갔을 때는 받은 시각 그대로입니다.
- 전투의 기점은 `GameData.GetEncounter().ClockOrigin`, 게임 던전 시계의 값은 `GameData.Session.DungeonTimer`로 읽습니다([플러그인 개발(데이터)](플러그인-개발(데이터))).
- 던전 도중의 수동 리셋, `SplitAsync`, 측정 중지로 만드는 전투도 던전 시작부터 셉니다.

## 다른 플러그인과의 겹침

- `DungeonStartSplit`, `BossRoomSplit`, `WipeSplit`, `DungeonClock`은 항목마다 처음 등록한 플러그인의 값을 사용합니다. 던전 시계를 가진 플러그인은 던전 시작의 구분도 가집니다.
- 다른 플러그인이 다른 값으로 가진 항목은 `SetRulesAsync`가 `Pending`으로 끝나고 `PendingItems`에 들어갑니다. 가진 플러그인이 해제하거나 멈췄을 때 사용되고, `RulesChanged`가 옵니다.
- 지금 앱이 사용하는 덮어쓰기는 `AppliedOverrides`로 읽습니다. 설정의 '진행에 따라 자동 리셋'에는 덮어쓰는 플러그인의 이름이 표시됩니다.
- 무조작과 경과의 초는 모든 플러그인의 것을 사용합니다.

## 동작 방식

- 메서드는 어느 스레드에서든 호출할 수 있습니다. 앱은 호출 전에 받은 메시지를 처리한 뒤, 게임의 메시지를 처리하는 스레드에서 실행합니다. 캡처가 멈춰 있는 동안은 UI 스레드에서 실행합니다.
- `Task`의 이어지는 처리는 앱의 스레드에서 실행되지 않습니다. `RulesChanged`는 UI 스레드에서 옵니다.
- 앱이 플러그인을 멈추면 그 플러그인의 규칙을 해제합니다. 그 뒤의 메서드는 아무것도 하지 않고 `Unavailable`로 끝납니다.

플러그인으로 이 앱에 창, 위젯, 알림 항목을 추가하기 위한 설명입니다. 플러그인은 C#으로 만드는 .NET 클래스 라이브러리(DLL)이며, 앱 안에서 동작합니다.

## 만들 수 있는 것

| 형태 | 진입점 클래스가 구현하는 인터페이스 | 설명 |
|---|---|---|
| 창 | `IPluginWindowProvider` | '[플러그인](플러그인)'의 행을 누르면 열리는 창입니다. 내용은 자유롭게 만들 수 있습니다([플러그인 개발(창)](플러그인-개발(창))). |
| 위젯 | `IPluginWidgetProvider`, `IPluginMultiWidgetProvider` | '[위젯](위젯)'에 카드가 나열되는 위젯입니다. 창이 1개인 형태와, 대상별로 창을 여는 형태가 있습니다([플러그인 개발(위젯)](플러그인-개발(위젯))). |
| 알림 항목 | `IPluginNotificationProvider` | '[알림](알림)'에 나열되는 항목입니다([플러그인 개발(알림)](플러그인-개발(알림))). |
| 뒤에서만 동작 | 없음 | 화면 없이, 게임 데이터를 읽어 로그에 쓰는 등의 처리만 합니다. |

- 하나의 플러그인에서 창, 위젯, 알림을 조합할 수 있습니다. 진입점 클래스에 사용하는 인터페이스를 모두 구현합니다.
- 게임 데이터, 이름, 통신을 읽는 방법은 [플러그인 개발(데이터)](플러그인-개발(데이터))에 있습니다.

## 필요한 것

- Windows(64비트)와 .NET 10 SDK.
- SDK 패키지(`StarResonanceDps.PluginSdk.<버전>.nupkg`). [릴리스 노트](https://github.com/kokoukohiro/StarResonanceDps/releases)에 앱의 zip과 함께 있습니다. NuGet 공식 사이트에는 올리지 않았습니다.
- 시험할 앱. SDK는 플러그인을 사용할 앱과 같은 릴리스의 것을 사용합니다(아래 'SDK 버전').

## 프로젝트를 만드는 방법

1. `net10.0-windows`에서 WPF를 사용하는 클래스 라이브러리 프로젝트를 만듭니다.
2. 프로젝트 폴더에 `packages` 폴더를 만들고, SDK의 `.nupkg`를 넣습니다.
3. 프로젝트 폴더에 `nuget.config`를 두고, `packages`를 패키지를 가져올 곳에 추가합니다.
4. csproj에 SDK의 `PackageReference`를 씁니다. `Version`에는 넣어 둔 `.nupkg`의 버전을 씁니다.

`nuget.config`:

```xml
<?xml version="1.0" encoding="utf-8"?>
<configuration>
  <packageSources>
    <add key="local" value="packages" />
  </packageSources>
</configuration>
```

csproj:

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>net10.0-windows</TargetFramework>
    <UseWPF>true</UseWPF>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
  </PropertyGroup>

  <ItemGroup>
    <PackageReference Include="StarResonanceDps.PluginSdk" Version="0.1.0" />
  </ItemGroup>
</Project>
```

- SDK 패키지는 빌드 출력에 부품 DLL을 복사하는 설정(`EnableDynamicLoading`)을 넣습니다. csproj에 쓸 필요는 없습니다.
- 어셈블리 이름(기본값은 프로젝트 이름)이 DLL 이름과, 앱 안의 위치 `Plugins\<어셈블리 이름>\`의 이름이 됩니다.
- SDK의 형식과 멤버에 대한 설명(영어)이 패키지에 들어 있습니다. Visual Studio 등의 편집기에서 마우스를 올리면 표시됩니다.

## 진입점 클래스와 속성

```csharp
using StarResonanceDps.PluginSdk;

[assembly: PluginRegistration(typeof(MyPlugin.Plugin), PluginSdkVersion.Current)]
[assembly: PluginDisplayName("ja-JP", "私のプラグイン")]
[assembly: PluginDisplayName("en-US", "My Plugin")]
[assembly: PluginAuthor("YourName")]
[assembly: PluginVersion("1.0.0")]

namespace MyPlugin;

public sealed class Plugin : IStarResonancePlugin
{
    public void Initialize(IPluginContext context)
    {
        context.Logger.Info("Started.");
    }

    public void Shutdown()
    {
    }
}
```

- 진입점 클래스는 이 DLL 안의 public이고 중첩되지 않은 클래스로 하며, `IStarResonancePlugin`과 사용하는 화면의 인터페이스를 구현하고, 인수가 없는 public 생성자를 갖게 합니다. abstract와 제네릭 클래스는 사용할 수 없습니다.
- 속성은 어셈블리에 붙입니다.

| 속성 | 쓰는 것 | 필수 여부 |
|---|---|---|
| `PluginRegistration` | 진입점 클래스와 `PluginSdkVersion.Current` | 필수 |
| `PluginDisplayName` | 언어 이름과, 목록에 표시할 이름. 언어마다 1개 | 1개 이상 |
| `PluginGenre` | 언어 이름과, 목록에 표시할 장르. 언어마다 1개 | 창이 있는 플러그인은 1개 이상. 창이 없으면 사용하지 않습니다 |
| `PluginAuthor` | 제작자 이름 | 필수 |
| `PluginVersion` | 버전. 숫자 3개를 '.'으로 이은 형태(`1.0.0`)이며, `v`는 붙이지 않습니다 | 필수 |
| `PluginIcon` | 아이콘 이미지의 경로 | 선택. 없으면 앱의 아이콘 |

- 언어 이름은 `ja-JP`, `ko-KR`, `zh-CN`, `en-US`입니다. 앱의 표시 언어의 이름이 없으면, 언어만의 이름(`ja` 등), `en-US`, 나머지 중 하나의 순서로 고릅니다. 1개만 쓰면 어느 표시 언어에서도 그 이름이 표시됩니다.
- 속성에는 상수만 쓸 수 있으므로, 이름과 장르를 resx에서 가져올 수는 없습니다.
- 아이콘은 플러그인 DLL에 WPF 리소스로 넣은 이미지입니다. csproj에 `<Resource Include="Assets\icon.ico" />`를 쓰고, 속성에는 프로젝트로부터의 경로(`Assets/icon.ico`)를 씁니다. 크기가 다른 이미지를 가진 `.ico`나, 1장의 `.png`를 사용합니다. 목록의 행, 플러그인 창의 왼쪽 위, 창의 아이콘에 표시됩니다.

## 앱이 넘겨주는 것

`Initialize`의 인수인 `IPluginContext`로 받습니다.

| 멤버 | 내용 |
|---|---|
| `Settings` | 플러그인 폴더에 두는 설정 파일(아래 '설정') |
| `Messages` | 앱과 같은 모양의 메시지 창(아래 '메시지') |
| `Localization` | 앱의 표시 언어와, 바뀌었을 때의 이벤트(아래 '언어') |
| `Logger` | 앱의 로그(아래 '로그') |
| `GameData` | 게임 데이터([플러그인 개발(데이터)](플러그인-개발(데이터))) |
| `Names` | 게임의 번호로 이름을 찾음([플러그인 개발(데이터)](플러그인-개발(데이터))) |
| `Packets` | 게임 메시지를 읽음([플러그인 개발(데이터)](플러그인-개발(데이터))) |
| `Notifications` | 정의한 알림을 보냄([플러그인 개발(알림)](플러그인-개발(알림))) |
| `Stopping` | 앱이 이 플러그인을 멈출 때 취소됨(아래 '동작 방식') |

### 설정

```csharp
var settings = context.Settings.Load<MySettings>("settings.json");
context.Settings.Save("settings.json", settings);
```

- 파일은 앱 폴더의 `Plugins\<어셈블리 이름>\`에 놓입니다(`Settings.SettingsDirectory`). 파일 이름에는 폴더를 포함하지 않은 이름을 씁니다.
- `Load`는 파일이 없으면 `new T()`를 반환합니다. 읽을 수 없거나 JSON으로 해석할 수 없을 때는 `InvalidDataException`을 던집니다.
- `Save`는 쓸 수 없으면 예외를 던집니다.
- JSON은 `System.Text.Json`으로 읽고 씁니다. 읽을 때는 속성 이름의 대소문자를 구분하지 않습니다.
- 업데이트해도 설정 파일은 남고, 삭제하면 폴더째 사라집니다.
- `uninstall.marker`, `app_terminated.marker`와 `update.pending`으로 시작하는 이름은 앱이 같은 폴더에서 사용하므로 사용하지 마세요.

### 언어

- `Localization.CurrentCulture`는 앱의 표시 언어이며, `ja-JP`, `ko-KR`, `zh-CN`, `en-US` 중 하나입니다. 바뀌면 `CultureChanged`가 UI 스레드에서 옵니다. 설정에서 언어를 고른 시점(저장 전)에도 옵니다.
- 4개 언어의 resx를 `PluginLocalizer`로 읽을 수 있습니다. resx는 플러그인 DLL에 포함합니다. .NET의 일반 빌드는 언어마다 별도의 DLL을 만들므로, csproj에서 언어마다 이름을 정해서 포함합니다.

```xml
<ItemGroup>
  <EmbeddedResource Update="Properties\Resources.resx">
    <WithCulture>false</WithCulture>
    <LogicalName>MyPlugin.Properties.Resources.resources</LogicalName>
  </EmbeddedResource>
  <EmbeddedResource Update="Properties\Resources.ja-JP.resx">
    <WithCulture>false</WithCulture>
    <LogicalName>MyPlugin.Properties.Resources.ja-JP.resources</LogicalName>
  </EmbeddedResource>
  <EmbeddedResource Update="Properties\Resources.ko-KR.resx">
    <WithCulture>false</WithCulture>
    <LogicalName>MyPlugin.Properties.Resources.ko-KR.resources</LogicalName>
  </EmbeddedResource>
  <EmbeddedResource Update="Properties\Resources.zh-CN.resx">
    <WithCulture>false</WithCulture>
    <LogicalName>MyPlugin.Properties.Resources.zh-CN.resources</LogicalName>
  </EmbeddedResource>
</ItemGroup>
```

```csharp
var texts = new PluginLocalizer(context.Localization, typeof(Plugin).Assembly, "MyPlugin.Properties.Resources");
string title = texts["WindowTitle"];
```

- 언어가 붙지 않은 `Resources.resx`가 `en-US`입니다. 4개 언어를 모두 포함하세요. 표시 언어의 resx가 없으면 예외가 됩니다.
- 키가 표시 언어에 없으면 `en-US`, 거기에도 없으면 키를 그대로 반환합니다.
- 인덱서(`texts["WindowTitle"]`)는 XAML의 Binding에서도 사용할 수 있습니다. 언어가 바뀌면 `PropertyChanged`로 다시 읽힙니다.
- 다 쓰면 `Dispose`로 언어 이벤트의 구독을 해제합니다.

### 로그

- `Logger.Info`, `Warning`, `Error`로 앱의 로그에 씁니다. 행의 앞에 `[Plugin:<어셈블리 이름>]`이 붙습니다.
- 로그는 '[로그](로그)'와 앱 폴더의 `Data\CombatRuntime.log`에 표시됩니다. `Data\CombatRuntime.log`는 앱의 버전이 바뀌면 사라집니다.

### 메시지

- `Messages.Show(제목, 본문, 상세)`로 앱과 같은 모양의 메시지 창을 띄웁니다. 상세는 생략할 수 있습니다.
- 어느 스레드에서도 호출할 수 있습니다. UI 스레드에서 호출하면 보통 창을 닫을 때까지 돌아오지 않습니다.
- '예', '아니요'를 고르게 하는 창은 없습니다.

## 동작 방식

- 앱은 시작할 때 모든 플러그인을 설치한 순서대로 하나씩 초기화합니다(진입점 클래스를 만들고, `Initialize`를 호출하고, 위젯과 알림의 정의를 읽음). '플러그인 추가'로 추가한 플러그인은 그 자리에서 초기화합니다.
- 앱이 플러그인의 코드를 호출하는 것은 모두 UI 스레드입니다(`Initialize`, 창과 위젯의 내용을 만드는 처리, 이벤트 등). 돌아올 때까지 앱의 화면이 멈추므로, 무거운 처리는 다른 스레드에서 합니다.
- `Initialize` 안에서는 아직 알림을 보낼 수 없습니다. 알림의 정의를 읽는 것은 `Initialize` 뒤입니다.
- `Shutdown`은 앱이 종료될 때와, 앱이 플러그인을 멈췄을 때 호출됩니다. `Initialize`가 예외로 끝났을 때도 호출됩니다. 그 전에 `Stopping`이 취소되므로, 플러그인이 시작한 타이머나 작업은 `Stopping`이나 `Shutdown`에서 멈춥니다.
- 예외
  - 앱이 호출한 코드의 예외와, 플러그인 코드에서 나온 UI 스레드의 예외, 기다리지 않은 `Task`의 예외에서는 그 플러그인만 멈춥니다. '플러그인'의 행이 '오류'가 되고, '플러그인 오류' 창이 표시됩니다. 다음 실행 때 다시 불러옵니다.
  - 플러그인이 만든 스레드의 예외에서는 앱이 종료됩니다. 그 플러그인은 다시 설치하거나 새 버전으로 업데이트할 때까지 불러오지 않습니다.
  - `Shutdown`의 예외는 로그에 쓰기만 합니다.
- 멈춘 플러그인은 그 실행 동안에는 다시 움직이지 않습니다. 불러온 DLL은 앱을 닫을 때까지 해제되지 않습니다.
- UI 스레드에서 돌아오지 않는 처리(끝나지 않는 반복이나 대기)는 앱에서 멈출 수 없으며, 앱 전체가 멈춥니다.

## 시험하는 방법

1. 빌드합니다. 출력 폴더에 `<어셈블리 이름>.dll`이 생깁니다.
2. 앱의 '[플러그인](플러그인)'의 '플러그인 추가'에서 그 DLL을 고릅니다. 부품 DLL은 같은 폴더에서 함께 복사됩니다.
3. 다시 만든 DLL을 시험할 때는 앱을 닫고 `<앱 폴더>\Plugins\<어셈블리 이름>\`에 덮어쓴 다음 앱을 실행합니다. 앱이 동작하는 동안에는 DLL을 바꿀 수 없습니다.

- 예외와 로그는 '[로그](로그)'에서 볼 수 있습니다.

## 배포와 업데이트

- 배포하는 것은 `<어셈블리 이름>.dll`과, 부품이 있으면 `.deps.json`과 부품 DLL입니다(출력 폴더의 구성 그대로). 부품이 없는 플러그인은 DLL 1개로 충분합니다.
- `StarResonanceDps.PluginSdk.dll`은 배포하지 않습니다. 앱의 것이 사용됩니다.
- 사용자는 '플러그인 추가'로 `<어셈블리 이름>.dll`을 고릅니다. 부품이 고른 DLL과 같은 폴더에 없으면 추가할 수 없습니다.
- 새 버전을 배포할 때는 `PluginVersion`을 올립니다. 사용자가 '플러그인 추가'로 새 DLL을 고르면, 앱을 다시 시작할 때 교체됩니다.
- 업데이트해도 설정 파일은 남습니다. 새 버전은 이전 버전의 설정 파일을 읽을 수 있게 해 주세요.
- 어셈블리 이름을 바꾸면 다른 플러그인으로 취급됩니다(업데이트가 되지 않고, 설정도 이어지지 않습니다).
- 삭제('플러그인'의 휴지통)하면 앱을 다시 시작할 때 폴더째 사라지며, 설정 파일도 사라집니다.

## SDK 버전

- SDK 패키지의 버전은 첫 번째 숫자가 `PluginSdkVersion.Current`이며, 기능을 추가했을 때는 두 번째 이후의 숫자가 올라갑니다.
- 앱이 불러오는 것은 `PluginRegistration`에 넘긴 `PluginSdkVersion.Current`가 앱과 같고, 만든 SDK의 버전이 앱의 SDK 이하인 플러그인입니다. 맞지 않으면 '플러그인'의 행이 '오류'가 되고, 툴팁에 '이 앱의 플러그인이 아니거나 앱과 버전이 맞지 않습니다'가 표시됩니다.
- 사용자의 앱에서 불러올 수 있도록, 그 앱과 같은 릴리스의 SDK로 만드세요. 새 SDK로 만든 플러그인은 오래된 앱에서 불러올 수 없습니다.

## 주의 사항

- 어셈블리 이름은 다른 플러그인과 겹치지 않는 이름으로 하세요. 같은 어셈블리 이름의 플러그인은 같은 플러그인으로 취급됩니다(새 버전이면 교체합니다). 앱의 부품과 같은 이름의 플러그인은 불러오지 않습니다.
- DLL의 파일 이름은 어셈블리 이름과 같게 합니다.
- XAML 리소스를 가진 부품 DLL을 다른 플러그인도 다른 버전으로 사용할 수 있을 때는, 부품의 csproj에 `AssemblyVersion`을 씁니다. WPF 리소스 지정에 버전이 들어가서, 다른 버전의 같은 부품과 혼동하지 않습니다. 부품의 리소스를 직접 가리킬 때도 버전을 쓴 형태(`/<부품 이름>;v<AssemblyVersion>;component/…`)로 합니다.
- 플러그인이 사용할 수 있는 것은 SDK의 형식과 `PluginResourceKeys`의 모양 키뿐입니다. 앱 내부의 형식과 다른 리소스의 키는 예고 없이 바뀝니다.
- 플러그인은 앱 안에서 동작하며, 앱과 같은 일을 할 수 있습니다.

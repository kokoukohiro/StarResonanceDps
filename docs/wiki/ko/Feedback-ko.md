버그 제보와 기능 요청을 GitHub에 올리는 탭입니다.

## 보는 방법

- '버그 제보 · 기능 요청': 누르면 GitHub의 작성 화면을 엽니다. 앱의 버전 등 환경은 미리 입력되어 있습니다.
- '감지된 문제': 앱이 감지한 항목의 목록입니다. 항목마다 종류, 번호, 감지한 시각이 표시됩니다.

| 종류 | 내용 |
|---|---|
| 이름 없는 스킬 | 스킬 상세의 행 이름을 알 수 없었던 스킬. |
| 스킬 이름 판정 불일치 | 스킬 상세의 행 이름 판정이 두 가지로 나온 스킬. |
| 클래스 판정 불일치 | 클래스 판정이 두 가지로 나온 효과나 스킬. |

## 조작

- 체크하고 '선택한 항목 제보'를 누르면, 선택한 항목에 대해 같은 제보가 Issue에 있는지 확인하고, 없는 항목을 본문에 넣은 작성 화면을 엽니다. 하나의 화면에 다 들어가지 않을 때는 나누어 모두 엽니다. 각 화면에서 내용을 확인하고 'Create'를 누르면 제보가 완료됩니다. 작성 화면에 넣은 항목은 체크가 해제됩니다.
- 같은 제보가 있는 항목은 '제보 완료'가 되어 체크할 수 없게 됩니다. 선택한 항목이 모두 '제보 완료'면 작성 화면은 열리지 않습니다.
- '제보 상태 확인'을 누르면 목록의 모든 항목을 다시 확인합니다. 같은 제보가 있는 항목은 '제보 완료'가 되고, 같은 제보가 없어진 항목은 미제보로 돌아갑니다. 확인이 끝나면 제보 완료가 아닌 항목에 모두 체크가 붙습니다. 작성 화면은 열리지 않습니다.
- 확인할 수 없을 때(인터넷에 연결할 수 없을 때 등)는 작성 화면을 열지 않습니다.
- 항목이 많을 때나 연속해서 눌렀을 때는 확인이 끝날 때까지 시간이 걸릴 수 있습니다. 확인하는 동안 '확인 취소'를 누르면 그만둘 수 있습니다.

## 주의 사항

- 제보 내용은 GitHub에 공개되며, 작성에는 GitHub 계정이 필요합니다.
- 본문에 다른 플레이어의 정보는 들어가지 않습니다.
- '제보 완료'는 Issue에 같은 제보가 있었다는 표시입니다. 작성해도 다음에 확인할 때까지는 붙지 않습니다.
- 목록과 로그는 앱의 버전이 바뀌면 삭제됩니다.
- 로그를 요청받았을 때는 앱 폴더의 `Data\CombatRuntime.log`를 첨부하세요. 로그에는 PC의 사용자 이름이 들어 있을 수 있습니다.

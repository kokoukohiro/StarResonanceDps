'[집계](집계)'의 기록(저장된 전투)을 플러그인으로 읽고, 플러그인의 값을 전투와 함께 저장하기 위한 설명입니다. 모든 플러그인에 필요한 것은 [플러그인 개발](플러그인-개발)에, 읽은 전투의 값을 읽는 방법은 [플러그인 개발(데이터)](플러그인-개발(데이터))의 '전투 읽기 객체'에 있습니다.

## 기록(`History`)

`IPluginContext.History`(`IPluginHistoryService`)를 사용합니다. 다음 예는 전투가 기록에 저장되었을 때 그 전투에 저장한 시각을 쓰고, 전투를 다시 읽어서 모든 사람의 준 피해 합계와 쓴 값을 로그에 씁니다.

```csharp
using System.Text;
using StarResonanceDps.PluginSdk;

[assembly: PluginRegistration(typeof(MyPlugin.Plugin), PluginSdkVersion.Current)]
[assembly: PluginDisplayName("ja-JP", "私のプラグイン")]
[assembly: PluginAuthor("YourName")]
[assembly: PluginVersion("1.0.0")]

namespace MyPlugin;

public sealed class Plugin : IStarResonancePlugin
{
    private const string NoteKey = "my.note";

    private IPluginContext? _context;

    public void Initialize(IPluginContext context)
    {
        _context = context;
        context.GameData.EncounterSaved += OnEncounterSaved;
    }

    private async void OnEncounterSaved(object? sender, PluginEncounterSaved saved)
    {
        IPluginContext? context = _context;
        if (context is null)
        {
            return;
        }

        byte[] note = Encoding.UTF8.GetBytes(DateTime.UtcNow.ToString("O"));
        PluginHistoryStatus status = await context.History.SetSavedEncounterDataAsync(saved.HistoryId, NoteKey, note);
        if (status != PluginHistoryStatus.Succeeded)
        {
            context.Logger.Warning($"{saved.HistoryId}: {status}");
            return;
        }

        PluginHistoryLoadResult loaded = await context.History.LoadAsync(saved.HistoryId);
        IPluginEncounterRecord? encounter = loaded.Encounter;
        if (encounter is null)
        {
            context.Logger.Warning($"{saved.HistoryId}: {loaded.Status}");
            return;
        }

        foreach (PluginEncounterPlayer player in encounter.GetTotals().Players)
        {
            context.Logger.Info($"{player.CharacterId}: {player.Damage.Total}");
        }

        if (encounter.GetPluginData(NoteKey) is ReadOnlyMemory<byte> stored)
        {
            context.Logger.Info(Encoding.UTF8.GetString(stored.Span));
        }
    }

    public void Shutdown()
    {
        if (_context is not null)
        {
            _context.GameData.EncounterSaved -= OnEncounterSaved;
        }
    }
}
```

| 멤버 | 내용 |
|---|---|
| `GetEntriesAsync()` | 저장된 전투 목록(아래 '목록') |
| `LoadAsync(historyId)` | 저장된 전투를 열지 않고 읽음(아래 '열지 않고 읽기') |
| `OpenAsync(historyId)` | 저장된 전투를 앱에서 엶(아래 '앱에서 열기') |
| `ReturnToLiveAsync()` | 앱을 현재 전투로 되돌림(아래 '앱에서 열기') |
| `KeepHistoryOpen()` | 열어 둔 기록에서 자동으로 현재 전투로 돌아가지 않게 함(아래 '열어 둔 기록 유지') |
| `HasOpenFailed`, `OpenFailedChanged` | 마지막으로 열려고 한 전투를 읽을 수 없었는지와, 바뀌었을 때의 이벤트(아래 '열 수 없었을 때') |
| `TrySetEncounterData(encounterKey, key, data)` | 아직 저장하지 않은 전투에 플러그인의 값을 넣음(아래 '전투에 저장') |
| `SetSavedEncounterDataAsync(historyId, key, data)` | 저장된 전투의 플러그인 값을 바꿔 씀(아래 '전투에 저장') |

- 어느 스레드에서 호출해도 괜찮습니다. `OpenFailedChanged`는 UI 스레드에서 옵니다.
- `GetEntriesAsync`, `LoadAsync`, `SetSavedEncounterDataAsync`는 백그라운드 스레드에서 기록을 읽고 씁니다. 플러그인 1개당 하나씩 차례로 동작하며, 앞서 호출한 것이 끝날 때까지 기다립니다.
- 이 3개의 `cancellationToken`은 생략할 수 있습니다. 읽고 쓰기 전(`GetEntriesAsync`, `LoadAsync`는 읽은 뒤에도)에 확인하고, 취소되어 있으면 작업이 `OperationCanceledException`으로 끝납니다. 읽고 쓰는 도중에는 멈추지 않습니다.
- 저장된 전투는 기록 번호(`HistoryId`)로, 저장하기 전의 전투는 `EncounterKey`로 가리킵니다([플러그인 개발(데이터)](플러그인-개발(데이터))의 '전투 집계').
- 플러그인이 멈춘 뒤(`Shutdown` 안에서도)에는 어느 메서드도 아무것도 하지 않습니다. 작업을 반환하는 메서드는 `Unavailable`로 끝나고(`ReturnToLiveAsync`는 그대로 끝납니다), `TrySetEncounterData`는 `false`를, `KeepHistoryOpen`은 아무것도 유지하지 않는 `IDisposable`을 반환합니다. 멈추기 전에 `OpenAsync`로 요청했고 아직 열리지 않은 기록은 열지 않습니다.
- 앱을 닫기 시작한 뒤에도 `GetEntriesAsync`, `LoadAsync`, `OpenAsync`, `ReturnToLiveAsync`, `SetSavedEncounterDataAsync`는 마찬가지로 아무것도 하지 않습니다.

| `PluginHistoryStatus` | 끝나는 방식 |
|---|---|
| `Succeeded` | 성공함 |
| `NotFound` | 그 번호의 저장된 전투가 없음(설정의 '기록 최대 보관 수'로 삭제되었음 등) |
| `Failed` | 기록을 읽을 수 없었거나 쓸 수 없었음. 이유는 앱의 로그에 씁니다 |
| `Unavailable` | 플러그인이 멈춘 뒤이거나 앱을 닫기 시작한 뒤이므로 아무것도 하지 않았음 |

### 목록(`GetEntriesAsync`)

```csharp
private static async Task LogHistoryAsync(IPluginContext context)
{
    PluginHistoryListResult list = await context.History.GetEntriesAsync().ConfigureAwait(false);
    foreach (PluginHistoryEntry entry in list.Entries)
    {
        string? sceneName = entry.Info.SceneId is int sceneId
            ? context.Names.GetSceneName(sceneId, entry.Info.DungeonDifficulty)
            : null;
        context.Logger.Info($"{entry.HistoryId}: {entry.Info.CreatedUtc:O} {sceneName} {entry.Elapsed}");
    }
}
```

- 저장된 전투를 '집계'의 기록과 같이 새것부터 순서대로 반환합니다. 열지 않으므로 앱의 표시는 바뀌지 않습니다.
- 결과(`PluginHistoryListResult`)의 `Entries`에 들어가는 것은 `Status`가 `Succeeded`일 때뿐입니다.
- 앱은 전투를 저장했을 때와 앱을 닫을 때, 설정의 '기록 최대 보관 수'를 넘은 오래된 전투를 삭제합니다.

| `PluginHistoryEntry`의 속성 | 내용 |
|---|---|
| `HistoryId` | 기록 번호. `LoadAsync`, `OpenAsync`, `SetSavedEncounterDataAsync`에 넘깁니다 |
| `Info` | 맵, 서버, 측정 등의 값(`PluginEncounterInfo`, [플러그인 개발(데이터)](플러그인-개발(데이터))의 '전투의 값'). `BenchmarkFirstTargetOnly`는 `null`입니다 |
| `StartUtc` | 전투의 시계가 움직이기 시작한 시각(UTC). 움직이기 시작하지 않은 전투는 `null` |
| `Elapsed` | 전투의 경과 시간(자동 일시정지 동안 제외) |

### 열지 않고 읽기(`LoadAsync`)

- 저장된 전투를 1개 읽습니다. 열지 않으므로 위젯, '집계', `GetEncounter`는 바뀌지 않습니다.
- 결과(`PluginHistoryLoadResult`)의 `Encounter`가 읽은 전투의 읽기 객체(`IPluginEncounterRecord`)입니다. `Status`가 `Succeeded`가 아니면 `null`입니다.
- 읽기 객체를 읽는 방법은 [플러그인 개발(데이터)](플러그인-개발(데이터))의 '전투 읽기 객체'에 있습니다. `IsHistory`는 `true`이며, 그 전투에 있던 플레이어는 `GetPlayers`로 읽을 수 있습니다.
- 읽은 전투는 나중에 바뀌지 않습니다. 읽은 뒤에 `SetSavedEncounterDataAsync`로 쓴 값도 들어가지 않으므로, 필요할 때는 다시 읽습니다.
- `EncounterKey`는 읽을 때마다 새 번호가 됩니다. 같은 전투인지는 `HistoryId`로 비교합니다.
- 읽기 객체를 가지고 있는 동안에는 읽은 전투가 메모리에 남습니다. 필요한 동안만 가지고 있습니다.

### 앱에서 열기(`OpenAsync`, `ReturnToLiveAsync`)

- `OpenAsync`는 '집계'에서 기록 행을 눌렀을 때와 같이 저장된 전투를 엽니다. DPS 미터 등의 위젯과 `GetEncounter`가 그 전투가 됩니다('[집계](집계)').
- 전투는 백그라운드 스레드에서 읽고, 표시를 예약하면 작업이 `Opened`로 끝납니다. 표시되면 `GameData.ShownEncounterChanged`가 옵니다.
- 읽고 있는 동안 다른 전투나 현재 전투가 선택되면 `Superseded`로 끝납니다. `Opened` 뒤, 표시되기 전에 선택되었을 때도 표시되지 않습니다. 표시되고 있는지는 `GameData.GetShownEncounter()`로 확인합니다.
- 설정의 '기록 표시 자동 해제'가 켜져 있으면, 현재 전투에서 일이 일어났을 때와 집계가 구분되었을 때 앱이 현재 전투로 되돌립니다. 되돌리지 않게 하려면 `KeepHistoryOpen`을 사용합니다.
- `ReturnToLiveAsync`는 '집계'에서 열고 있는 기록 행을 한 번 더 눌렀을 때와 같이 현재 전투로 되돌립니다. 되돌린 뒤에 작업이 끝납니다. 현재 전투를 표시하고 있으면 아무것도 바뀌지 않습니다.
- 되돌리는 처리에서 앱에 예외가 일어났을 때는 작업이 그 예외로 끝납니다(앱의 로그에도 씁니다).

| `PluginHistoryOpenResult` | 끝나는 방식 |
|---|---|
| `Opened` | 전투를 읽고 표시를 예약했음 |
| `NotFound` | 그 번호의 저장된 전투가 없음. 표시는 바뀌지 않음 |
| `Superseded` | 읽고 있는 동안 다른 전투나 현재 전투가 선택되었음. 표시하지 않음 |
| `Failed` | 전투를 읽을 수 없었음(이유는 앱의 로그). 표시는 바뀌지 않음 |
| `Unavailable` | 플러그인이 멈춘 뒤이거나 앱을 닫기 시작한 뒤이므로 아무것도 하지 않았음 |

### 열어 둔 기록 유지(`KeepHistoryOpen`)

- 반환된 `IDisposable`을 `Dispose`할 때까지는 설정의 '기록 표시 자동 해제'가 켜져 있어도 현재 전투의 일이나 집계의 구분으로 현재 전투로 되돌리지 않습니다.
- `ReturnToLiveAsync`일 때, '집계'에서 열고 있는 기록 행을 한 번 더 눌렀을 때, 로그아웃했을 때는 현재 전투로 돌아갑니다.
- 호출할 때마다 새 `IDisposable`을 반환합니다. 같은 것을 2번 `Dispose`해도 2번째는 아무것도 하지 않습니다.
- 모든 플러그인의 `IDisposable`이 `Dispose`되면 다음 일부터 설정대로 현재 전투로 돌아갑니다.
- 플러그인이 멈추면 앱이 그 플러그인의 몫을 `Dispose`합니다.

### 열 수 없었을 때(`HasOpenFailed`)

- `HasOpenFailed`는 '집계'에서 골랐을 때를 포함해, 마지막으로 열려고 한 전투를 앱이 읽을 수 없었을 때(예외이거나 그 번호의 전투가 없음) `true`입니다. 표시는 이전 그대로입니다.
- 전투를 열었을 때와 현재 전투로 돌아갔을 때 `false`가 됩니다. `LoadAsync`로는 바뀌지 않습니다.
- 바뀌면 `OpenFailedChanged`가 옵니다. 짧은 사이의 변화는 1번으로 묶습니다.

## 전투에 저장

플러그인의 값을 바이트열로 전투와 함께 저장하고, 나중에 기록에서 다시 읽을 수 있습니다.

| 메서드 | 쓰는 전투 | 결과 |
|---|---|---|
| `TrySetEncounterData(encounterKey, key, data)` | 아직 저장하지 않은 전투(현재 전투, 또는 닫은 뒤 저장하기 전의 전투). `encounterKey`는 전투의 `EncounterKey`입니다 | 넣을 수 있으면 `true` |
| `SetSavedEncounterDataAsync(historyId, key, data)` | 저장된 전투. `historyId`는 기록 번호입니다 | `PluginHistoryStatus` |

- 값은 키별로 가집니다. 키는 1~128자의 영숫자와 '.', '-', '_'이며, 대소문자는 구분하지 않습니다.
- 읽고 쓸 수 있는 것은 이 플러그인의 값뿐입니다. 읽는 것은 전투 읽기 객체의 `GetPluginData(key)`이며, 없으면 `null`입니다.
- 1개의 전투에 저장할 수 있는 것은 플러그인 1개당 키 32개(`PluginEncounterDataLimits.MaxKeys`), 합계 4MiB(`PluginEncounterDataLimits.MaxTotalBytes`)까지입니다.
- 빈 값을 쓰면 그 키를 삭제합니다. 값은 앱이 복사하므로, 넘긴 뒤에 고쳐 써도 저장된 값은 바뀌지 않습니다.
- 키가 규칙에 맞지 않을 때와 값이 4MiB를 넘을 때는 호출한 시점에 `ArgumentException`이 됩니다. `GetPluginData`도 키가 규칙에 맞지 않으면 `ArgumentException`입니다.
- 키의 수나 합계가 상한을 넘을 때는 쓰지 않고 `InvalidOperationException`이 됩니다(`SetSavedEncounterDataAsync`는 작업이 이 예외로 끝납니다).
- 값은 전투와 함께 삭제됩니다(설정의 '기록 최대 보관 수'). 플러그인을 삭제해도 남으며, 같은 어셈블리 이름의 플러그인을 다시 설치하면 읽을 수 있습니다. 어셈블리 이름을 바꾸면 이전 값은 읽을 수 없습니다.

### 아직 저장하지 않은 전투(`TrySetEncounterData`)

- 현재 전투(`GameData.GetLiveEncounter()`의 `EncounterKey`) 등에 값을 넣어 두면, 앱이 전투를 저장할 때 함께 저장합니다.
- 저장한 뒤의 전투에는 넣을 수 없으며 `false`를 반환합니다. `GameData.EncounterSaved` 뒤에는 `SetSavedEncounterDataAsync`로 씁니다.
- `GameData.EncounterClosed`의 처리 안에서 넣은 값은 전투와 함께 저장된다고는 할 수 없습니다. 닫은 전투의 마지막 값은 `EncounterSaved`를 받은 뒤 `SetSavedEncounterDataAsync`로 씁니다.
- 기록이 없는 전투는 저장되지 않으며, 넣은 값도 함께 버립니다.
- 앱을 닫을 때는 마지막 전투를 저장한 뒤에 플러그인을 멈추므로, `Shutdown` 안에서는 `false`입니다.

### 저장된 전투(`SetSavedEncounterDataAsync`)

- 저장된 전투의 그 키의 값을 바꿉니다.
- 그 번호의 전투가 없으면 `NotFound`, 쓸 수 없으면 `Failed`(이유는 앱의 로그)로 끝납니다.
- '집계'에서 열고 있는 전투와, 이전 전투를 표시하고 있는 동안의 그 전투에는 새 값이 들어갑니다. 이전에 `LoadAsync`로 읽은 전투와, 앱이 더 이상 표시하지 않는 전투의 읽기 객체에는 들어가지 않습니다.
- 쓰고 있는 동안 같은 전투를 열면, 연 전투에 새 값이 들어가지 않을 수 있습니다. 기록에는 들어가 있으므로 `LoadAsync`로 다시 읽을 수 있습니다.

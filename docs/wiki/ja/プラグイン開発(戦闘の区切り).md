`IPluginContext.EncounterControl`(`IPluginEncounterControlService`)で、アプリの戦闘の区切りと戦闘の時計を変えます。アプリの画面(メーター・推移グラフ・タイムライン・履歴)は、変えた区切りと時計で表示します。

## 今の戦闘を区切る(`SplitAsync`)

```csharp
private static async Task SplitNowAsync(IPluginContext context)
{
    PluginEncounterSplitResult result = await context.EncounterControl.SplitAsync().ConfigureAwait(false);
    context.Logger.Info($"{result.Outcome} {result.ClosedEncounterHadRecords}");
}
```

- 今の戦闘を閉じて、新しい戦闘を作ります。「集計」の手動のリセットと同じ動きです
- `keepPreviousInMeter`が`true`なら、全体設定の「次のイベントまで結果を保持」がオンのとき、新しい戦闘に記録が入るまでメーターが前の戦闘を映します。`false`なら、すぐ新しい戦闘を映します
- 計測中(最初のできごとを待っている間も)は何もせず、`SkippedBenchmark`で終わります
- 新しい戦闘は`GameData.EncounterStarted`、閉じた戦闘は記録があれば`GameData.EncounterClosed`で受け取ります。`ClosedEncounterHadRecords`は、閉じた戦闘に記録があったかです(記録の無い戦闘は保存しません)

## 区切りの規則(`SetRulesAsync`)

```csharp
private static async Task RegisterRulesAsync(IPluginContext context)
{
    PluginEncounterRulesResult result = await context.EncounterControl.SetRulesAsync(new PluginEncounterRules
    {
        IdleSplitSeconds = 30,
        DungeonClock = PluginDungeonClock.DungeonServerStart,
    }).ConfigureAwait(false);
    if (result.Status == PluginEncounterRulesStatus.Pending)
    {
        context.Logger.Warning($"Held by another plugin: {string.Join(", ", result.PendingItems)}");
    }
}
```

- アプリがゲームのメッセージを処理しながら判定する規則を登録します。プラグインがイベントを受けてから区切ると、その間に受信したメッセージの記録が前の戦闘に入るためです
- 登録し直すと前の規則を置き換え、`null`で外します。アプリは規則を保存しないので、`Initialize`で自分の設定から登録します

| プロパティ | 中身 |
|---|---|
| `IdleSplitSeconds` | 戦闘のできごとがこの秒数(1〜86400)来なければ、今の戦闘を区切ります。0は区切りません |
| `IntervalSplitSeconds` | 最初の戦闘のできごとからこの秒数(1〜86400)たったら、今の戦闘を区切ります。止まっていた間も数えます。0は区切りません |
| `KeepPreviousInMeterOnConditionSplit` | 上の2つの区切りで、前の戦闘をメーターに残すか(`SplitAsync`の`keepPreviousInMeter`と同じ) |
| `DungeonStartSplit`・`BossRoomSplit`・`WipeSplit` | ダンジョンの開始・ボス部屋への入場・全滅で区切るか(`PluginAutoSplitMode`)。`HostSetting`は全体設定の「進行で自動リセット」のまま、`Split`は区切る、`DoNotSplit`は区切りません |
| `DungeonClock` | ダンジョンの時計(下の「ダンジョンの時計」)。`None`は使いません |

- 無操作と経過の秒は、メッセージを処理する直前と1秒ごとに判定します。区切った後の最初の戦闘のできごとは、新しい戦闘に入ります
- 計測の戦闘・閉じた戦闘・戦闘の時計がまだ動いていない戦闘・ダンジョンの時計の戦闘では、無操作と経過の秒で区切りません
- 規則は登録した後に作る戦闘から効きます。無操作と経過の秒は、今の戦闘にも効きます
- 範囲の外の値は`ArgumentOutOfRangeException`、ダンジョンの時計と合わない組(`DungeonStartSplit`が`DoNotSplit`、`BossRoomSplit`か`WipeSplit`が`Split`)は`ArgumentException`になります

## ダンジョンの時計(`DungeonClock`)

- ダンジョンの開始で作る戦闘の時計を、ダンジョンの開始から動かし、ダンジョンの終わりまで1つの戦闘で数えます
- その戦闘の中では、ボス部屋・全滅・無操作と経過の秒で区切らず、自動一時停止も使いません。ゲームのダンジョンの時計が止まっていた間(ボス部屋への入場からボス戦の始まりまで、ボスを倒した後など)は、経過時間から除きます
- 起点は2つから選びます
  - `DungeonStartArrival`: ダンジョンの開始を受信した時刻
  - `DungeonServerStart`: ゲームのダンジョンの時計の開始時刻(ゲームが表示する時間の起点)。時計はダンジョンの開始の少し後に受信するため、アプリはダンジョンの開始を受信した時刻で始め、時計を受信したときに戦闘の記録がまだ無ければ起点を置き換えます。時計を送らないダンジョン、アプリがサーバーの時刻をまだ受信していないとき、記録が先に入ったときは、受信した時刻のままです
- 戦闘の起点は`GameData.GetEncounter().ClockOrigin`、ゲームのダンジョンの時計の値は`GameData.Session.DungeonTimer`で読みます([プラグイン開発(データ)](プラグイン開発(データ)))
- ダンジョンの途中の手動のリセット・`SplitAsync`・計測の停止で作る戦闘も、ダンジョンの開始から数えます

## 他のプラグインとの重なり

- `DungeonStartSplit`・`BossRoomSplit`・`WipeSplit`・`DungeonClock`は、項目ごとに、最初に登録したプラグインの値を使います。ダンジョンの時計を持つプラグインは、ダンジョンの開始の区切りも持ちます
- 他のプラグインが違う値で持っている項目は、`SetRulesAsync`が`Pending`で終わり、`PendingItems`に入ります。持っているプラグインが外したか止まったときに使われ、`RulesChanged`が来ます
- 今アプリが使っている上書きは`AppliedOverrides`で読みます。全体設定の「進行で自動リセット」には、上書きしているプラグインの名前が表示されます
- 無操作と経過の秒は、すべてのプラグインの分を使います

## 動き方

- メソッドは、どのスレッドからでも呼べます。アプリは、呼ぶ前に受信したメッセージを処理した後に、ゲームのメッセージを処理するスレッドで実行します。キャプチャが止まっている間はUIスレッドで実行します
- `Task`の続きは、アプリのスレッドでは実行されません。`RulesChanged`はUIスレッドで来ます
- アプリがプラグインを止めると、そのプラグインの規則を外します。その後のメソッドは何もせず、`Unavailable`で終わります

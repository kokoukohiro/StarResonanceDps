プラグインで、このアプリにウィンドウ・ウィジェット・通知の項目を足すための説明です。プラグインはC#で作る.NETのクラスライブラリ(DLL)で、アプリの中で動きます。

## 作れるもの

| 形 | 入口のクラスが実装するインターフェース | 説明 |
|---|---|---|
| ウィンドウ | `IPluginWindowProvider` | 「[プラグイン](プラグイン)」の行を押すと開くウィンドウです。中身は自由に作れます([プラグイン開発(ウィンドウ)](プラグイン開発(ウィンドウ))) |
| ウィジェット | `IPluginWidgetProvider`・`IPluginMultiWidgetProvider` | 「[ウィジェット](ウィジェット)」にカードが並ぶウィジェットです。ウィンドウが1枚の形と、相手ごとにウィンドウを開く形があります([プラグイン開発(ウィジェット)](プラグイン開発(ウィジェット))) |
| 通知の項目 | `IPluginNotificationProvider` | 「[通知](通知)」に並ぶ項目です([プラグイン開発(通知)](プラグイン開発(通知))) |
| 裏で動くだけ | なし | 画面を持たず、ゲームのデータを読んでログに書くなどの処理だけをします |

- 1つのプラグインで、ウィンドウ・ウィジェット・通知を組み合わせられます。入口のクラスに、使うインターフェースを全部実装します
- ゲームのデータ・名前・通信の読み方は、[プラグイン開発(データ)](プラグイン開発(データ))にあります

## 必要なもの

- Windows(64ビット)と.NET 10 SDK
- SDKのパッケージ(`StarResonanceDps.PluginSdk.<バージョン>.nupkg`)。[Releases](https://github.com/kokoukohiro/StarResonanceDps/releases)に、アプリのzipと並んでいます。NuGetの公式のサイトには置いていません
- 試すためのアプリ。SDKは、プラグインを使うアプリと同じリリースのものを使います(下の「SDKのバージョン」)

## プロジェクトの作り方

1. `net10.0-windows`でWPFを使うクラスライブラリのプロジェクトを作ります
2. プロジェクトのフォルダに`packages`フォルダを作り、SDKの`.nupkg`を置きます
3. プロジェクトのフォルダに`nuget.config`を置き、`packages`をパッケージの取得先に足します
4. csprojに、SDKの`PackageReference`を書きます。`Version`には、置いた`.nupkg`のバージョンを書きます

`nuget.config`:

```xml
<?xml version="1.0" encoding="utf-8"?>
<configuration>
  <packageSources>
    <add key="local" value="packages" />
  </packageSources>
</configuration>
```

csproj:

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>net10.0-windows</TargetFramework>
    <UseWPF>true</UseWPF>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
  </PropertyGroup>

  <ItemGroup>
    <PackageReference Include="StarResonanceDps.PluginSdk" Version="1.0.0" />
  </ItemGroup>
</Project>
```

- SDKのパッケージは、ビルドの出力に部品のDLLを写す設定(`EnableDynamicLoading`)を入れます。csprojに書く必要はありません
- アセンブリ名(既定はプロジェクトの名前)が、DLLの名前と、アプリの中の置き場所`Plugins\<アセンブリ名>\`の名前になります
- SDKの型とメンバーの説明(英語)が、パッケージに入っています。Visual Studioなどのエディターで、マウスを乗せると出ます

## 入口のクラスと属性

```csharp
using StarResonanceDps.PluginSdk;

[assembly: PluginRegistration(typeof(MyPlugin.Plugin), PluginSdkVersion.Current)]
[assembly: PluginDisplayName("ja-JP", "私のプラグイン")]
[assembly: PluginDisplayName("en-US", "My Plugin")]
[assembly: PluginAuthor("YourName")]
[assembly: PluginVersion("1.0.0")]

namespace MyPlugin;

public sealed class Plugin : IStarResonancePlugin
{
    public void Initialize(IPluginContext context)
    {
        context.Logger.Info("Started.");
    }

    public void Shutdown()
    {
    }
}
```

- 入口のクラスは、このDLLの中のpublicで入れ子でないクラスにし、`IStarResonancePlugin`と、使う画面のインターフェースを実装し、引数なしのpublicコンストラクターを持たせます。abstractとジェネリックのクラスは使えません
- 属性はアセンブリに付けます

| 属性 | 書くこと | 必須か |
|---|---|---|
| `PluginRegistration` | 入口のクラスと`PluginSdkVersion.Current` | 必須 |
| `PluginDisplayName` | 言語の名前と、一覧に出す名前。言語ごとに1つ | 1つ以上 |
| `PluginGenre` | 言語の名前と、一覧に出すジャンル。言語ごとに1つ | ウィンドウのあるプラグインは1つ以上。ウィンドウが無ければ使いません |
| `PluginAuthor` | 制作者の名前 | 必須 |
| `PluginVersion` | バージョン。数字3つを「.」でつないだ形(`1.0.0`)で、`v`は付けません | 必須 |
| `PluginIcon` | アイコンの画像のパス | 任意。無ければアプリのアイコン |

- 言語の名前は`ja-JP`・`ko-KR`・`zh-CN`・`en-US`です。アプリの表示言語の名前が無ければ、言語だけの名前(`ja`など)、`en-US`、残りのどれか、の順で選びます。1つだけ書けば、どの表示言語でもその名前が出ます
- 属性には定数しか書けないので、名前とジャンルをresxから引くことはできません
- アイコンは、プラグインのDLLにWPFの資源として入れた画像です。csprojに`<Resource Include="Assets\icon.ico" />`を書き、属性にはプロジェクトからのパス(`Assets/icon.ico`)を書きます。大きさの違う画像を持つ`.ico`か、1枚の`.png`を使います。一覧の行・プラグインのウィンドウの左上・ウィンドウのアイコンに出ます

### ビルドの検査

SDKのパッケージには、属性と定義を確かめる検査が入っています。エラーがあるとビルドが止まります。アプリも、読み込むときに同じことを確かめます。

| ID | 重さ | 内容 |
|---|---|---|
| SRDPS001 | エラー | `PluginRegistration`が無い |
| SRDPS003 | エラー | `PluginRegistration`のバージョンが、参照しているSDKと違う。数字を直に書かず、`PluginSdkVersion.Current`を渡します |
| SRDPS004 | エラー | 入口のクラスが、上の決まりに合わない |
| SRDPS005 | エラー | `PluginDisplayName`が無い |
| SRDPS006 | エラー | 同じ言語の`PluginDisplayName`か`PluginGenre`が2つある |
| SRDPS007 | エラー | `PluginAuthor`が無いか、空 |
| SRDPS008 | エラー | ウィンドウのあるプラグインに`PluginGenre`が無い |
| SRDPS009 | 警告 | ウィンドウの無いプラグインに`PluginGenre`がある(使われません) |
| SRDPS010 | 警告 | 言語の名前か文字が空の`PluginDisplayName`・`PluginGenre`がある(使われません) |
| SRDPS011 | 警告 | `PluginIcon`のパスが空 |
| SRDPS012 | エラー | `PluginVersion`が無いか、数字3つの形でない |
| SRDPS013 | エラー | 相手ごとにウィンドウを開くウィジェットの`GetWidgetTargets`が、いつも空の一覧を返す |
| SRDPS014 | エラー | ウィジェット・通知・設定の名前や、通知の既定の文など、必須の文字が空 |

## アプリが渡すもの

`Initialize`の引数の`IPluginContext`で受け取ります。

| メンバー | 中身 |
|---|---|
| `Settings` | プラグインのフォルダに置く設定ファイル(下の「設定」) |
| `Messages` | アプリと同じ見た目のメッセージのウィンドウ(下の「メッセージ」) |
| `Localization` | アプリの表示言語と、変わったときのイベント(下の「言語」) |
| `Logger` | アプリのログ(下の「ログ」) |
| `GameData` | ゲームのデータ([プラグイン開発(データ)](プラグイン開発(データ))) |
| `Names` | ゲームの番号から名前を引く([プラグイン開発(データ)](プラグイン開発(データ))) |
| `Packets` | ゲームのメッセージを読む([プラグイン開発(データ)](プラグイン開発(データ))) |
| `Notifications` | 定義した通知を出す([プラグイン開発(通知)](プラグイン開発(通知))) |
| `Stopping` | アプリがこのプラグインを止めるときにキャンセルされる(下の「動き方」) |

### 設定

```csharp
var settings = context.Settings.Load<MySettings>("settings.json");
context.Settings.Save("settings.json", settings);
```

- ファイルは、アプリのフォルダの`Plugins\<アセンブリ名>\`に置かれます(`Settings.SettingsDirectory`)。ファイル名には、フォルダを含まない名前を書きます
- `Load`は、ファイルが無ければ`new T()`を返します。読めない・JSONとして解けないときは`InvalidDataException`を投げます
- `Save`は、書けなければ例外を投げます
- JSONは`System.Text.Json`で読み書きします。読むときは、プロパティ名の大文字と小文字を区別しません
- 更新しても設定ファイルは残り、削除するとフォルダごと消えます
- `uninstall.marker`・`app_terminated.marker`と、`update.pending`で始まる名前は、アプリが同じフォルダで使うので使わないでください

### 言語

- `Localization.CurrentCulture`はアプリの表示言語で、`ja-JP`・`ko-KR`・`zh-CN`・`en-US`のどれかです。変わると`CultureChanged`がUIスレッドで来ます。全体設定で言語を選んだ時点(保存の前)にも来ます
- 4言語のresxを、`PluginLocalizer`で読めます。resxはプラグインのDLLに埋め込みます。.NETの普通のビルドは言語ごとに別のDLLを作るので、csprojで言語ごとに名前を決めて埋め込みます

```xml
<ItemGroup>
  <EmbeddedResource Update="Properties\Resources.resx">
    <WithCulture>false</WithCulture>
    <LogicalName>MyPlugin.Properties.Resources.resources</LogicalName>
  </EmbeddedResource>
  <EmbeddedResource Update="Properties\Resources.ja-JP.resx">
    <WithCulture>false</WithCulture>
    <LogicalName>MyPlugin.Properties.Resources.ja-JP.resources</LogicalName>
  </EmbeddedResource>
  <EmbeddedResource Update="Properties\Resources.ko-KR.resx">
    <WithCulture>false</WithCulture>
    <LogicalName>MyPlugin.Properties.Resources.ko-KR.resources</LogicalName>
  </EmbeddedResource>
  <EmbeddedResource Update="Properties\Resources.zh-CN.resx">
    <WithCulture>false</WithCulture>
    <LogicalName>MyPlugin.Properties.Resources.zh-CN.resources</LogicalName>
  </EmbeddedResource>
</ItemGroup>
```

```csharp
var texts = new PluginLocalizer(context.Localization, typeof(Plugin).Assembly, "MyPlugin.Properties.Resources");
string title = texts["WindowTitle"];
```

- 言語の付かない`Resources.resx`が`en-US`です。4言語とも埋め込んでください。表示言語のresxが無いと例外になります
- キーが表示言語に無ければ`en-US`、それにも無ければキーをそのまま返します
- インデクサー(`texts["WindowTitle"]`)はXAMLのBindingでも使えます。言語が変わると`PropertyChanged`で読み直されます
- 使い終わったら`Dispose`で、言語のイベントの購読を外します

### ログ

- `Logger.Info`・`Warning`・`Error`で、アプリのログへ書きます。行の頭に`[Plugin:<アセンブリ名>]`が付きます
- ログは「[ログ](ログ)」と、アプリのフォルダの`Data\CombatRuntime.log`に出ます。`Data\CombatRuntime.log`は、アプリのバージョンが変わると消えます

### メッセージ

- `Messages.Show(タイトル, 本文, 詳細)`で、アプリと同じ見た目のメッセージのウィンドウを出します。詳細は省けます
- どのスレッドからでも呼べます。UIスレッドから呼ぶと、ふつうはウィンドウを閉じるまで戻りません
- 「はい」「いいえ」を選ばせるウィンドウはありません

## 動き方

- アプリは起動時に、全部のプラグインを入れた順に1つずつ初期化します(入口のクラスを作り、`Initialize`を呼び、ウィジェットと通知の定義を読む)。「プラグインを追加」で足したプラグインは、その場で初期化します
- アプリがプラグインのコードを呼ぶのは、全部UIスレッドです(`Initialize`、ウィンドウとウィジェットの中身を作る処理、イベントなど)。戻るまでアプリの画面が止まるので、重い処理は別のスレッドで行います
- `Initialize`の中では、まだ通知を出せません。通知の定義を読むのは`Initialize`の後です
- `Shutdown`は、アプリの終了時と、アプリがプラグインを止めたときに呼ばれます。`Initialize`が例外で終わったときも呼ばれます。その前に`Stopping`がキャンセルされるので、プラグインが始めたタイマーやタスクは`Stopping`か`Shutdown`で止めます
- 例外
  - アプリが呼んだコードの例外と、プラグインのコードから出たUIスレッドの例外・待たれなかった`Task`の例外では、そのプラグインだけが止まります。「プラグイン」の行が「エラー」になり、「プラグインエラー」のウィンドウが出ます。次の起動で、また読み込みます
  - プラグインが作ったスレッドの例外では、アプリが終わります。そのプラグインは、入れ直すか新しいバージョンに更新するまで読み込まれません
  - `Shutdown`の例外は、ログに書くだけです
- 止まったプラグインは、その起動の間は動かし直しません。読み込んだDLLは、アプリを閉じるまで外れません
- UIスレッドで戻らない処理(終わらない繰り返しや待ち合わせ)は、アプリでは止められず、アプリ全体が固まります

## 試し方

1. ビルドします。出力のフォルダに`<アセンブリ名>.dll`ができます
2. アプリの「[プラグイン](プラグイン)」の「プラグインを追加」で、そのDLLを選びます。部品のDLLは、同じフォルダから一緒に写されます
3. 作り直したDLLを試すときは、アプリを閉じて`<アプリのフォルダ>\Plugins\<アセンブリ名>\`へ上書きし、アプリを起動します。動いている間は、DLLを置き換えられません

- 例外とログは「[ログ](ログ)」で見られます

## 配り方と更新

- 配るのは、`<アセンブリ名>.dll`と、部品があれば`.deps.json`と部品のDLLです(出力のフォルダの並びのまま)。部品の無いプラグインは、DLL1つで足ります
- `StarResonanceDps.PluginSdk.dll`は配りません。アプリのものが使われます
- アプリのものが使われるのは、SDKと.NET・WPFだけです。ほかの部品(NuGetで足したライブラリなど)は、アプリに同じものが入っていても一緒に配ります
- 使う人は「プラグインを追加」で`<アセンブリ名>.dll`を選びます。部品が選んだDLLと同じフォルダに無いと、追加できません
- 新しいバージョンを配るときは`PluginVersion`を上げます。使う人が「プラグインを追加」で新しいDLLを選ぶと、アプリを再起動したときに置き換わります
- 更新しても設定ファイルは残ります。新しいバージョンは、前のバージョンの設定ファイルを読めるようにしてください
- アセンブリ名を変えると、別のプラグインとして扱われます(更新にならず、設定も引き継がれません)
- 削除(「プラグイン」のゴミ箱)すると、アプリを再起動したときにフォルダごと消え、設定ファイルも消えます

## SDKのバージョン

- SDKのパッケージのバージョンは、1つ目の数字が`PluginSdkVersion.Current`で、機能を足したときは2つ目以降が上がります
- アプリが読むのは、`PluginRegistration`に渡した`PluginSdkVersion.Current`がアプリと同じで、作ったSDKのバージョンがアプリのSDK以下のプラグインです。合わないと、「プラグイン」の行が「エラー」になり、「プラグインエラー」のウィンドウに「このアプリのプラグインではないか、アプリとバージョンが一致しません。」と表示されます
- 使う人のアプリで読めるように、そのアプリと同じリリースのSDKで作ってください。新しいSDKで作ったプラグインは、古いアプリでは読めません
- 新しいSDKに替えるときは、`packages`の`.nupkg`を置き換え、csprojの`Version`を新しいバージョンに書き換えます。`Version`が前のままだと、NuGetのキャッシュにある前のSDKでビルドされ、警告も出ません

## 注意

- アセンブリ名は、ほかのプラグインと重ならない名前にしてください。同じアセンブリ名のプラグインは、同じプラグインとして扱われます(新しいバージョンなら置き換えます)。アプリの部品と同じ名前のプラグインは読み込みません
- DLLのファイル名は、アセンブリ名と同じにします
- XAMLの資源を持つ部品のDLLを、ほかのプラグインも別のバージョンで使うかもしれないときは、部品のcsprojに`AssemblyVersion`を書きます。WPFの資源の指定にバージョンが入り、別のバージョンの同じ部品と取り違えません。部品の資源を自分で指すときも、バージョンを書いた形(`/<部品の名前>;v<AssemblyVersion>;component/…`)にします
- プラグインが使えるのは、SDKの型と`PluginResourceKeys`の見た目のキーだけです。アプリの内部の型と、ほかの資源のキーは、予告なく変わります
- プラグインはアプリの中で動き、アプリと同じことができます

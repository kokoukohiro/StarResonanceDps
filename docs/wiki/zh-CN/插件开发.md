这是用插件为本应用添加窗口、小组件和通知项目的说明。插件是用C#编写的.NET类库(DLL)，在应用中运行。

## 可以制作的内容

| 形式 | 入口类实现的接口 | 说明 |
|---|---|---|
| 窗口 | `IPluginWindowProvider` | 点击“[插件](插件)”中的行时打开的窗口。内容可以自由制作([插件开发(窗口)](插件开发(窗口))) |
| 小组件 | `IPluginWidgetProvider`、`IPluginMultiWidgetProvider` | 卡片排列在“[小组件](小组件)”中的小组件。有只有1个窗口的形式，和按对象打开窗口的形式([插件开发(小组件)](插件开发(小组件))) |
| 通知项目 | `IPluginNotificationProvider` | 排列在“[通知](通知(简体中文))”中的项目([插件开发(通知)](插件开发(通知))) |
| 只在后台运行 | 无 | 没有画面，只进行读取游戏数据并写入日志等处理 |

- 一个插件中可以组合窗口、小组件和通知。在入口类中实现所有要使用的接口
- 游戏数据、名称和通信的读取方法，请参阅[插件开发(数据)](插件开发(数据))

## 所需内容

- Windows(64位)和.NET 10 SDK
- SDK的包(`StarResonanceDps.PluginSdk.<版本>.nupkg`)。与应用的zip一起放在[Releases](https://github.com/kokoukohiro/StarResonanceDps/releases)中。没有放在NuGet的官方网站上
- 用于测试的应用。SDK使用与要使用插件的应用相同发布版本的SDK(下面的“SDK的版本”)

## 项目的创建方法

1. 创建以`net10.0-windows`为目标并使用WPF的类库项目
2. 在项目文件夹中创建`packages`文件夹，并放入SDK的`.nupkg`
3. 在项目文件夹中放置`nuget.config`，将`packages`添加为包的获取来源
4. 在csproj中写入SDK的`PackageReference`。`Version`中写入所放置的`.nupkg`的版本

`nuget.config`：

```xml
<?xml version="1.0" encoding="utf-8"?>
<configuration>
  <packageSources>
    <add key="local" value="packages" />
  </packageSources>
</configuration>
```

csproj：

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>net10.0-windows</TargetFramework>
    <UseWPF>true</UseWPF>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
  </PropertyGroup>

  <ItemGroup>
    <PackageReference Include="StarResonanceDps.PluginSdk" Version="1.0.0" />
  </ItemGroup>
</Project>
```

- SDK的包会加入将依赖项的DLL复制到生成输出中的设置(`EnableDynamicLoading`)。无需写在csproj中
- 程序集名称(默认为项目名称)会成为DLL的名称，以及应用中放置位置`Plugins\<程序集名称>\`的名称
- 包中包含SDK的类型和成员的说明(英语)。在Visual Studio等编辑器中将鼠标悬停在上面时会显示

## 入口类和特性

```csharp
using StarResonanceDps.PluginSdk;

[assembly: PluginRegistration(typeof(MyPlugin.Plugin), PluginSdkVersion.Current)]
[assembly: PluginDisplayName("ja-JP", "私のプラグイン")]
[assembly: PluginDisplayName("en-US", "My Plugin")]
[assembly: PluginAuthor("YourName")]
[assembly: PluginVersion("1.0.0")]

namespace MyPlugin;

public sealed class Plugin : IStarResonancePlugin
{
    public void Initialize(IPluginContext context)
    {
        context.Logger.Info("Started.");
    }

    public void Shutdown()
    {
    }
}
```

- 入口类应为此DLL中public且非嵌套的类，实现`IStarResonancePlugin`和要使用的画面的接口，并具有无参数的public构造函数。不能使用abstract类和泛型类
- 特性加在程序集上

| 特性 | 写入的内容 | 是否必需 |
|---|---|---|
| `PluginRegistration` | 入口类和`PluginSdkVersion.Current` | 必需 |
| `PluginDisplayName` | 语言名称和列表中显示的名称。每种语言1个 | 1个以上 |
| `PluginGenre` | 语言名称和列表中显示的类型。每种语言1个 | 有窗口的插件需要1个以上。没有窗口时不使用 |
| `PluginAuthor` | 制作者的名称 | 必需 |
| `PluginVersion` | 版本。用“.”连接3个数字的形式(`1.0.0`)，不加`v` | 必需 |
| `PluginIcon` | 图标图片的路径 | 可选。没有时使用应用的图标 |

- 语言名称为`ja-JP`、`ko-KR`、`zh-CN`、`en-US`。没有应用显示语言的名称时，按只有语言的名称(`ja`等)、`en-US`、其余任意一个的顺序选择。只写1个时，任何显示语言都会显示该名称
- 特性中只能写常量，因此无法从resx获取名称和类型
- 图标是作为WPF资源放入插件DLL中的图片。在csproj中写入`<Resource Include="Assets\icon.ico" />`，在特性中写入从项目开始的路径(`Assets/icon.ico`)。使用包含不同尺寸图片的`.ico`，或1张`.png`。会显示在列表的行、插件窗口的左上角和窗口的图标中

### 生成检查

SDK的包中包含检查特性和定义的功能。有错误时生成会停止。应用在加载时也会进行相同的检查。

| ID | 级别 | 内容 |
|---|---|---|
| SRDPS001 | 错误 | 没有`PluginRegistration` |
| SRDPS003 | 错误 | `PluginRegistration`的版本与所引用的SDK不同。不要直接写数字，请传入`PluginSdkVersion.Current` |
| SRDPS004 | 错误 | 入口类不符合上面的规则 |
| SRDPS005 | 错误 | 没有`PluginDisplayName` |
| SRDPS006 | 错误 | 同一语言的`PluginDisplayName`或`PluginGenre`有2个 |
| SRDPS007 | 错误 | 没有`PluginAuthor`，或为空 |
| SRDPS008 | 错误 | 有窗口的插件没有`PluginGenre` |
| SRDPS009 | 警告 | 没有窗口的插件有`PluginGenre`(不会被使用) |
| SRDPS010 | 警告 | 有语言名称或文字为空的`PluginDisplayName`、`PluginGenre`(不会被使用) |
| SRDPS011 | 警告 | `PluginIcon`的路径为空 |
| SRDPS012 | 错误 | 没有`PluginVersion`，或不是3个数字的形式 |
| SRDPS013 | 错误 | 按对象打开窗口的小组件的`GetWidgetTargets`总是返回空列表 |
| SRDPS014 | 错误 | 小组件、通知、设置的名称或通知的默认文本等必需的文字为空 |

## 应用提供的内容

通过`Initialize`的参数`IPluginContext`接收。

| 成员 | 内容 |
|---|---|
| `Settings` | 放在插件文件夹中的设置文件(下面的“设置”) |
| `Messages` | 与应用外观相同的消息窗口(下面的“消息”) |
| `Localization` | 应用的显示语言，以及变化时的事件(下面的“语言”) |
| `Logger` | 应用的日志(下面的“日志”) |
| `GameData` | 游戏数据([插件开发(数据)](插件开发(数据))) |
| `Names` | 根据游戏中的编号查找名称([插件开发(数据)](插件开发(数据))) |
| `Packets` | 读取游戏的消息([插件开发(数据)](插件开发(数据))) |
| `Notifications` | 发出定义的通知([插件开发(通知)](插件开发(通知))) |
| `Stopping` | 应用停止此插件时被取消(下面的“运行方式”) |

### 设置

```csharp
var settings = context.Settings.Load<MySettings>("settings.json");
context.Settings.Save("settings.json", settings);
```

- 文件放在应用文件夹的`Plugins\<程序集名称>\`中(`Settings.SettingsDirectory`)。文件名请写不包含文件夹的名称
- `Load`在文件不存在时返回`new T()`。无法读取或无法解析为JSON时抛出`InvalidDataException`
- `Save`在无法写入时抛出异常
- JSON用`System.Text.Json`读写。读取时不区分属性名的大小写
- 更新后设置文件会保留，删除后会连同文件夹一起删除
- `uninstall.marker`、`app_terminated.marker`以及以`update.pending`开头的名称会被应用在同一文件夹中使用，请不要使用

### 语言

- `Localization.CurrentCulture`是应用的显示语言，为`ja-JP`、`ko-KR`、`zh-CN`、`en-US`中的一种。变化时`CultureChanged`会在UI线程上触发。在设置中选择语言的时刻(保存之前)也会触发
- 可以用`PluginLocalizer`读取4种语言的resx。resx嵌入插件DLL中。.NET的普通生成会按语言分别生成DLL，因此在csproj中按语言决定名称后嵌入

```xml
<ItemGroup>
  <EmbeddedResource Update="Properties\Resources.resx">
    <WithCulture>false</WithCulture>
    <LogicalName>MyPlugin.Properties.Resources.resources</LogicalName>
  </EmbeddedResource>
  <EmbeddedResource Update="Properties\Resources.ja-JP.resx">
    <WithCulture>false</WithCulture>
    <LogicalName>MyPlugin.Properties.Resources.ja-JP.resources</LogicalName>
  </EmbeddedResource>
  <EmbeddedResource Update="Properties\Resources.ko-KR.resx">
    <WithCulture>false</WithCulture>
    <LogicalName>MyPlugin.Properties.Resources.ko-KR.resources</LogicalName>
  </EmbeddedResource>
  <EmbeddedResource Update="Properties\Resources.zh-CN.resx">
    <WithCulture>false</WithCulture>
    <LogicalName>MyPlugin.Properties.Resources.zh-CN.resources</LogicalName>
  </EmbeddedResource>
</ItemGroup>
```

```csharp
var texts = new PluginLocalizer(context.Localization, typeof(Plugin).Assembly, "MyPlugin.Properties.Resources");
string title = texts["WindowTitle"];
```

- 不带语言的`Resources.resx`为`en-US`。请嵌入全部4种语言。没有显示语言的resx时会发生异常
- 键在显示语言中不存在时使用`en-US`，在其中也不存在时直接返回键
- 索引器(`texts["WindowTitle"]`)也可以在XAML的Binding中使用。语言变化后会通过`PropertyChanged`重新读取
- 使用完毕后，用`Dispose`取消对语言事件的订阅

### 日志

- 用`Logger.Info`、`Warning`、`Error`写入应用的日志。行首会加上`[Plugin:<程序集名称>]`
- 日志会显示在“[日志](日志)”和应用文件夹的`Data\CombatRuntime.log`中。`Data\CombatRuntime.log`会在应用的版本变化后被清除

### 消息

- 用`Messages.Show(标题, 正文, 详细)`显示与应用外观相同的消息窗口。详细可以省略
- 可以从任何线程调用。从UI线程调用时，通常在窗口关闭之前不会返回
- 没有让用户选择“是”“否”的窗口

## 运行方式

- 应用在启动时，按安装的顺序逐个初始化所有插件(创建入口类，调用`Initialize`，读取小组件和通知的定义)。用“添加插件”添加的插件会当场初始化
- 应用调用插件代码的地方全部在UI线程上(`Initialize`、创建窗口和小组件内容的处理、事件等)。在返回之前应用的画面会停止，因此请在其他线程中进行繁重的处理
- 在`Initialize`中还不能发出通知。通知的定义在`Initialize`之后读取
- `Shutdown`在应用退出时和应用停止插件时被调用。`Initialize`因异常结束时也会被调用。在此之前`Stopping`会被取消，因此请在`Stopping`或`Shutdown`中停止插件启动的计时器和任务
- 异常
  - 应用调用的代码中的异常、插件代码发出的UI线程上的异常，以及未被等待的`Task`的异常，只会停止该插件。“插件”中的行会变为“错误”，并出现“插件错误”窗口。下次启动时会再次加载
  - 插件创建的线程中的异常会使应用退出。在重新安装或更新到新版本之前，不会加载该插件
  - `Shutdown`中的异常只会写入日志
- 停止的插件在本次运行期间不会重新运行。加载的DLL在关闭应用之前不会被卸载
- 在UI线程上不返回的处理(无限循环或等待)无法被应用停止，整个应用会卡住

## 测试方法

1. 生成。输出文件夹中会生成`<程序集名称>.dll`
2. 在应用的“[插件](插件)”中用“添加插件”选择该DLL。依赖项的DLL会从同一文件夹一起复制
3. 测试重新生成的DLL时，请关闭应用，覆盖到`<应用文件夹>\Plugins\<程序集名称>\`中，然后启动应用。应用运行期间无法替换DLL

- 异常和日志可以在“[日志](日志)”中查看

## 发布和更新

- 要发布的是`<程序集名称>.dll`，有依赖项时还有`.deps.json`和依赖项的DLL(保持输出文件夹中的排列)。没有依赖项的插件只需1个DLL
- 不要发布`StarResonanceDps.PluginSdk.dll`。会使用应用中的该文件
- 只有SDK、.NET和WPF会使用应用中的文件。其他依赖项(如从NuGet添加的库)即使应用中有相同的文件，也要随插件一起发布
- 用户用“添加插件”选择`<程序集名称>.dll`。依赖项不在所选DLL的同一文件夹中时无法添加
- 发布新版本时请提高`PluginVersion`。用户用“添加插件”选择新的DLL后，会在重新启动应用时替换
- 更新后设置文件会保留。请让新版本能够读取旧版本的设置文件
- 更改程序集名称后，会被视为另一个插件(不会成为更新，设置也不会继承)
- 删除(“插件”中的垃圾桶)后，会在重新启动应用时连同文件夹一起删除，设置文件也会被删除

## SDK的版本

- SDK包的版本中，第1个数字为`PluginSdkVersion.Current`，添加功能时第2个及以后的数字会提高
- 应用加载的是传给`PluginRegistration`的`PluginSdkVersion.Current`与应用相同，且生成时的SDK版本不高于应用的SDK的插件。不符合时，“插件”中的行会变为“错误”，“插件错误”窗口中会显示“不是本应用的插件，或与应用的版本不一致。”
- 为了能在用户的应用中加载，请使用与该应用相同发布版本的SDK制作。用较新的SDK制作的插件无法在较旧的应用中加载
- 换用新的SDK时，替换`packages`中的`.nupkg`，并将csproj的`Version`改为新的版本。如果`Version`保持不变，会使用NuGet缓存中以前的SDK生成，也不会出现警告

## 注意

- 请将程序集名称设为不与其他插件重复的名称。程序集名称相同的插件会被视为同一插件(如果是新版本则会替换)。不会加载与应用的组件同名的插件
- DLL的文件名应与程序集名称相同
- 带有XAML资源的依赖项DLL可能被其他插件以不同版本使用时，请在依赖项的csproj中写入`AssemblyVersion`。版本会进入WPF的资源引用，不会与不同版本的同一组件混淆。自己指向依赖项的资源时，也请使用写有版本的形式(`/<组件名称>;v<AssemblyVersion>;component/…`)
- 插件能使用的只有SDK的类型和`PluginResourceKeys`的外观键。应用内部的类型和其他资源的键可能会在不经预告的情况下更改
- 插件在应用中运行，能做与应用相同的事情

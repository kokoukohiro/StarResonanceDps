这是用插件读取游戏数据的说明。所有插件都需要的内容，请参阅[插件开发](插件开发)。

| `IPluginContext`的成员 | 内容 |
|---|---|
| `GameData`(`IPluginGameDataService`) | 应用根据通信生成的值(连接和地图、玩家、附近的敌人、增益、战斗统计和记录、自己的模组)、统计设置，以及变化时的事件 |
| `Names`(`IPluginNameService`) | 根据技能、增益、怪物、职业流派、地图、物品的编号查找名称 |
| `Packets`(`IPluginPacketService`) | 游戏的消息本身 |
| `CombatEvents`(`IPluginCombatEventService`) | 应用处理的战斗事件(伤害、技能和承伤和时间轴的记录、增益的施加和移除、怪物的技能和HP为0)的流 |
| `History`(`IPluginHistoryService`) | 读取和打开已保存的战斗(历史记录)，将插件的值保存到战斗中([插件开发(历史记录)](插件开发(历史记录))) |

## 游戏数据(`GameData`)

以下示例在战斗结束时，将所有人造成伤害的合计写入日志。

```csharp
using StarResonanceDps.PluginSdk;

[assembly: PluginRegistration(typeof(MyPlugin.Plugin), PluginSdkVersion.Current)]
[assembly: PluginDisplayName("ja-JP", "私のプラグイン")]
[assembly: PluginAuthor("YourName")]
[assembly: PluginVersion("1.0.0")]

namespace MyPlugin;

public sealed class Plugin : IStarResonancePlugin
{
    private IPluginContext? _context;

    public void Initialize(IPluginContext context)
    {
        _context = context;
        context.GameData.EncounterClosed += OnEncounterClosed;
    }

    private void OnEncounterClosed(object? sender, PluginEncounterResult result)
    {
        foreach (PluginEncounterPlayer player in result.Totals.Players)
        {
            _context?.Logger.Info($"{player.CharacterId}: {player.Damage.Total}");
        }
    }

    public void Shutdown()
    {
        if (_context is not null)
        {
            _context.GameData.EncounterClosed -= OnEncounterClosed;
        }
    }
}
```

| 成员 | 内容 | 变化时的事件 |
|---|---|---|
| `CurrentServer` | 当前读取的游戏服务器(`PluginGameServer`的`Asia`、`China`、`Global`、`SoutheastAsia`)。无法确定时为`Unknown` | 无 |
| `Session` | 连接和地图的状态(`PluginSessionState`) | `SessionChanged` |
| `Players` | 玩家的列表(`PluginPlayer`) | `PlayersChanged` |
| `Entities` | 附近怪物的列表(`PluginEntity`) | `EntitiesChanged` |
| `SelfModules` | 自己持有的模组和装配中的栏位(`PluginModuleInventory`)。尚未发送时为`null` | `SelfModulesChanged` |
| `GetPlayerBuffs(characterId)` | 该玩家当前带有的增益和减益(`PluginBuff`) | 无(重新读取) |
| `GetEntityBuffs(entityUuid)` | 该实体当前带有的增益和减益 | 无(重新读取) |
| `GetPlayer(characterId)` | 该玩家的行(`PluginPlayer`)。不在`Players`中的人，为离开列表后的最后的值，或通过名片、聊天收到的值。都没有时为`null` | 无(重新读取) |
| `GetPlayerBuild(characterId)` | 该玩家的配装(`PluginPlayerBuild`，下面的“配装”)。`GetPlayer`为`null`的人为`null` | 无(重新读取) |
| `GetEncounter()` | “[DPS计量器](DPS计量器)”显示的战斗中所有人的统计(`PluginEncounterSnapshot`) | 无(重新读取) |
| `GetSkillTotals(characterId, kind)` | 同一战斗中该玩家按技能的明细(`PluginSkillTotals`)。`kind`为造成伤害(`Damage`)或治疗(`Healing`) | 无(重新读取) |
| `GetShownEncounter()` | 与`GetEncounter`相同的战斗的读取接口(`IPluginEncounterRecord`)。尚无战斗时为`null` | `ShownEncounterChanged` |
| `GetLiveEncounter()` | 当前战斗的读取接口。尚无战斗时为`null` | `EncounterStarted` |
| `AggregationSettings` | 设置中“统计设置”的值(`PluginAggregationSettings`) | `AggregationSettingsChanged` |

| 事件 | 触发时机 |
|---|---|
| `EncounterStarted` | 应用创建新的战斗时 |
| `EncounterClosed` | 关闭有记录的战斗时。会传入已关闭战斗的统计和所有人按技能的明细(`PluginEncounterResult`) |
| `EncounterSaved` | 将战斗保存到历史记录时。会传入该战斗的`EncounterKey`和历史记录的编号`HistoryId`(`PluginEncounterSaved`) |
| `MapEntered` | 移动到其他地图或频道时 |
| `LoggedOut` | 游戏返回登录界面时 |

- 值可以从任何线程读取。事件全部在UI线程上触发
- `SessionChanged`、`PlayersChanged`、`EntitiesChanged`、`SelfModulesChanged`、`ShownEncounterChanged`、`AggregationSettingsChanged`会将短时间内的变化合并为1次，并以触发时的值通知。其他5个在每次发生时都会触发
- 值是不可更改的副本，之后不会更新。新的值需要重新读取。连续读取2个值时，可能是不同时刻的值。战斗的读取接口(`IPluginEncounterRecord`)不是副本，每次调用时都会读取值(下面的“战斗的读取接口”)
- `Players`、`Entities`、`SelfModules`以及`EncounterClosed`的结果，会将同一个对象传给所有插件。请不要将`IReadOnlyList`等转换为原来的类型进行修改
- 事件处理在与应用画面相同的UI线程上运行。进行繁重的处理时，小组件也会停止
- 事件处理中抛出异常时，插件会停止

### 连接和地图(`Session`)

|---|---|

| `DungeonFlowState`、`DungeonFlowChanges` | 副本进行的状态(`PluginDungeonFlowState`)，以及进入地图后的状态变化(`PluginDungeonFlowChange`：状态和收到的时间(UTC)，从旧到新)。未收到时为`null`和空 |
| `DungeonTimer` | 游戏的副本计时(`PluginDungeonTimer`)。开始时间(服务器时间的Unix秒，以及换算为此PC时间的UTC)、限制时间、是否倒数、已停止秒数的合计、停止期间显示的值。不发送计时的副本和副本外为`null` |

- 在游戏途中启动应用时，在切换地图之前，可能无法确定自己的角色ID和持有的模组
- 游戏的锁定和其他玩家的目标，游戏不会发送，因此无法获取
- 进行的状态为游戏的值，按`Active`(进入副本地图)、`Ready`(开始前)、`Playing`(开始)、`End`(结束)、`Settlement`(结算画面)、`Vote`(投票)的顺序到达。`None`是游戏的初始值。同一状态连续到达时不加入变化。切换地图或登出后变为空

### 玩家(`Players`)

- 包括自己、队伍成员、附近的玩家，以及在DPS计量器显示的战斗中有记录的人。这是“[玩家列表](玩家列表)”的原始列表，不应用玩家列表的筛选和按名称排序
- 顺序为自己、队伍成员(按队伍编号的顺序)、既不在附近也不在队伍中的人、战斗中的人、其他人
- 名称遵循设置中的“玩家名称”。隐藏的人为`*****`。无法确定时也可能为空

| 属性 | 内容 |
|---|---|
| `CharacterId` | 角色ID。即使隐藏了名称也是真实的值 |
| `Name` | 名称 |
| `ProfessionId` | 职业的编号。无法确定时为0 |
| `SpecState`、`SpecId` | 职业流派的状态(`Unknown`、`NotEquipped`(一阶)、`Specialized`、`Transformation`(变身))。只在`Specialized`时`SpecId`中有编号(传给`Names.GetClassSpecName`) |
| `Level`、`AbilityScore`、`SeasonStrength` | 等级、能力评分、赛季强度。无法确定时为0 |
| `CurrentHp`、`MaxHp`、`CurrentShield` | HP和护盾的量。护盾只能了解自己和附近的人 |
| `PartyNumber` | 队伍编号。不在队伍中时为`null` |
| `IsSelf`、`IsNpc`、`IsPartyMember`、`IsNearby` | 是否为自己、是否为助战NPC、是否为队伍成员、是否在附近 |
| `IsInCombat`、`IsIncapacitated` | 战斗状态、被击败。只能了解自己和附近的人的战斗状态 |
| `PsychoscopeRootBuffId`、`IsPsychoscopeInactive` | 深眠心相仪的类型(根增益的编号)，以及是否未启用 |
| `IsFromRecord` | 只在打开的统计历史记录中存在的人。已保存战斗的`GetPlayers`的行全部为`true` |

### 配装(`GetPlayerBuild`)

- 与“[天赋信息](天赋信息)”“[深眠心相仪信息](深眠心相仪信息)”“[模组信息](模组信息)”“[装备信息](装备信息)”来源相同的值。每次调用都会生成新的副本
- 打开统计的历史记录期间，只在历史记录中的人为该战斗的值，其他人为当前的值(与玩家的小组件相同)。已保存战斗的值用战斗的读取接口的`GetPlayerBuild`读取
- 列表在未收到时均为`null`，收到但为空时为空。用`==`比较`PluginPlayerBuild`时不会比较列表的内容，因此请比较内容

| `PluginPlayerBuild`的属性 | 内容 |
|---|---|
| `RootBuffIds` | 带有的根增益(天赋、深眠心相仪的节点效果和高级节点效果、因子、模组效果)的编号，按升序。在收到该玩家的全部增益之前为`null` |
| `TalentNodeIds` | 当前职业中已获得的天赋树节点的编号，按升序。只有自己，其他人为`null` |
| `LastUsedReplaceableSkills` | 不附加增益而替换技能的天赋中，从原技能编号到最后使用的一方(原技能或替换后)的技能编号的对应。都尚未使用时为`null` |
| `Equipment` | 装备(`PluginEquipmentItem`：部位`Slot`和装备编号`EquipmentId`。名称用`Names.GetItemName`)。无法读取游戏的值时`IsReadable`为`false`，列表为空 |
| `SkillLevels` | 技能编号、等级、阶段(`PluginSkillLevel`的`SkillId`、`Level`、`RemodelLevel`)。自己为当前职业的已学技能、职责技能、所选的幻想，其他人为游戏发送的列表(幻想只有装备中的2个)，不在附近的队伍成员为通过队伍同步最后收到的列表 |
| `Factors` | 当前赛季中启用的类型上装备的因子(栏位编号`SlotId`和物品编号`ItemId`)。只有自己，其他人为`null` |
| `ModuleEffects` | 装配中的模组的效果(`PluginModuleEffect`)。`LinkCount`为装配中的模组的合计。只有自己，其他人为`null` |

- 只包括附近种类为怪物的实体。这是“[实体列表](实体列表)”的原始列表，不应用实体列表的筛选和按名称排序
- 顺序为战斗状态的实体在前、其余在后，各部分中按首领、精英、普通、其他的顺序排列

| 属性 | 内容 |
|---|---|
| `EntityUuid` | 实体的UUID。传给`GetEntityBuffs` |
| `MonsterId` | 怪物的编号(传给`Names.GetMonsterName`)。启动应用之前就在附近的怪物，在一度离开附近后再次出现之前为`null` |
| `CurrentHp`、`MaxHp` | HP |
| `IsInCombat` | 战斗状态 |
| `Cast` | 正在吟唱的技能(`SkillId`、`StartedAtUtc`、`TotalSeconds`)。开始有吟唱时间的技能时放入，在下次技能变化之前保留。超过`TotalSeconds`后也可能保留，因此请根据时间判断结束 |
| `TargetCharacterId` | 正在锁定的玩家的角色ID。不一定是仇恨第1名 |

| `CurrentShield` | 护盾的量 |

- 不在附近的人和敌人的为空。切换地图后会全部清除
- 即使打开了统计的历史记录，也是当前的值

| 属性 | 内容 |
|---|---|
| `BuffUuid` | 每个增益的UUID |
| `BuffId` | 增益的编号(传给`Names.GetBuffName`) |
| `Level`、`Layer` | 等级和层数(叠加数) |
| `DurationSeconds` | 效果时间的总量(延长后会变长)。没有持续时间时为`null` |
| `EndUtc` | 结束的时间(UTC)。没有持续时间或无法确定剩余时间时为`null` |
| `IsRemainingUnknown` | 无法确定剩余时间 |
| `CasterEntityUuid`、`CasterCharacterId` | 施加者实体的UUID(无法确定时为0)，以及施加者为玩家时的角色ID |

### 战斗统计(`GetEncounter`、`GetSkillTotals`)

- 读取的是DPS计量器显示的战斗。打开了统计的历史记录时为该战斗，通过设置中的“保留结果至下次事件”显示之前的战斗时为该战斗
- 尚无战斗时，`GetEncounter`返回`EncounterKey`为0的空统计
- 以读取接口读取同一场战斗的是`GetShownEncounter`，读取当前战斗的是`GetLiveEncounter`(下面的“战斗的读取接口”)

| `PluginEncounterSnapshot`的属性 | 内容 |
|---|---|
| `IsHistory` | 从已保存的历史记录中读取的战斗。在`GetEncounter`中表示打开了统计的历史记录 |
| `StartUtc` | 战斗时钟开始走动的时间(UTC)。尚未开始时为`null`。通常是最初的战斗事件的时间，在副本时钟(`ClockOrigin`)的战斗中是副本开始的时间 |
| `Elapsed` | 战斗的经过时间(不包括自动暂停期间，以及副本时钟的战斗中游戏的副本计时停止的期间) |
| `IsClosed` | 战斗已结束 |
| `Players` | 有造成伤害、治疗、承伤中任意一项的玩家(`PluginEncounterPlayer`)。不按队伍筛选，顺序不固定 |
| `EncounterKey` | 在应用运行期间区分战斗的编号(从1开始)。没有战斗时为0。当前的战斗在保存后也是同一编号。从历史记录中读取的战斗每次读取都会成为新的编号，因此已保存的战斗请用`HistoryId`区分。重新启动应用后会从1重新计数 |
| `HistoryId` | 历史记录的编号([插件开发(历史记录)](插件开发(历史记录)))。保存之前，以及没有记录而不会保存的战斗为`null`。`EncounterClosed`的结果中总是为`null`，编号请通过`EncounterSaved`接收 |
| `LastCombatEventUtc` | 接收到最后的战斗事件(伤害、治疗等)的时间(UTC)。尚无时为`null`。战斗时钟在此之后经过`Info.AutoPauseSeconds`的秒数时停止(为0时不停止。下面的“战斗的值”) |
| `IsAggregationStopped` | 当前的战斗中，应用什么也不记录，战斗时钟也不走动(设置中的“在非战斗区域停止统计”开启，且位于非战斗区域)。已关闭的战斗和从历史记录中读取的战斗中为`false` |
| `ClockOrigin` | 战斗时钟的起点(`PluginClockOrigin`)。为最初的战斗事件、收到副本开始的时间、游戏的副本计时的开始时间之一。插件未注册副本时钟时，为最初的战斗事件([插件开发(战斗划分)](插件开发(战斗划分))) |
| `FirstCombatEventUtc` | 接收到最初的战斗事件的时间(UTC)。尚无时为`null`。治疗、仇恨、破韧从这个时间起记录。不是副本时钟的战斗时与`StartUtc`相同 |
| `BenchmarkFirstTargetEntityUuid` | 测量中只统计最先攻击的敌人时，自己最先造成伤害的敌人的UUID。只统计对该敌人的伤害、仇恨、破韧。确定之前、其他战斗中，以及从历史记录中读取的战斗中为`null` |

- `PluginEncounterPlayer`具有`CharacterId`，以及造成伤害(`Damage`)、治疗(`Healing`)、承伤(`DamageTaken`)的合计(`PluginCombatTotals`)
- `PluginCombatTotals`为合计(`Total`)、每秒数值(`PerSecond`，与DPS计量器相同)、该玩家有效时间内的每秒数值(`ActivePerSecond`，与技能详情相同)、命中次数(`Hits`)，以及暴击和幸运的合计与次数
- `PluginSkillTotals`是与技能详情相同的行，具有行的键(`RowKey`)、行的名称(`Name`，没有时为`null`)、合计、每秒数值、命中次数、暴击率(`CritRate`)、占该玩家合计的比例(`Share`)。按合计从大到小排列
- `EncounterStarted`会在切换地图、副本开始、“按进度自动重置”的划分、手动重置、测量的开始和停止、登出，以及插件的划分请求和规则([插件开发(战斗划分)](插件开发(战斗划分)))时触发。1次切换地图可能触发几次
- 没有战斗时钟开始走动时的事件。请读取`GetEncounter().StartUtc`
- `EncounterClosed`在关闭有记录的战斗并创建下一场战斗时触发。关闭应用时的最后一场战斗不会触发。只有在计量器显示已关闭的战斗期间，才能用`GetEncounter`读取该战斗，因此需要的值请在收到结果时当场保存。保存之后，可以用`EncounterSaved`的`HistoryId`，通过[插件开发(历史记录)](插件开发(历史记录))的`LoadAsync`重新读取
- `EncounterSaved`在应用每次将战斗保存到历史记录时触发1次，时机在同一场战斗的`EncounterClosed`之后、下一次`EncounterStarted`之前。没有记录的战斗不会保存，因此不会触发。关闭应用时的最后一场战斗也不会触发
- `ShownEncounterChanged`在`GetEncounter`和`GetShownEncounter`读取的战斗切换后触发。即打开历史记录时(用户打开时和`OpenAsync`时都会)、返回当前的战斗时(自动返回时也会)、开始显示新的战斗时、停止显示之前的战斗时。重新打开同一历史记录时也会触发。显示之前的战斗期间创建新的战斗时，以及无法打开历史记录时不会触发

### 战斗的读取接口(`GetShownEncounter`、`GetLiveEncounter`)

- `GetShownEncounter`以读取接口(`IPluginEncounterRecord`)返回与`GetEncounter`相同的战斗，`GetLiveEncounter`以读取接口返回当前的战斗。尚无战斗时为`null`
- 打开统计的历史记录期间，以及显示之前的战斗期间，`GetLiveEncounter`也返回当前的战斗
- 读取接口会一直读取创建时的战斗。应用转到下一场战斗后，仍读取同一场战斗
- 持有读取接口期间，该战斗会留在内存中。请只在需要期间持有
- 可以从任何线程调用。当前战斗的值在每次调用时读取当时的值，因此连续调用2个时，可能是不同时刻的值。从历史记录中读取的战斗，除插件的值外不会变化
- 已保存的战斗也可以用相同的读取接口读取([插件开发(历史记录)](插件开发(历史记录))的`LoadAsync`)

| `IPluginEncounterRecord`的成员 | 内容 |
|---|---|
| `EncounterKey`、`HistoryId` | 战斗的编号和历史记录的编号(与上面的`PluginEncounterSnapshot`相同)。当前战斗的`HistoryId`在保存后放入 |
| `IsHistory` | 从已保存的历史记录中读取的战斗(在统计的历史记录中打开的战斗，以及用`LoadAsync`读取的战斗)。当前的战斗，以及显示之前的战斗期间的该战斗为`false` |
| `Info` | 地图、服务器、测量等的值(`PluginEncounterInfo`，下面的“战斗的值”) |
| `GetTotals()` | 所有人的统计(`PluginEncounterSnapshot`)。与DPS计量器的值相同，如果是DPS计量器显示的战斗，则与`GetEncounter()`相同 |
| `GetSkillTotals(characterId, kind)` | 该玩家按技能的明细(与上面的`GetSkillTotals`相同的行)。在该战斗中没有合计的人为空 |
| `ToCombatOffset(utc)` | 将时间转换为战斗的经过时间(下面的“战斗的经过时间”) |
| `GetPlayers()` | 在已保存的战斗中的玩家(下面的“已保存战斗的玩家”)。当前的战斗中为`null` |
| `GetMonsters()` | 留在战斗中的怪物(下面的“战斗的怪物”) |
| `GetPlayerBuffIntervals(characterId)` | 该玩家带有增益的区间，以及在附近的区间(下面的“增益的区间”) |
| `GetPlayerBuild(characterId)` | 已保存战斗中该玩家的配装(上面的“配装”)。为保存时的值，`TalentNodeIds`、`Factors`、`ModuleEffects`只有保存时登录的角色，`SkillLevels`为游戏发送的列表。当前的战斗和不在`GetPlayers`中的人为`null` |
| `GetSkillActivations(characterId, startIndex)` | 该玩家使用技能的记录(`PluginSkillActivation`)中第`startIndex`条及之后的内容(下面的“战斗的记录”) |
| `GetTakenHits(startIndex)` | 玩家承受伤害的记录(`PluginTakenHit`)中第`startIndex`条及之后的内容(下面的“战斗的记录”) |
| `GetCombatLog(startIndex)` | “[时间轴](时间轴)”的记录(`PluginCombatLogRecord`)中第`startIndex`条及之后的内容(下面的“战斗的记录”) |
| `GetPerSecondTotals(characterId, kind)` | 该玩家每秒的伤害或治疗的合计(下面的“每秒的合计”) |
| `GetPluginData(key)` | 此插件保存到战斗中的值。没有时为`null`([插件开发(历史记录)](插件开发(历史记录))的“保存到战斗”) |

### 战斗的值(`Info`)

| `PluginEncounterInfo`的属性 | 内容 |
|---|---|
| `CreatedUtc` | 应用创建战斗的时间(UTC)。战斗时钟通常在其之后开始走动，在副本时钟的战斗中可能从稍早之前开始走动(`StartUtc`)。历史记录的列表按此时间从新到旧排列 |
| `SceneId`、`DungeonDifficulty` | 地图的编号(无法确定时为`null`)和副本的难度(没有时为0)。名称用`Names.GetSceneName(sceneId, dungeonDifficulty)`查找 |
| `ChannelLine` | 频道的编号。没有频道的地方为`null` |
| `Server` | 游戏服务器。应用在保存战斗时写入，因此当前的战斗在保存之前为`Unknown`。当前的服务器请读取`CurrentServer` |
| `SeasonId` | 赛季的编号。与`Server`相同，在保存之前为`null`。当前的赛季请读取`Session.SeasonId` |
| `IsWipe` | 通过设置中的“按进度自动重置”，在团灭时关闭的战斗 |
| `BenchmarkSeconds` | 测量的战斗为测量时间(秒)，等待测量开始期间也会放入。不是测量时为0 |
| `BenchmarkFirstTargetOnly` | 测量中是否只统计最先攻击的敌人。不是测量时为`false`。应用不保存此值，因此从历史记录中读取的战斗中为`null` |
| `AutoPauseSeconds` | 应用创建战斗时设置中“自动暂停”的秒数。战斗时钟在最后的战斗事件之后经过这个秒数时停止。设置为不暂停时、测量的战斗中、副本时钟的战斗中为0 |

- 当前的战斗中，频道、难度、`IsWipe`可能会变化，需要时请重新读取`Info`

### 战斗的经过时间(`ToCombatOffset`)

- 将时间转换为与应用的图表和时间轴的横轴相同的战斗经过时间。即从`StartUtc`起的时间，减去其之前的停止期间(自动暂停，以及副本时钟的战斗中游戏的副本计时停止的期间)
- 停止期间的时间，为停止时刻的经过时间
- 战斗时钟开始走动之前为`null`，早于`StartUtc`的时间为负值
- 请传入UTC的时间。不会根据`DateTime.Kind`进行转换
- 当前的战斗中，晚于最后的战斗事件的时间的值，在战斗继续时可能会变化

### 记录的规则

这是应用在战斗中记录内容的规则。统计和`GetMonsters`的吟唱，都是按此规则记录的内容。

- `IsAggregationStopped`为`true`的战斗中，什么也不记录
- 治疗、仇恨、破韧只在最初的战斗事件之后(从`FirstCombatEventUtc`起)记录
- 测量的战斗(`Info.BenchmarkSeconds`大于0)中，只记录从`StartUtc`起到经过测量时间为止的事件。其中也只记录自己的事件，以及不属于任何玩家的事件(敌人的吟唱、首领技能的预告、敌人的行动)
- `Info.BenchmarkFirstTargetOnly`为`true`时，伤害、仇恨、破韧只统计对自己最先造成伤害的敌人(`BenchmarkFirstTargetEntityUuid`)的部分。该敌人确定之前的仇恨和破韧不统计

### 已保存战斗的玩家(`GetPlayers`)

- 只在从历史记录中读取的战斗(`IsHistory`为`true`)中返回，当前的战斗中为`null`。当前战斗的玩家请读取`Players`
- 包括在该战斗中有造成伤害、治疗、仇恨、破韧、承伤中任意一项，或有时间轴记录的人。顺序不固定
- 行是与`Players`相同的`PluginPlayer`(上面的“玩家”)。值只有与战斗一起保存的值(保存时应用显示的值)，不使用当前的队伍和应用当前持有的值，因此可能与`Players`中同一人的行不同
- `IsFromRecord`为`true`，`CurrentHp`与`MaxHp`相同，`CurrentShield`为0，`PartyNumber`为`null`，`IsPartyMember`、`IsNearby`、`IsInCombat`、`IsIncapacitated`为`false`
- `IsSelf`为调用时登录的角色。名称遵循调用时设置中的“玩家名称”

### 战斗的怪物(`GetMonsters`)

- 当前的战斗中，为附近的怪物，以及离开附近的怪物中属于首领，或出现在“[时间轴](时间轴)”“[承伤日志](承伤日志)”中的怪物。每次调用时读取当时的值
- 从历史记录中读取的战斗中，为与战斗一起保存的怪物。保存的是有吟唱记录的、出现在时间轴的敌人行动中的、对玩家造成伤害的怪物。没有记录的首领不会保存
- 顺序不固定

| `PluginRecordedMonster`的属性 | 内容 |
|---|---|
| `EntityUuid` | 实体的UUID。在附近期间与`Entities`的`EntityUuid`相同 |
| `MonsterId` | 怪物的编号(传给`Names.GetMonsterName`)。尚未接收时为`null` |
| `Hp`、`MaxHp` | 最后接收的HP和最大HP。从历史记录中读取的战斗中为保存时的值。尚未接收时为0 |
| `Casts` | 该怪物的吟唱(`PluginRecordedCast`)，按接收的顺序排列。为有吟唱时间的技能，以及战斗画面上会显示警告的技能 |

- `PluginRecordedCast`为技能的编号(`SkillId`，传给`Names.GetSkillName`)、接收到开始的时间(`StartedAtUtc`，UTC)、是否为会显示警告的技能(`IsWarning`)
- 没有自己名称的被召唤实体的吟唱，记录为召唤它的怪物的吟唱
- 吟唱只在按上面的“记录的规则”记录时才会记录

### 增益的区间(`GetPlayerBuffIntervals`)

- 这是应用为“[增益覆盖率](增益覆盖率)”记录的区间。为增益列表中显示的增益(不包括减益)，只有玩家。测量的战斗中只有自己，`IsAggregationStopped`为`true`的战斗中什么也不记录
- 没有该玩家的记录时，以及战斗时钟开始走动之前为`null`
- 时间在从`StartUtc`到战斗时钟结束为止的期间内。战斗时钟开始走动之前就带有的增益，从`StartUtc`开始。当前的战斗中，仍带有的增益的区间会延长到当前战斗时钟的结束
- 未接收到移除的增益，在效果时间结束的时间结束
- 要与图表的横轴对齐时，请用`ToCombatOffset`转换为战斗的经过时间

| 属性 | 内容 |
|---|---|
| `Buffs` | 按增益编号的区间(`PluginBuffInterval`)。按在该战斗中最先带有的顺序 |
| `PresentIntervals` | 接收到该玩家的值的(在附近的)区间。按从旧到新的顺序。在此区间之外的增益无法获取。离开附近后，带有的增益的区间也会在此时结束 |
| `PluginBuffInterval.BuffId` | 增益的编号(传给`Names.GetBuffName`)。保持接收到的编号，在“增益覆盖率”中合并为1行的增益也不合并 |
| `PluginBuffInterval.IsPermanent` | 最后的区间开始时(从未带有的状态变为带有时)的增益没有效果时间(常驻增益) |
| `PluginBuffInterval.Intervals` | 带有1个以上该增益的区间。按从旧到新的顺序，不重叠 |

- 区间(`PluginTimeInterval`)为开始(`StartUtc`)和结束(`EndUtc`)的UTC时间

### 战斗的记录(`GetSkillActivations`、`GetTakenHits`、`GetCombatLog`)

- 按记录的顺序(从旧到新)返回应用在战斗中记录的内容中第`startIndex`条及之后的内容。将之前读取的数量传给`startIndex`，就可以只读取增加的部分
- `startIndex`为负数，或大于调用时的记录数量时，为`ArgumentOutOfRangeException`。`GetSkillActivations`的数量按玩家计算
- 为按上面的“记录的规则”记录的内容。`GetSkillActivations`中也包括战斗时钟开始走动之前的记录
- 从历史记录中读取的战斗也可以同样读取
- 时间(`ArrivalTimeUtc`)为接收的时间(UTC)。预告结束的记录为预告条结束的时间。要与图表的横轴对齐时，请用`ToCombatOffset`转换
- 承伤的记录和时间轴的记录有共同的序号(`Sequence`)。将两者合在一起排列时，请按此序号排列

| 方法 | 1条的内容 |
|---|---|
| `GetSkillActivations` | `PluginSkillActivation`：技能的编号(`SkillId`)、图标的框(`Frame`)、接收的时间。自己在游戏接受技能时记录，其他玩家在开始使用技能时记录。名称用`Names.GetSkillActivationName`查找 |
| `GetTakenHits` | `PluginTakenHit`：承受伤害的玩家(`CharacterId`)、造成伤害的实体(`Attacker`)、伤害的来源(`Source`和`SourceId`)、值、属性、类型、是否被击败(`IsLethal`)。值为0的伤害不包括在内。自己的技能、坠落、来自玩家的伤害也包括在内 |
| `GetCombatLog` | 从`PluginCombatLogRecord`派生的类型：敌人的吟唱(`PluginCastRecord`)、首领技能的预告和预告的结束(`PluginAnnouncementRecord`)、没有伤害的被击败(`PluginPlayerDeathRecord`)、敌人的治疗(`PluginEnemyHealRecord`)、敌人对敌人造成的伤害(`PluginEnemyDamageRecord`)、敌人施加的增益(`PluginEnemyBuffRecord`) |

- `Frame`为“[DPS趋势图表](DPS趋势图表)”等中显示在技能图标后面的框(`Imagine`：幻想技能，`Ultimate`：终极技能，两者都包括其派生技能。`Standard`：其他技能)
- 记录中出现的实体(`PluginCombatParty`)为UUID(`EntityUuid`)、种类(`Kind`：`Player`、`Monster`、`System`、`Other`)、玩家时为角色编号(`CharacterId`)、怪物时为怪物的编号(`MonsterId`，未接收时为`null`)。`System`为在时间轴中显示为“系统”的、既不是玩家也不是怪物的游戏机关
- 被召唤实体的行动，在可以判别时，记录为召唤它的玩家或怪物的行动(与“时间轴”相同)
- 伤害的来源(`Source`)为技能、子弹、增益、坠落等，`SourceId`为其编号。来自增益或被召唤实体的伤害中，也包括原来的技能(`BuffSourceSkillId`、`SummonSourceSkillId`)

### 每秒的合计(`GetPerSecondTotals`)

- 该玩家的伤害(`Damage`)或治疗(`Healing`)按战斗时钟每秒的合计。与“[DPS趋势图表](DPS趋势图表)”“[HPS趋势图表](HPS趋势图表)”的值相同
- `Totals[i]`为战斗的经过时间从第i秒到第i+1秒(包括第i+1秒)的合计。延迟接收的伤害也计入其时间所在的秒
- 当前的战斗中，只包括已满的秒。已结束的战斗(`IsClosed`)中，也包括最后不足1秒的部分。`Elapsed`为读取时战斗的经过时间
- 该玩家不在战斗中时，以及战斗时钟开始走动之前为`null`
- 每次调用时重新计算所有的秒。没有变化时的事件，因此请按固定的间隔重新读取

### 自己的模组(`SelfModules`)

- `Modules`为持有的模组(`PluginModuleItem`：`Uuid`、物品编号`ConfigId`、`Quality`、效果`Effects`)，`EquippedUuidBySlot`为装配中的栏位编号和模组的`Uuid`
- 效果(`PluginModuleEffect`)为效果的编号(`EffectId`)和链接数(`LinkCount`，尚未发送时为`null`)
- 每次进入地图时，即使内容相同也会触发`SelfModulesChanged`
- 登出后，以及更改设置中的“监听网卡”“游戏执行文件”后，在下次切换地图之前为`null`

### 统计设置(`AggregationSettings`)

- 设置中“统计设置”的值，与用户的设置相同。在设置中保存后值发生变化时，会触发`AggregationSettingsChanged`

| `PluginAggregationSettings`的属性 | 设置的项目 |
|---|---|
| `StopInNonCombatAreas` | 在非战斗区域停止统计。开启时，在非战斗区域什么也不记录，战斗时钟也不走动(`IsAggregationStopped`) |
| `AutoPauseSeconds` | 自动暂停的秒数。不暂停时为0。从更改后创建的战斗起生效(每场战斗的值为`Info.AutoPauseSeconds`) |
| `SplitOnProgress` | 按进度自动重置。在副本开始、进入BOSS房间、团灭时创建新的战斗。为使用者的设置原样，插件的覆盖用`EncounterControl.AppliedOverrides`读取 |
| `KeepResultUntilNextEvent` | 保留结果至下次事件。按进度划分或切换地图后，在新的战斗中有记录之前，计量器显示之前的战斗 |
| `ReturnToLiveOnNextEvent` | 自动退出历史显示。打开历史记录期间，如果当前战斗中发生了事件，则返回当前的战斗。插件用`KeepHistoryOpen`保持期间不返回 |
| `MaxSavedEncounters` | 历史最大保留数。没有上限时为0。超过后，会从旧的战斗开始连同插件的值一起删除 |
| `BenchmarkSeconds` | 测量时间(秒)。从下次测量起生效(测量的战斗的值为`Info.BenchmarkSeconds`) |
| `BenchmarkFirstTargetOnly` | 仅测量最先攻击的敌人。从下次测量起生效(测量的战斗的值为`Info.BenchmarkFirstTargetOnly`) |

| `GetSkillActivationName(skillId)` | 使用的技能。与“[DPS趋势图表](DPS趋势图表)”等的图标相同的名称，有计量器的行名称时为该名称 |

## 游戏的消息(`Packets`)

将要接收的种类传给`ReadAsync`，用`await foreach`读取到达的消息。

```csharp
private static async Task ReadMessagesAsync(IPluginContext context, IReadOnlyCollection<PluginPacketType> types)
{
    await foreach (PluginPacketMessage message in context.Packets.ReadAsync(types).ConfigureAwait(false))
    {
        context.Logger.Info($"{message.Kind} {message.ServiceId}/{message.MethodId}: {message.Payload.Length} bytes");
    }
}
```

- 在`Initialize`中像`_ = ReadMessagesAsync(context, types);`这样不等待地开始
- 要接收的种类(`PluginPacketType`)是种类(`Kind`)、服务编号、方法编号的组合，传入1个以上。只有三者都一致的消息才会到达
- 种类为来自服务器的通知(`Notify`)、游戏对服务器的调用(`Call`)、对调用的响应(`Return`)。`Return`的编号为其所响应的调用的编号
- 从开始`await foreach`时起，按到达的顺序传入到达的消息。不会传入之前的消息。退出循环后会停止接收
- 内容(`Payload`)为protobuf的字节序列。`Notify`和`Return`为解压后的内容，`Return`保持包裹响应的形式。`Call`没有解压
- `Payload`是应用复制的内容，因此可以一直保留
- 尚未取走的内容与下面的“战斗事件”合计，每个插件超过64MB时，插件会停止，“[插件](插件)”中的行会变为“错误”(会显示“插件错误”窗口，下次启动时会再次加载)。请缩小接收的种类，到达的内容请立即取走
- `Initialize`在UI线程上被调用，因此不加`ConfigureAwait(false)`时，循环的内容会在UI线程上运行
- 应用停止插件后，循环会结束。没有传入`Stopping`时不带异常结束，传入时以`OperationCanceledException`结束
- 本Wiki不说明游戏消息的编号和内容的格式

## 战斗事件(`CombatEvents`)

将要接收的种类传给`ReadAsync`，用`await foreach`读取应用处理的战斗事件。

```csharp
private static async Task ReadCombatEventsAsync(IPluginContext context)
{
    PluginCombatEventKinds kinds = PluginCombatEventKinds.SkillActivation | PluginCombatEventKinds.MonsterHpZero;
    await foreach (PluginCombatEvent combatEvent in context.CombatEvents.ReadAsync(kinds).ConfigureAwait(false))
    {
        if (combatEvent is PluginSkillActivationEvent activation)
        {
            context.Logger.Info($"{activation.CharacterId}: {context.Names.GetSkillActivationName(activation.Record.SkillId)}");
        }
        else if (combatEvent is PluginMonsterHpZeroEvent { IsZero: true, MonsterId: { } monsterId })
        {
            context.Logger.Info($"{context.Names.GetMonsterName(monsterId)}: 0 HP");
        }
    }
}
```

| 种类 | 类型 | 到达的时候 |
|---|---|---|
| `Damage` | `PluginDamageEvent` | 玩家和玩家召唤的实体对敌人造成伤害，应用将其加到“[DPS计量器](DPS计量器)”时 |
| `SkillActivation` | `PluginSkillActivationEvent` | 添加技能的记录时(与`GetSkillActivations`相同的记录) |
| `TakenHit` | `PluginTakenHitEvent` | 添加承伤的记录时(与`GetTakenHits`相同的记录) |
| `CombatLog` | `PluginCombatLogEvent` | 添加时间轴的记录时(与`GetCombatLog`相同的记录) |
| `PlayerBuff` | `PluginBuffEvent` | 接收到玩家的增益的施加、变化、移除时 |
| `MonsterBuff` | `PluginBuffEvent` | 接收到怪物的增益的施加、变化、移除时 |
| `MonsterSkill` | `PluginMonsterSkillEvent` | 接收到怪物正在使用的技能时(开始使用和结束使用) |
| `MonsterHpZero` | `PluginMonsterHpZeroEvent` | 怪物的HP变为0时、从0恢复时 |

- 在`Initialize`中像`_ = ReadCombatEventsAsync(context);`这样不等待地开始。`ConfigureAwait(false)`以及应用停止插件时的结束方式与“游戏的消息”相同
- 种类用`|`组合，传入1个以上。为`None`或包括未定义的值时，为`ArgumentException`
- 从开始`await foreach`时起，按应用处理的顺序传入事件。不会传入之前的事件
- 时间(`ArrivalTimeUtc`)为接收到运送该事件的消息的时间(UTC)。预告结束的记录为预告条结束的时间
- `SequenceNumber`为与游戏的消息(`Packets`)共同的序号。由消息引起的事件，为晚于该消息的序号
- 记录的种类(`SkillActivation`、`TakenHit`、`CombatLog`)带有记录时的战斗的`EncounterKey`和记录的编号(`RecordIndex`)。`GetLiveEncounter()`的`EncounterKey`相同时，可以将`RecordIndex + 1`传给`startIndex`继续读取
- `Damage`只会收到按上面的“记录的规则”记录的内容。其他种类的`IsRecorded`为当时应用的当前战斗是否按记录的规则进行记录
- `PluginDamageEvent`的`RowKey`与`GetSkillTotals`的行(`PluginSkillTotals.RowKey`)相同。`IsImmune`的伤害不加到计量器中
- `PluginBuffEvent`的`Kind`为施加(`Added`)、层数或效果时间的变化(`Changed`)、移除(`Removed`)、当时带有的增益(`Present`)、该列表的结束(`AppearListEnd`)
  - `Present`在进入附近的实体的增益列表中，以及移动到其他地图后游戏重新施加自己的所有增益时到达。接着会到达1条`AppearListEnd`。之前带有但不在列表中的增益，为看不到期间移除的增益。游戏不发送列表的出现中，两者都不会到达
  - `Changed`和`Removed`的增益编号、施加者、来源(`SourceType`、`SourceConfigId`)为接收到施加时的值。没有接收到施加的增益(进入地图之前就带有的增益等)的编号为0
  - 接收的消息没有运送的值(`Level`、`Layer`、`DurationMilliseconds`、`ServerCreateTimeUtc`)为`null`
- `PluginMonsterSkillEvent`在结束使用时以`SkillId`为0到达。再次接收到相同的技能时也会到达。进入附近时正在使用的技能不会到达
- `PluginMonsterHpZeroEvent`对最大HP为0的实体(没有HP条的机关等)也会到达。进入附近时HP为0的怪物，以`IsOnAppear`为`true`到达
- 副本的结果和投票画面期间，应用不处理增益、伤害、治疗，因此不会收到`Damage`、`TakenHit`、`PlayerBuff`、`MonsterBuff`，以及`CombatLog`的敌人的治疗、敌人对敌人造成的伤害、敌人施加的增益
- 尚未取走的事件与游戏的消息合计，每个插件超过64MB时，插件会停止(与上面的“游戏的消息”相同)。请缩小接收的种类，到达的内容请立即取走
- 传入的值为不能改写的副本，所有插件收到的是同一个对象

## 读取数据时的规则

- 在窗口的内容、小组件的主体和底栏中订阅的事件，请在`Dispose`中取消。不取消时，已关闭窗口的内容会继续接收事件，也会留在内存中
- 在`Initialize`中订阅的事件，请在`Shutdown`中取消。应用也会在`Shutdown`之前取消，因此停止后不会调用处理
- 增益、战斗统计、`GetPlayer`、`GetPlayerBuild`没有变化时的事件，因此请用计时器重新读取。增益施加和移除的瞬间可以用`CombatEvents`接收

## 未提供的内容

- 未提供装备的详细值、属性、技能栏位、冷却时间、副本的目标和分数、聊天等。需要时请读取游戏的消息。装备的部位和编号、天赋、技能等级可以用`GetPlayerBuild`读取，敌人的吟唱以及战斗画面上会显示警告的技能可以用战斗的读取接口的`GetMonsters`读取，首领技能的预告可以用`GetCombatLog`读取

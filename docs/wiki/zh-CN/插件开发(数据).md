这是用插件读取游戏数据的说明。所有插件都需要的内容，请参阅[插件开发](插件开发)。

| `IPluginContext`的成员 | 内容 |
|---|---|
| `GameData`(`IPluginGameDataService`) | 应用根据通信生成的值(连接和地图、玩家、附近的敌人、增益、战斗统计、自己的模组)，以及变化时的事件 |
| `Names`(`IPluginNameService`) | 根据技能、增益、怪物、职业流派、地图、物品的编号查找名称 |
| `Packets`(`IPluginPacketService`) | 游戏的消息本身 |

## 游戏数据(`GameData`)

以下示例在战斗结束时，将所有人造成伤害的合计写入日志。

```csharp
using StarResonanceDps.PluginSdk;

[assembly: PluginRegistration(typeof(MyPlugin.Plugin), PluginSdkVersion.Current)]
[assembly: PluginDisplayName("ja-JP", "私のプラグイン")]
[assembly: PluginAuthor("YourName")]
[assembly: PluginVersion("1.0.0")]

namespace MyPlugin;

public sealed class Plugin : IStarResonancePlugin
{
    private IPluginContext? _context;

    public void Initialize(IPluginContext context)
    {
        _context = context;
        context.GameData.EncounterClosed += OnEncounterClosed;
    }

    private void OnEncounterClosed(object? sender, PluginEncounterResult result)
    {
        foreach (PluginEncounterPlayer player in result.Totals.Players)
        {
            _context?.Logger.Info($"{player.CharacterId}: {player.Damage.Total}");
        }
    }

    public void Shutdown()
    {
        if (_context is not null)
        {
            _context.GameData.EncounterClosed -= OnEncounterClosed;
        }
    }
}
```

| 成员 | 内容 | 变化时的事件 |
|---|---|---|
| `CurrentServer` | 当前读取的游戏服务器(`PluginGameServer`的`Asia`、`China`、`Global`、`SoutheastAsia`)。无法确定时为`Unknown` | 无 |
| `Session` | 连接和地图的状态(`PluginSessionState`) | `SessionChanged` |
| `Players` | 玩家的列表(`PluginPlayer`) | `PlayersChanged` |
| `Entities` | 附近怪物的列表(`PluginEntity`) | `EntitiesChanged` |
| `SelfModules` | 自己持有的模组和装配中的栏位(`PluginModuleInventory`)。尚未发送时为`null` | `SelfModulesChanged` |
| `GetPlayerBuffs(characterId)` | 该玩家当前带有的增益和减益(`PluginBuff`) | 无(重新读取) |
| `GetEntityBuffs(entityUuid)` | 该实体当前带有的增益和减益 | 无(重新读取) |
| `GetEncounter()` | “[DPS计量器](DPS计量器)”显示的战斗中所有人的统计(`PluginEncounterSnapshot`) | 无(重新读取) |
| `GetSkillTotals(characterId, kind)` | 同一战斗中该玩家按技能的明细(`PluginSkillTotals`)。`kind`为造成伤害(`Damage`)或治疗(`Healing`) | 无(重新读取) |

| 事件 | 触发时机 |
|---|---|
| `EncounterStarted` | 应用创建新的战斗时 |
| `EncounterClosed` | 关闭有记录的战斗时。会传入已关闭战斗的统计和所有人按技能的明细(`PluginEncounterResult`) |
| `MapEntered` | 移动到其他地图或频道时 |
| `LoggedOut` | 游戏返回登录界面时 |

- 值可以从任何线程读取。事件全部在UI线程上触发
- `SessionChanged`、`PlayersChanged`、`EntitiesChanged`、`SelfModulesChanged`会将短时间内的变化合并为1次，并以触发时的值通知。其他4个在每次发生时都会触发
- 值是不可更改的副本，之后不会更新。新的值需要重新读取。连续读取2个值时，可能是不同时刻的值
- `Players`、`Entities`、`SelfModules`以及`EncounterClosed`的结果，会将同一个对象传给所有插件。请不要将`IReadOnlyList`等转换为原来的类型进行修改
- 事件处理在与应用画面相同的UI线程上运行。进行繁重的处理时，小组件也会停止
- 事件处理中抛出异常时，插件会停止

### 连接和地图(`Session`)

| 属性 | 内容 |
|---|---|
| `SelfCharacterId` | 自己的角色ID。确定之前和登出后为`null` |
| `SceneId` | 当前地图的编号。传给`Names.GetSceneName` |
| `SeasonId` | 当前赛季的编号 |
| `DungeonState` | 副本外(`NotInDungeon`)、副本内(`InDungeon`)、结束后(`Finished`) |
| `IsMidLaunch` | 从中途开始读取游戏的通信，自己的信息尚不完整(在游戏途中启动应用时等)。切换地图后会变为`false` |

- 在游戏途中启动应用时，在切换地图之前，可能无法确定自己的角色ID和持有的模组

### 玩家(`Players`)

- 包括自己、队伍成员、附近的玩家，以及在DPS计量器显示的战斗中有记录的人。这是“[玩家列表](玩家列表)”的原始列表，不应用玩家列表的筛选和按名称排序
- 顺序为自己、队伍成员(按队伍编号的顺序)、既不在附近也不在队伍中的人、战斗中的人、其他人
- 名称遵循设置中的“玩家名称”。隐藏的人为`*****`。无法确定时也可能为空

| 属性 | 内容 |
|---|---|
| `CharacterId` | 角色ID。即使隐藏了名称也是真实的值 |
| `Name` | 名称 |
| `ProfessionId` | 职业的编号。无法确定时为0 |
| `SpecState`、`SpecId` | 职业流派的状态(`Unknown`、`NotEquipped`(一阶)、`Specialized`、`Transformation`(变身))。只在`Specialized`时`SpecId`中有编号(传给`Names.GetClassSpecName`) |
| `Level`、`AbilityScore`、`SeasonStrength` | 等级、能力评分、赛季强度。无法确定时为0 |
| `CurrentHp`、`MaxHp`、`CurrentShield` | HP和护盾的量。护盾只能了解自己和附近的人 |
| `PartyNumber` | 队伍编号。不在队伍中时为`null` |
| `IsSelf`、`IsNpc`、`IsPartyMember`、`IsNearby` | 是否为自己、是否为助战NPC、是否为队伍成员、是否在附近 |
| `IsInCombat`、`IsIncapacitated` | 战斗状态、被击败。只能了解自己和附近的人的战斗状态 |
| `PsychoscopeRootBuffId`、`IsPsychoscopeInactive` | 深眠心相仪的类型(根增益的编号)，以及是否未启用 |
| `IsFromRecord` | 只在打开的统计历史记录中存在的人 |

### 附近的敌人(`Entities`)

- 只包括附近种类为怪物的实体。这是“[实体列表](实体列表)”的原始列表，不应用实体列表的筛选和按名称排序
- 顺序为战斗状态的实体在前、其余在后，各部分中按首领、精英、普通、其他的顺序排列

| 属性 | 内容 |
|---|---|
| `EntityUuid` | 实体的UUID。传给`GetEntityBuffs` |
| `MonsterId` | 怪物的编号(传给`Names.GetMonsterName`)。启动应用之前就在附近的怪物，在一度离开附近后再次出现之前为`null` |
| `CurrentHp`、`MaxHp` | HP |
| `IsInCombat` | 战斗状态 |
| `Cast` | 正在吟唱的技能(`SkillId`、`StartedAtUtc`、`TotalSeconds`)。开始有吟唱时间的技能时放入，在下次技能变化之前保留。超过`TotalSeconds`后也可能保留，因此请根据时间判断结束 |
| `TargetCharacterId` | 正在锁定的玩家的角色ID。不一定是仇恨第1名 |
| `HateRanking` | 仇恨的列表(只有玩家，按值从大到小) |

### 增益(`GetPlayerBuffs`、`GetEntityBuffs`)

- 包括当前带有的全部增益。不应用“[增益列表](增益列表)”那样的显示筛选和合并
- 不在附近的人和敌人的为空。切换地图后会全部清除
- 即使打开了统计的历史记录，也是当前的值

| 属性 | 内容 |
|---|---|
| `BuffUuid` | 每个增益的UUID |
| `BuffId` | 增益的编号(传给`Names.GetBuffName`) |
| `Level`、`Layer` | 等级和层数(叠加数) |
| `DurationSeconds` | 效果时间的总量(延长后会变长)。没有持续时间时为`null` |
| `EndUtc` | 结束的时间(UTC)。没有持续时间或无法确定剩余时间时为`null` |
| `IsRemainingUnknown` | 无法确定剩余时间 |
| `CasterEntityUuid`、`CasterCharacterId` | 附加者实体的UUID(无法确定时为0)，以及附加者为玩家时的角色ID |

### 战斗统计(`GetEncounter`、`GetSkillTotals`)

- 读取的是DPS计量器显示的战斗。打开了统计的历史记录时为该战斗，通过设置中的“保留结果至下次事件”显示之前的战斗时为该战斗

| `PluginEncounterSnapshot`的属性 | 内容 |
|---|---|
| `IsHistory` | 打开了统计的历史记录 |
| `StartUtc` | 战斗时钟开始走动的时间(UTC)。尚未开始时为`null` |
| `Elapsed` | 战斗的经过时间(不包括自动暂停期间) |
| `IsClosed` | 战斗已结束 |
| `Players` | 有造成伤害、治疗、承伤中任意一项的玩家(`PluginEncounterPlayer`)。不按队伍筛选，顺序不固定 |

- `PluginEncounterPlayer`具有`CharacterId`，以及造成伤害(`Damage`)、治疗(`Healing`)、承伤(`DamageTaken`)的合计(`PluginCombatTotals`)
- `PluginCombatTotals`为合计(`Total`)、每秒数值(`PerSecond`，与DPS计量器相同)、该玩家有效时间内的每秒数值(`ActivePerSecond`，与技能详情相同)、命中次数(`Hits`)，以及暴击和幸运的合计与次数
- `PluginSkillTotals`是与技能详情相同的行，具有行的键(`RowKey`)、行的名称(`Name`，没有时为`null`)、合计、每秒数值、命中次数、暴击率(`CritRate`)、占该玩家合计的比例(`Share`)。按合计从大到小排列
- `EncounterStarted`会在切换地图、副本开始、“按进度自动重置”的划分、手动重置、测量的开始和停止、登出时触发。1次切换地图可能触发几次
- 没有战斗时钟开始走动时的事件。请读取`GetEncounter().StartUtc`
- `EncounterClosed`在关闭有记录的战斗并创建下一场战斗时触发。关闭应用时的最后一场战斗不会触发。已关闭战斗的值，请在收到结果时当场保存

### 自己的模组(`SelfModules`)

- `Modules`为持有的模组(`PluginModuleItem`：`Uuid`、物品编号`ConfigId`、`Quality`、效果`Effects`)，`EquippedUuidBySlot`为装配中的栏位编号和模组的`Uuid`
- 效果(`PluginModuleEffect`)为效果的编号(`EffectId`)和链接数(`LinkCount`，尚未发送时为`null`)
- 每次进入地图时，即使内容相同也会触发`SelfModulesChanged`
- 登出后，以及更改设置中的“监听网卡”“游戏执行文件”后，在下次切换地图之前为`null`

## 查找名称(`Names`)

| 方法 | 查找的名称 |
|---|---|
| `GetSkillName(skillId)` | 技能 |
| `GetBuffName(buffId)` | 增益 |
| `GetMonsterName(monsterId)` | 怪物 |
| `GetClassSpecName(specId)` | 职业流派(`PluginPlayer.SpecId`) |
| `GetSceneName(sceneId, dungeonDifficulty)` | 地图。有难度名称时为“地图名称-难度名称”。`dungeonDifficulty`可以省略 |
| `GetItemName(itemId)` | 物品(包括装备) |

- 名称为应用显示语言的名称。没有该语言的名称时为中文名称，两者都没有时为`null`
- 与应用的画面不同，不会附上内部名称和内部ID。设置中的“内部ID”“无名称技能和Buff”也无效
- 没有一阶和变身的名称，因此`GetClassSpecName`为`null`
- 没有查找职业、深眠心相仪的类型、赛季、模组效果名称的方法
- 可以从任何线程调用。显示语言变化后，请在`Localization.CultureChanged`中重新查找

## 游戏的消息(`Packets`)

将要接收的种类传给`ReadAsync`，用`await foreach`读取到达的消息。

```csharp
private static async Task ReadMessagesAsync(IPluginContext context, IReadOnlyCollection<PluginPacketType> types)
{
    await foreach (PluginPacketMessage message in context.Packets.ReadAsync(types).ConfigureAwait(false))
    {
        context.Logger.Info($"{message.Kind} {message.ServiceId}/{message.MethodId}: {message.Payload.Length} bytes");
    }
}
```

- 在`Initialize`中像`_ = ReadMessagesAsync(context, types);`这样不等待地开始
- 要接收的种类(`PluginPacketType`)是种类(`Kind`)、服务编号、方法编号的组合，传入1个以上。只有三者都一致的消息才会到达
- 种类为来自服务器的通知(`Notify`)、游戏对服务器的调用(`Call`)、对调用的响应(`Return`)。`Return`的编号为其所响应的调用的编号
- 从开始`await foreach`时起，按到达的顺序传入到达的消息。不会传入之前的消息。退出循环后会停止接收
- 内容(`Payload`)为protobuf的字节序列。`Notify`和`Return`为解压后的内容，`Return`保持包裹响应的形式。`Call`没有解压
- `Payload`是应用复制的内容，因此可以一直保留
- 尚未取走的内容合计每个插件超过64MB时，插件会停止，“[插件](插件)”中的行会变为“错误”(会显示“插件错误”窗口，下次启动时会再次加载)。请缩小接收的种类，到达的内容请立即取走
- `Initialize`在UI线程上被调用，因此不加`ConfigureAwait(false)`时，循环的内容会在UI线程上运行
- 应用停止插件后，循环会结束。没有传入`Stopping`时不带异常结束，传入时以`OperationCanceledException`结束
- 本Wiki不说明游戏消息的编号和内容的格式

## 读取数据时的规则

- 在窗口的内容、小组件的主体和底栏中订阅的事件，请在`Dispose`中取消。不取消时，已关闭窗口的内容会继续接收事件，也会留在内存中
- 在`Initialize`中订阅的事件，请在`Shutdown`中取消。应用也会在`Shutdown`之前取消，因此停止后不会调用处理
- 增益和战斗统计没有变化时的事件，因此请用计时器重新读取

## 未提供的内容

- 未提供装备、属性、天赋、技能栏位、冷却时间、副本的目标和分数、预兆技能、聊天等。需要时请读取游戏的消息

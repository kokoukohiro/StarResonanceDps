这是用插件读取“[统计](统计)”的历史记录(已保存的战斗)，并将插件的值与战斗一起保存的说明。所有插件都需要的内容，请参阅[插件开发](插件开发)。读取到的战斗中的值的读取方法，请参阅[插件开发(数据)](插件开发(数据))的“战斗的读取接口”。

## 历史记录(`History`)

使用`IPluginContext.History`(`IPluginHistoryService`)。以下示例在战斗保存到历史记录时，将保存的时间写入该战斗，重新读取战斗，并将所有人造成伤害的合计和写入的值写入日志。

```csharp
using System.Text;
using StarResonanceDps.PluginSdk;

[assembly: PluginRegistration(typeof(MyPlugin.Plugin), PluginSdkVersion.Current)]
[assembly: PluginDisplayName("ja-JP", "私のプラグイン")]
[assembly: PluginAuthor("YourName")]
[assembly: PluginVersion("1.0.0")]

namespace MyPlugin;

public sealed class Plugin : IStarResonancePlugin
{
    private const string NoteKey = "my.note";

    private IPluginContext? _context;

    public void Initialize(IPluginContext context)
    {
        _context = context;
        context.GameData.EncounterSaved += OnEncounterSaved;
    }

    private async void OnEncounterSaved(object? sender, PluginEncounterSaved saved)
    {
        IPluginContext? context = _context;
        if (context is null)
        {
            return;
        }

        byte[] note = Encoding.UTF8.GetBytes(DateTime.UtcNow.ToString("O"));
        PluginHistoryStatus status = await context.History.SetSavedEncounterDataAsync(saved.HistoryId, NoteKey, note);
        if (status != PluginHistoryStatus.Succeeded)
        {
            context.Logger.Warning($"{saved.HistoryId}: {status}");
            return;
        }

        PluginHistoryLoadResult loaded = await context.History.LoadAsync(saved.HistoryId);
        IPluginEncounterRecord? encounter = loaded.Encounter;
        if (encounter is null)
        {
            context.Logger.Warning($"{saved.HistoryId}: {loaded.Status}");
            return;
        }

        foreach (PluginEncounterPlayer player in encounter.GetTotals().Players)
        {
            context.Logger.Info($"{player.CharacterId}: {player.Damage.Total}");
        }

        if (encounter.GetPluginData(NoteKey) is ReadOnlyMemory<byte> stored)
        {
            context.Logger.Info(Encoding.UTF8.GetString(stored.Span));
        }
    }

    public void Shutdown()
    {
        if (_context is not null)
        {
            _context.GameData.EncounterSaved -= OnEncounterSaved;
        }
    }
}
```

| 成员 | 内容 |
|---|---|
| `GetEntriesAsync()` | 已保存战斗的列表(下面的“列表”) |
| `LoadAsync(historyId)` | 不打开已保存的战斗，直接读取(下面的“不打开直接读取”) |
| `OpenAsync(historyId)` | 在应用中打开已保存的战斗(下面的“在应用中打开”) |
| `ReturnToLiveAsync()` | 使应用返回当前的战斗(下面的“在应用中打开”) |
| `KeepHistoryOpen()` | 使应用不会从打开的历史记录自动返回当前的战斗(下面的“保持打开的历史记录”) |
| `HasOpenFailed`、`OpenFailedChanged` | 最后尝试打开的战斗是否无法读取，以及变化时的事件(下面的“无法打开时”) |
| `TrySetEncounterData(encounterKey, key, data)` | 在尚未保存的战斗中放入插件的值(下面的“保存到战斗”) |
| `SetSavedEncounterDataAsync(historyId, key, data)` | 改写已保存战斗中插件的值(下面的“保存到战斗”) |

- 可以从任何线程调用。`OpenFailedChanged`在UI线程上触发
- `GetEntriesAsync`、`LoadAsync`、`SetSavedEncounterDataAsync`在后台线程中读写历史记录。每个插件逐个按顺序运行，会等待之前调用的方法结束
- 这3个方法的`cancellationToken`可以省略。会在读写之前(`GetEntriesAsync`、`LoadAsync`在读取之后也会)检查，已取消时，任务以`OperationCanceledException`结束。读写途中不会停止
- 已保存的战斗用历史记录的编号(`HistoryId`)指定，保存之前的战斗用`EncounterKey`指定([插件开发(数据)](插件开发(数据))的“战斗统计”)
- 插件停止后(包括`Shutdown`中)，所有方法都什么也不做。返回任务的方法以`Unavailable`结束(`ReturnToLiveAsync`直接结束)，`TrySetEncounterData`返回`false`，`KeepHistoryOpen`返回不保持任何内容的`IDisposable`。停止前通过`OpenAsync`请求但尚未打开的历史记录不会打开
- 开始关闭应用后，`GetEntriesAsync`、`LoadAsync`、`OpenAsync`、`ReturnToLiveAsync`、`SetSavedEncounterDataAsync`同样什么也不做

| `PluginHistoryStatus` | 结束方式 |
|---|---|
| `Succeeded` | 成功 |
| `NotFound` | 没有该编号的已保存战斗(因设置中的“历史最大保留数”被删除等) |
| `Failed` | 无法读取或写入历史记录。原因会写入应用的日志 |
| `Unavailable` | 在插件停止后或开始关闭应用后，因此什么也没有做 |

### 列表(`GetEntriesAsync`)

```csharp
private static async Task LogHistoryAsync(IPluginContext context)
{
    PluginHistoryListResult list = await context.History.GetEntriesAsync().ConfigureAwait(false);
    foreach (PluginHistoryEntry entry in list.Entries)
    {
        string? sceneName = entry.Info.SceneId is int sceneId
            ? context.Names.GetSceneName(sceneId, entry.Info.DungeonDifficulty)
            : null;
        context.Logger.Info($"{entry.HistoryId}: {entry.Info.CreatedUtc:O} {sceneName} {entry.Elapsed}");
    }
}
```

- 与“统计”的历史记录相同，按从新到旧的顺序返回已保存的战斗。不会打开，因此应用的显示不会变化
- 结果(`PluginHistoryListResult`)的`Entries`只在`Status`为`Succeeded`时有内容
- 应用在保存战斗时和关闭应用时，会删除超过设置中“历史最大保留数”的旧战斗

| `PluginHistoryEntry`的属性 | 内容 |
|---|---|
| `HistoryId` | 历史记录的编号。传给`LoadAsync`、`OpenAsync`、`SetSavedEncounterDataAsync` |
| `Info` | 地图、服务器、测量等的值(`PluginEncounterInfo`，[插件开发(数据)](插件开发(数据))的“战斗的值”)。`BenchmarkFirstTargetOnly`为`null` |
| `StartUtc` | 战斗时钟开始走动的时间(UTC)。未开始走动的战斗为`null` |
| `Elapsed` | 战斗的经过时间(不包括自动暂停期间) |

### 不打开直接读取(`LoadAsync`)

- 读取1场已保存的战斗。不会打开，因此小组件、“统计”、`GetEncounter`不会变化
- 结果(`PluginHistoryLoadResult`)的`Encounter`是读取到的战斗的读取接口(`IPluginEncounterRecord`)。`Status`不是`Succeeded`时为`null`
- 读取接口的读取方法，请参阅[插件开发(数据)](插件开发(数据))的“战斗的读取接口”。`IsHistory`为`true`，在该战斗中的玩家可以用`GetPlayers`读取
- 读取到的战斗之后不会变化。读取后用`SetSavedEncounterDataAsync`写入的值也不会放入，需要时请重新读取
- 每次读取，`EncounterKey`都会成为新的编号。是否为同一场战斗，请用`HistoryId`比较
- 持有读取接口期间，读取到的战斗会留在内存中。请只在需要期间持有

### 在应用中打开(`OpenAsync`、`ReturnToLiveAsync`)

- `OpenAsync`与在“统计”中点击历史记录的行时相同，打开已保存的战斗。DPS计量器等小组件和`GetEncounter`会变为该战斗(“[统计](统计)”)
- 战斗在后台线程中读取，安排显示后任务以`Opened`结束。显示后会触发`GameData.ShownEncounterChanged`
- 读取期间选择了其他战斗或当前的战斗时，以`Superseded`结束。在`Opened`之后、显示之前被选择时也不会显示。是否已显示，请用`GameData.GetShownEncounter()`确认
- 设置中的“自动退出历史显示”开启时，当前战斗中发生事件时，以及统计被划分时，应用会返回当前的战斗。要使其不返回，请使用`KeepHistoryOpen`
- `ReturnToLiveAsync`与在“统计”中再次点击正在打开的历史记录的行时相同，返回当前的战斗。返回后任务结束。正在显示当前的战斗时什么也不会变化
- 返回的处理中应用发生异常时，任务以该异常结束(也会写入应用的日志)

| `PluginHistoryOpenResult` | 结束方式 |
|---|---|
| `Opened` | 读取了战斗，并安排了显示 |
| `NotFound` | 没有该编号的已保存战斗。显示不变 |
| `Superseded` | 读取期间选择了其他战斗或当前的战斗。不显示 |
| `Failed` | 无法读取战斗(原因见应用的日志)。显示不变 |
| `Unavailable` | 在插件停止后或开始关闭应用后，因此什么也没有做 |

### 保持打开的历史记录(`KeepHistoryOpen`)

- 在对返回的`IDisposable`执行`Dispose`之前，即使设置中的“自动退出历史显示”开启，也不会因当前战斗的事件或统计的划分而返回当前的战斗
- 调用`ReturnToLiveAsync`时、在“统计”中再次点击正在打开的历史记录的行时、登出时，会返回当前的战斗
- 每次调用都会返回新的`IDisposable`。对同一个执行2次`Dispose`时，第2次什么也不做
- 所有插件的`IDisposable`都执行`Dispose`后，从下一次事件起，会按照设置返回当前的战斗
- 插件停止后，应用会对该插件的部分执行`Dispose`

### 无法打开时(`HasOpenFailed`)

- 应用无法读取最后尝试打开的战斗时(发生异常，或没有该编号的战斗)，`HasOpenFailed`为`true`，在“统计”中选择时也包括在内。显示保持之前的内容
- 打开战斗时和返回当前的战斗时变为`false`。`LoadAsync`不会使其变化
- 变化时会触发`OpenFailedChanged`。短时间内的变化会合并为1次

## 保存到战斗

可以将插件的值以字节序列与战斗一起保存，之后从历史记录中重新读取。

| 方法 | 写入的战斗 | 结果 |
|---|---|---|
| `TrySetEncounterData(encounterKey, key, data)` | 尚未保存的战斗(当前的战斗，或关闭后尚未保存的战斗)。`encounterKey`为战斗的`EncounterKey` | 能放入时为`true` |
| `SetSavedEncounterDataAsync(historyId, key, data)` | 已保存的战斗。`historyId`为历史记录的编号 | `PluginHistoryStatus` |

- 值按键分别保存。键为1～128个字符的英文字母、数字和“.”“-”“_”，不区分大小写
- 只能读写此插件的值。读取时使用战斗的读取接口的`GetPluginData(key)`，没有时为`null`
- 1场战斗中，每个插件最多可以保存32个键(`PluginEncounterDataLimits.MaxKeys`)、合计4MiB(`PluginEncounterDataLimits.MaxTotalBytes`)
- 写入空的值时，会删除该键。值由应用复制，因此传入后即使改写，已保存的值也不会变化
- 键不符合规则时，以及值超过4MiB时，在调用时会发生`ArgumentException`。`GetPluginData`在键不符合规则时也会发生`ArgumentException`
- 键的数量或合计超过上限时，不会写入，并发生`InvalidOperationException`(`SetSavedEncounterDataAsync`的任务以该异常结束)
- 值会与战斗一起被删除(设置中的“历史最大保留数”)。删除插件后也会保留，重新安装同一程序集名称的插件后可以读取。更改程序集名称后，无法读取之前的值

### 尚未保存的战斗(`TrySetEncounterData`)

- 在当前的战斗(`GameData.GetLiveEncounter()`的`EncounterKey`)等中放入值后，应用保存战斗时会一起保存
- 无法放入已保存的战斗，会返回`false`。`GameData.EncounterSaved`之后，请用`SetSavedEncounterDataAsync`写入
- 在`GameData.EncounterClosed`的处理中放入的值，不一定会与战斗一起保存。已关闭战斗的最后的值，请在收到`EncounterSaved`后用`SetSavedEncounterDataAsync`写入
- 没有记录的战斗不会保存，放入的值也会一起丢弃
- 关闭应用时，会先保存最后的战斗再停止插件，因此在`Shutdown`中为`false`

### 已保存的战斗(`SetSavedEncounterDataAsync`)

- 替换已保存战斗中该键的值
- 没有该编号的战斗时以`NotFound`结束，无法写入时以`Failed`结束(原因见应用的日志)
- 在“统计”中打开的战斗，以及正在显示之前的战斗时的该战斗，其读取接口中会放入新的值。之前用`LoadAsync`读取的战斗，以及应用已不再显示的战斗的读取接口中不会放入
- 写入期间打开同一场战斗时，打开的战斗中可能不会放入新的值。历史记录中已经放入，因此可以用`LoadAsync`重新读取

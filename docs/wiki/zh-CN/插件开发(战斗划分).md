用`IPluginContext.EncounterControl`(`IPluginEncounterControlService`)改变应用的战斗划分和战斗时钟。应用的画面(仪表、趋势图、时间轴、历史记录)按改变后的划分和时钟显示。

## 划分当前战斗(`SplitAsync`)

```csharp
private static async Task SplitNowAsync(IPluginContext context)
{
    PluginEncounterSplitResult result = await context.EncounterControl.SplitAsync().ConfigureAwait(false);
    context.Logger.Info($"{result.Outcome} {result.ClosedEncounterHadRecords}");
}
```

- 关闭当前战斗并创建新的战斗。与“统计”的手动重置相同
- `keepPreviousInMeter`为`true`时，在设置中“保留结果直到下次事件”开启的情况下，新战斗有记录之前仪表显示上一个战斗。为`false`时立即显示新战斗
- 测量中(包括等待第一个事件期间)不做任何事，以`SkippedBenchmark`结束
- 新战斗由`GameData.EncounterStarted`、已关闭的战斗在有记录时由`GameData.EncounterClosed`接收。`ClosedEncounterHadRecords`表示已关闭的战斗是否有记录(没有记录的战斗不保存)

## 划分规则(`SetRulesAsync`)

```csharp
private static async Task RegisterRulesAsync(IPluginContext context)
{
    PluginEncounterRulesResult result = await context.EncounterControl.SetRulesAsync(new PluginEncounterRules
    {
        IdleSplitSeconds = 30,
        DungeonClock = PluginDungeonClock.DungeonServerStart,
    }).ConfigureAwait(false);
    if (result.Status == PluginEncounterRulesStatus.Pending)
    {
        context.Logger.Warning($"Held by another plugin: {string.Join(", ", result.PendingItems)}");
    }
}
```

- 注册应用在处理游戏消息时判定的规则。如果插件收到事件后再划分，其间到达的消息的记录会进入上一个战斗
- 再次注册会替换之前的规则，用`null`解除。应用不保存规则，因此在`Initialize`中根据自己的设置注册

| 属性 | 内容 |
|---|---|
| `IdleSplitSeconds` | 战斗事件在这个秒数(1～86400)内没有到达时，划分当前战斗。0不划分 |
| `IntervalSplitSeconds` | 从最初的战斗事件起经过这个秒数(1～86400)时，划分当前战斗。停止期间也计算在内。0不划分 |
| `KeepPreviousInMeterOnConditionSplit` | 上面两种划分时，是否在仪表中保留上一个战斗(与`SplitAsync`的`keepPreviousInMeter`相同) |
| `DungeonStartSplit`、`BossRoomSplit`、`WipeSplit` | 副本开始、进入BOSS房间、团灭时是否划分(`PluginAutoSplitMode`)。`HostSetting`按设置中的“按进度自动重置”，`Split`划分，`DoNotSplit`不划分 |
| `DungeonClock` | 副本时钟(下面的“副本时钟”)。`None`不使用 |

- 无操作和经过的秒数在处理消息之前和每秒判定。划分后的第一个战斗事件进入新的战斗
- 测量的战斗、已关闭的战斗、战斗时钟尚未走动的战斗、副本时钟的战斗中，不按无操作和经过的秒数划分
- 规则从注册后创建的战斗开始生效。无操作和经过的秒数对当前战斗也生效
- 超出范围的值为`ArgumentOutOfRangeException`，与副本时钟不符的组合(`DungeonStartSplit`为`DoNotSplit`，`BossRoomSplit`或`WipeSplit`为`Split`)为`ArgumentException`

## 副本时钟(`DungeonClock`)

- 副本开始时创建的战斗的时钟从副本开始走动，到副本结束为止按1个战斗计算
- 在该战斗中，不按BOSS房间、团灭、无操作和经过的秒数划分，也不使用自动暂停。游戏的副本计时停止的期间(从进入BOSS房间到BOSS战开始、击败BOSS之后等)从经过时间中除去
- 起点从2种中选择
  - `DungeonStartArrival`：收到副本开始的时间
  - `DungeonServerStart`：游戏的副本计时的开始时间(游戏显示的时间的起点)。计时在副本开始后稍晚到达，因此应用先用收到的时间开始，计时到达时如果战斗还没有记录就替换起点。不发送计时的副本、应用尚未收到服务器时间时、记录先进入时，保持收到的时间
- 战斗的起点用`GameData.GetEncounter().ClockOrigin`，游戏的副本计时的值用`GameData.Session.DungeonTimer`读取([插件开发(数据)](插件开发(数据)))
- 副本中途的手动重置、`SplitAsync`、测量停止所创建的战斗也从副本开始计算

## 与其他插件的重叠

- `DungeonStartSplit`、`BossRoomSplit`、`WipeSplit`、`DungeonClock`按每个项目使用最先注册的插件的值。持有副本时钟的插件也持有副本开始的划分
- 其他插件以不同的值持有的项目，`SetRulesAsync`以`Pending`结束，并进入`PendingItems`。持有的插件解除或停止时使用，并触发`RulesChanged`
- 应用当前使用的覆盖用`AppliedOverrides`读取。设置中的“按进度自动重置”会显示进行覆盖的插件的名称
- 无操作和经过的秒数使用所有插件的值

## 运行方式

- 方法可以从任何线程调用。应用在处理调用之前收到的消息后，在处理游戏消息的线程中执行。捕获停止期间在UI线程中执行
- `Task`的后续处理不在应用的线程中执行。`RulesChanged`在UI线程中触发
- 应用停止插件时，解除该插件的规则。之后的方法不做任何事，以`Unavailable`结束
